基线来源：用户提供的《设计基线》附件（40 个 GamePlatform 插件、4 个 DBA 项目插件）；附件原有四角色条款已由用户 2026-09-27 的明确指令覆盖。现行服务器角色为 OpenWorld、Village、MainArena 三类，大厅属于 OpenWorld 体验；不覆盖凭据、资产真实性、保留用户修改和验证证据等安全规则。

2026-09-27目录修订：用户批准三层方案后，四个DBA扩展为五个（新增可选DBAArena），平台物理分类统一为GamePlatform；40个既定平台插件身份不变，但GamePlatformArena归MOBA层。代码／机制46个＋真实内容插件N。旧附件40+4来源保留作历史说明，现行要求以下文为准。

## 1. 目标与边界

将当前工作空间渐进整理为基线规定的单仓库工程：一个 `Game/DivineBeastsArena.uproject`，40 个相互独立的 GamePlatform 插件和 5 个 DBA 项目代码插件及独立的MobaPresentation，真实内容插件另计N；客户端、专用服务器、编辑器各一个正式 UE Target；OpenWorld、Village、MainArena 三类服务器角色由同一服务器程序按启动配置选择，大厅作为 OpenWorld 体验；Go 后端保留五个薄入口；UE 与 Go 继续以 `Shared/Contracts` 为唯一跨语言契约源。

不在本次目标中：创建 DevHost 或第二个正式 UE 工程；把多个平台插件合并；按客户端／服务器复制成两套同名插件；恢复旧阵营、五行或王印玩法；生成文本假资产；修改生产凭据或执行生产部署；凭空声称缺少工具链的构建、烘焙或联机验证通过。

## 2. 冻结的插件清单与职责边界

### GamePlatform（40 个，均保留独立 `.uplugin` 身份）

`GamePlatformCore`、`GamePlatformData`、`GamePlatformApplicationFlow`、`GamePlatformOnline`、`GamePlatformSession`、`GamePlatformUI`、`GamePlatformInput`、`GamePlatformLoading`、`GamePlatformSettings`、`GamePlatformSave`、`GamePlatformLocalization`、`GamePlatformServer`、`GamePlatformWorld`、`GamePlatformOpenWorld`、`GamePlatformPCG`、`GamePlatformInteraction`、`GamePlatformNavigation`、`GamePlatformGameplay`、`GamePlatformCharacter`、`GamePlatformAbilitySystem`、`GamePlatformCombat`、`GamePlatformAI`、`GamePlatformQuest`、`GamePlatformAnimation`、`GamePlatformPresentation`、`GamePlatformVFX`、`GamePlatformSFX`、`GamePlatformCamera`、`GamePlatformLobby`、`GamePlatformVillage`、`GamePlatformArena`、`GamePlatformInventory`、`GamePlatformEntitlement`、`GamePlatformEquipment`、`GamePlatformProgression`、`GamePlatformLiveOps`、`GamePlatformCommerceUI`、`GamePlatformTelemetry`、`GamePlatformDebug`、`GamePlatformDeveloperTools`。

39个跨游戏插件位于 `Game/Plugins/GamePlatform/<职责分类>/<插件叶目录>`，第40个GamePlatformArena位于 `Game/Plugins/MobaCommon/GamePlatformArena`，保留五模块；分类目录不放 `.uplugin`。插件名、模块名、构建规则类、导出宏和注册名逐项核对。双端职责在插件内部按真实需要拆模块，不为整齐制造空模块；客户端、服务器、编辑器隔离由模块类型、Target、依赖和运行上下文共同证明。

### DBA 项目代码插件（5 个）

- `DBAGameplay`：公共项目身份、生肖角色和非竞技玩法定义；不依赖MOBA，不引用客户端纯表现或服务端专有类型。
- `DBAWorlds`：世界定义类型与项目校验，不依赖竞技；世界地图、碰撞及专属环境资产由三个世界内容包分别持有，不重复存放。无真实资产时只登记待生成状态，不放占位二进制。
- `DBAClient`：公共客户端流程、项目表现上下文与映射、项目UI适配；不依赖竞技。通用播放器归平台插件，美术资源归相应内容包。
- `DBAServer`：唯一项目服务器装配模块，按启动配置只激活 OpenWorld、Village、MainArena 之一；大厅是 OpenWorld 内的体验，不建立独立 Lobby 角色或程序；承载非竞技公共后端桥接、就绪与服务器专用数据；竞技扩展由DBAArena按需加入。
- `DBAArena`：可选竞技装配，保留DivineBeastsArenaRuntime、DivineBeastsArenaClient、DivineBeastsArenaServer三个模块；客户端实现私有依赖公共流程扩展，DBAClient插件引用仅允许Client／Editor目标，Server不带入客户端。

内容插件按`Game/Plugins/DivineBeasts/ContentPacks/ContentPackRegistry.json`登记。公共、英雄、三世界、公共表现和可选包属于项目层内部；登记不会自动激活资源，不建立第二套资产管理器。当前N=0，不创建空包。

## 3. 角色、构建和业务契约

正式服务器角色仅有 `GameServer.Role.OpenWorld`、`GameServer.Role.Village`、`GameServer.Role.MainArena`。体验与角色分离：OpenWorld 包含 `Experience.OpenWorld.Hub`（大厅默认体验）和 `Experience.OpenWorld.Main`；Village 包含 Main、Tutorial、Training；MainArena 通过数据选择 1v1 至 5v5。已发布的 `Experience.Lobby.Main` 保留为兼容标识并映射到 OpenWorld，不是角色、不进入新 Profile 的允许体验。一个 UE Server Target／平台／工具链只生成一套服务器程序；按受校验的三角色 Profile 启动不同进程实例。正式 UE Targets 为 Client、Server、Editor，不建立角色专用 Target 或 DevHost。

兼容性：移除已发布的独立 `GameServer.Role.Lobby` 属破坏性角色契约变更，当前 Shared 契约版本为 `2.0.0`；1.x 服务端角色契约不与 2.x 混用。`Experience.Lobby.Main` 字符串仅保留作迁移别名，后端按 OpenWorld 处理，不创建 Lobby 实例，也不改写已存在的实例身份或未消费票据。

UE/Go 公共真源仍是 `Shared/Contracts/GamePlatform` 与 `Shared/Contracts/Games/DivineBeasts`；Go 内部契约仍在 `Backend/internal/contracts`。新增或调整角色必须修改真源并运行仓库锁定的生成流程，不手改生成物、不复用已发布字段号或枚举号。后端在既有五入口边界内校验三角色注册、心跳、就绪、准入、分配、排空及结果权限；大厅流量使用 OpenWorld；不增加第六个服务，不将大厅组队真源迁到 UE。

服务器 Profile 明确三种角色之一、体验、地图／资源集、容量或实例上下文、后端准入及排空策略；启动时拒绝缺字段、角色与体验不匹配、非法跨角色资源引用和版本不兼容。大厅使用 OpenWorld Profile 且默认 `Experience.OpenWorld.Hub`。凭据由部署密钥机制提供，不进入仓库配置或内容包。常驻世界与短生命周期竞技按不同排空／回收策略处理。

## 4. 先前导入基线与现行迁移决定

以下为2026-09-26导入前历史盘点，不是当前插件数量：目标工程有 37 个 `.uplugin` 描述，其中 30 个是目标清单内的 GamePlatform，另有 6 个旧 `DivineBeasts*` 插件及 `MobaPresentation`；10 个目标 GamePlatform 和 4 个 DBA 插件缺失。源目录有 51 个描述：40 个目标 GamePlatform、4 个 DBA 插件，以及同样的 6 个旧项目插件和 `MobaPresentation`。目标工作树包含大量未提交修改和未跟踪源码，不能以源目录覆盖目标目录，也不能用清理命令重建插件树。

源目录的 DBA 代码不是可直接验收的完整实现：`DBAGameplay` 当前仅有模块入口；`DBAWorlds.uplugin` 的 Modules 为空；`DBAServer` 的角色 `.cpp` 明确标注为骨架；`DBAClient` 仍依赖旧 `DivineBeasts*` 模块。缺失的 10 个 GamePlatform 插件虽有源文件，仍须逐插件审查描述、模块、Build.cs 依赖、端侧和目标引用。复制完成不等于实现完成。

旧实现的职责迁移建议如下；最终移动前必须形成逐文件清单和引用影响表：

| 旧实现 | 目标归属 | 保留边界 |
| --- | --- | --- |
| `DivineBeastsRuntime` | `DBAGameplay` | 项目身份、项目契约适配和中立项目定义；生成代码仍由锁定契约工具产生 |
| `DivineBeastsApplicationFlow` | `GamePlatformApplicationFlow` 的扩展点 + `DBAClient` 装配 | 通用流程执行器不复制到项目插件 |
| `DivineBeastsCharacters` | 规则／定义迁入 `DBAGameplay`，客户端外观迁入 `DBAClient` | 通用角色、GAS、动画机制仍归对应平台插件 |
| `DivineBeastsArena` | 三个既有模块统一归 `DBAArena`，从公共项目插件移出 | 通用匹配、比赛与竞技运行时继续归 GamePlatformArena |
| `DivineBeastsPresentation` | `DBAClient` | 仅项目上下文、默认映射和内容注册；不实现第二套 VFX 执行器 |
| `DivineBeastsUI` | 项目页面和主题进 `DBAClient` | 通用 UI 导航、页面框架归 GamePlatformUI |
| `MobaPresentation` | 保持独立的 MOBA 表现语义插件，位于 `Game/Plugins/MobaCommon/Presentation/MobaPresentation/` | 不并入 `DBAClient`；由竞技专用组合根经平台中立接口连接，通用世界表现不能因关闭竞技而失效 |

迁移须保留已发布反射路径、资产身份、协议字段、配置键和挂载点的兼容策略。先审计引用、内容所有权和目标差异，再迁移；确认新归属可构建、旧依赖清零且有可恢复迁移快照后，才能退役旧 `.uplugin`。不得先删后补。真实 `.uasset`／`.umap` 及外置对象数据须由引擎处理；不把文件夹占位符当成资源。

## 6. 验收门槛与证据边界

- 清单门槛：46个代码／机制插件描述（40 GamePlatform + 5 DBA + 1独立 `MobaPresentation`）及按登记交付的N个纯内容插件，唯一 `.uproject`，正式UE Target为Client、Server、Editor；没有DevHost、其他额外业务插件或嵌套插件。
- 架构门槛：插件描述与构建规则匹配；依赖图无环；无不存在模块、跨模块私有头访问、服务器到客户端依赖、共享模块依赖端侧实现；关闭 MOBA 后非竞技世界基础功能仍可装配。
