### 3.2 仍直接继承 UPrimaryDataAsset 的候选

当前需要后续逐类迁移评估：

```text
UGamePlatformHeroDefinition
UGamePlatformAIDefinition
UGamePlatformQuestDefinition
UGamePlatformEntitlementDefinition

UGamePlatformInventoryItemDefinition
UGamePlatformProgressionTrackDefinition
UGamePlatformUIScreenDefinition
UGamePlatformUIRouteDefinition
UGamePlatformVFXDefinition

```

不能一次性机械改基类。每个迁移必须先列出：

- 现有 PrimaryAssetType／PrimaryAssetId 是否已发布。
- 自有 DefinitionId／Version／Revision 与 `UGamePlatformDefinitionBase.DataVersion` 的字段映射。
- `RequiredDefinitions` 当前字段类型是否一致；例如 Hero 当前使用 `TArray<FName>`，不能无迁移地替换为 `TArray<FPrimaryAssetId>`。
- 现有 CDO 校验、序列化、反射路径和代码消费者影响。
- 插件是否已经依赖 GamePlatformData。
- 编辑器验证器和 Codegen／Cook 规则是否需要兼容。

当前没有正式 `.uasset`／`.umap`，是低资产迁移窗口，但 C++／反射兼容仍需真实 UE 构建证明。

### 3.3 本轮低风险整改


并同步文件名、generated include、测试和 README；保留 DeveloperTools 公开通用验证器身份不变。

### 3.4 推荐迁移批次

## 5. P0-4｜VFX Definition 扩展点审查

当前 10 个行为 Definition 全部由 `UGamePlatformVFXDefinition` 派生，且具体行为类目前均为 `final`：

```text
Instant
Attached
Projectile
Beam
Area
Shield
Portal
Trail
World
Composite
```

### 5.1 P0 决策

本轮不批量删除 `final`。

保持 `final`：

```text
Instant
Attached
Portal
Trail
World
Composite
```

当前没有证据证明这些行为需要项目 C++ 结构扩展，纯参数／资源差异应继续使用 DataAsset。

Phase 2 候选开放：

```text
Projectile
Beam
Area
Shield
```

只有当 DivineBeasts 项目层确实需要平台不应拥有的公共项目字段和额外校验时才移除对应 `final`。

### 5.2 项目魔法 VFX 推荐结构

不要引入与“行为基类”竞争的第二条 UObject 魔法继承树。C++ 是单继承，项目公共魔法元数据应优先组合为：

```text
FDivineBeastsMagicVFXMetadata
- SpellSemanticId
- ContentPackId
- HeroPresentationProfileId
- ProjectValidationFlags
```

然后：

```text
UGamePlatformVFXProjectileDefinition
        ↑
UDivineBeastsMagicProjectileVFXDefinition
        + FDivineBeastsMagicVFXMetadata

UGamePlatformVFXBeamDefinition
        ↑
UDivineBeastsMagicBeamVFXDefinition
        + FDivineBeastsMagicVFXMetadata
```

Area／Shield 同理。

寒冰箭、火球、雷电弹、龙息等如果只是 Niagara／材质／颜色／参数／速度不同，必须是同一 Definition 类型的数据资产实例，不创建每技能 C++ 子类。

### 5.3 VFX 根迁移顺序

开放 Projectile／Beam／Area／Shield 派生前，先完成 `UGamePlatformVFXDefinition → UGamePlatformDefinitionBase` 的兼容评估，统一主资产身份、DataVersion、RequiredDefinitions 和租约校验，避免先扩项目类后再迁根导致二次迁移。

## 6. P0-5｜Lobby／Village／OpenWorld 职责审查

活动源码引用扫描确认三个插件均没有外部消费者，只有自身 `.uplugin`、`Build.cs` 和模块注册入口。

### GamePlatformLobby

- 当前：Runtime + ClientOnly + ServerOnly 三个模块壳。
- 禁止：Lobby ServerRole、独立 Lobby Server Target、独立 Lobby 世界包。
- 当前最高规则：保留 `GamePlatformLobby` 通用体验插件身份。
- P0 处理：保留但明确为“未实现／条件保留”；不得生产启用。
- 只有出现可跨游戏复用的非权威大厅 Experience／Party Ready／社交集结等独立机制，才允许真正实现。
- 若后续确认所有职责均可由 World／ApplicationFlow／UI／Party 表达，再通过正式基线变更退休该插件。

### GamePlatformVillage

- 当前：Runtime + ClientOnly + ServerOnly 三个模块壳，无外部消费者。
- Village 是《神兽联盟》正式 ServerRole，但“服务器角色”不等于“平台必须有 Village 插件”。
- P0 判定：尚未证明跨游戏通用职责；保持 Disabled，列为退休／合并候选。
- Tutorial／Training 应优先由 Quest／Gameplay／World／项目 Definition 组合，不把项目新手村规则塞入平台基类。

### GamePlatformOpenWorld

- P0原判定：Runtime + ServerOnly 模块壳，无外部消费者；World、PCG、Navigation、Interaction、AI 已覆盖开放世界基础机制，因此不得实现万能 OpenWorld Manager。
- 2026-09-29专项复审：全工作空间没有运行时消费者，也没有 Dynamic World Event／Zone Activity／Population Scheduler 等真实跨项目需求；继续保留空壳与“禁止空插件”规则冲突。
- 现行判定：正式退休 GamePlatformOpenWorld 描述及两个空模块，并从设计基线移除。OpenWorld 仍是正式服务器角色，其世界生命周期和项目策略分别由既有平台插件与 DivineBeasts 项目层组合承担。
- 未来若出现独立跨项目职责，必须重新提交公开契约、真实消费者、端侧／生命周期／网络权威和独立验收方案，不直接恢复旧空壳。

## 7. P0-6｜Online + Session 完整缺口

### 7.1 GamePlatformOnline

已有：

- `IGamePlatformOnlineService` 完整公开合同。
- 配置、Probe、Login、Profile、Refresh、Logout、Cancel、Diagnostics 等中立接口。
- `UGamePlatformOnlineClientSubsystem` 和认证 Provider 生命周期。
- 认证代次、旧回调失效、无秘密公开快照等安全设计。

缺口：

1. `IGamePlatformOnlineService::Get` 和公开门面的真实实现未闭合。
2. Private `OnlineSession` 状态机尚未接入门面、UE HTTP、JSON、UObject Service。
3. Shared OpenAPI DTO／错误映射／版本兼容和真正请求调度未形成生产链。
4. 取消、超时、有限重试、TraceId、幂等键需要统一 Transport 层实现。
5. `GamePlatformOnlineServer` 当前只有模块注册入口；若 Phase 1 仍没有独立职责，应提出删除该模块而不是继续留空壳。

### 7.2 GamePlatformSession

已有：

- `FSessionConnectionState` Private 状态内核。
- Join／Transfer／Reconnect 意图、Operation／Attempt 身份、Deadline、Assign、CommitTravel、四事实 Observe、Cancel／Fail／ResolveRemote。
- PostgreSQL 准入原子内核设计与隔离测试材料。

缺口：

1. 没有 `IGamePlatformSessionService`。
2. 没有公开 GameInstance／Client Subsystem。
3. 没有 JoinDefaultWorld／JoinAssignment／Transfer／Reconnect／Leave 等正式 API。
4. 没有真实 World Assignment／Transfer Ticket／Connection／Admission Provider。
5. 没有引擎 ClientTravel／连接握手适配。
6. 没有将 Online 身份代次接入 Session；Session 也不能获取或保存 Access Token。
7. 没有与 Loading／World 的四事实 Ready 对接。
8. DBAClient 仍引用不存在的 `GamePlatformSessionClientSubsystem.h`，真实头预检因此失败。
9. Dedicated Server 真实 `UNetConnection` 与后端 Claim／Commit 的身份绑定尚未通过 UE5.8 引擎门禁。

详细后端／准入设计沿用 `Docs/Architecture/游戏流程与会话准入后端纵向修复设计规格.md`；本 P0 不重复造第二套协议。

### 7.3 Phase 1 前硬门禁

只有以下条件满足后，才允许 DBAClient 报告 InWorld／Ready：

```text
Online authenticated
+ backend assignment valid
+ target server registered/ready
+ real network connection established
+ server admission committed
+ target World/Experience identity matches
+ required Data lease ready
+ gameplay/character controller ready
```

任何一项缺失都不得以地图打开、客户端布尔值或固定成功替代。

## 8. P0-7｜Animation／Camera／SFX 规格入口
