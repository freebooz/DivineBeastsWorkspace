## 设计与约束

- 依赖方向为 DivineBeasts（项目层）→ MobaCommon（MOBA层）→ GamePlatform（平台层）；项目可直接依赖平台。2026-09-29现行平台层为39个插件，GamePlatformArena在MOBA层，共40个GamePlatform稳定身份；新增GamePlatformSurface只使用ClientOnly＋Editor模块，不形成Server或项目层反向依赖。
- DBAGameplay、DBAWorlds、DBAClient、DBAServer保留；新增DBAArena承接三个既有项目竞技模块，不改变模块名、反射名、导出宏或Shared契约。
- 非竞技公共项目插件的依赖闭包不得包含DBAArena、GamePlatformArena或MobaPresentation。竞技到公共流程的接线使用现有公开扩展接口；仅客户端适配依赖DBAClient，服务器装配不引入客户端插件。
- 现行基线为46个代码／机制插件＋登记的内容插件N。2026-09-27历史46中的GamePlatformOpenWorld已因空壳退休；当前由有真实服务、资产合同、Editor生成/验证和使用者边界的GamePlatformSurface加入，OpenWorld不得恢复。内容插件在ContentPacks分类下按真实内容交付，不创建空插件和假UE资产。
- OpenWorld、Village、MainArena三角色及单Server Target不变；大厅属于OpenWorld体验。无新工程、无新运行框架、无后端功能或协议变更。
- 当前工程原位增量修改，既有未提交修改保留；迁移前保存受影响文件快照。无UE工具链或真实资产时如实记录未验证，不降低版本或伪造通过。

## 风险审查重点

1. 直接或间接重新引入竞技依赖：用实际描述的依赖闭包及违规夹具验证。
2. 服务器启用竞技时顺带引入DBAClient：按Client/Server/Editor分别计算依赖与模块可用性。
3. 移动目录后模块丢失、重名、构建规则或稳定身份变化：清单、哈希、模块解析回归。
4. 内容登记通过路径穿越、重复身份或代码插件伪装绕过清单：登记校验与失败夹具。
5. 历史40／46与更早45个计数、旧路径和旧项目插件树仍充当现行规则：同步正式文档，历史资料明确标记，不改历史执行证据冒充新要求。
