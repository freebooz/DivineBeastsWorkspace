# 游戏流程与会话准入后端纵向修复设计规格

> 状态：待用户审阅；本文件是设计，不代表实现、构建、测试或部署已完成。
> 日期：2026-09-27。
> 范围：修复 DBAClient 应用流程与 GamePlatformApplicationFlow 的 API 断层，并把玩家世界分配、服务器会话准入和真实 UE 网络连接纳入同一可信业务链。

## 1. 目标与验收结果

实现一条最小但真实的登录后进入世界流程：已认证玩家请求目标世界，后端按可信身份和服务器状态建立可幂等追踪的准入预留，目标专用服务器只可为已认证且真实关联的连接领取和提交该预留；客户端只有在真实目标世界、角色控制器和后端准入事实匹配后，才由统一平台流程执行器报告 Ready。

同时消除项目流程对已删除旧 Flow API 的调用。不得通过旧接口兼容壳、固定成功回调、客户端自报 `PlayerID`／`SessionID`／连接身份、把地图打开当作准入，或把纯状态内核测试冒充端到端完成。

成功边界：

1. 玩家身份只来自 Gateway 验证的访问令牌；目标角色、体验、区域和角色所有权按项目业务规则校验。
2. 服务器注册、启动代次、协议版本、容量和 Ready 状态来源于受认证的服务器控制面；玩家不能选择任意端点或伪造服务器身份。
3. 后端准入使用现有 PostgreSQL `postgresadmission.Store` 与 `000003_session_admission.sql` 原子内核；Reserve／Claim／Commit／Release／Cancel 的重试、竞争和不确定结果遵循已有语义。
4. 认证凭据、一次性准入材料和访问令牌不写日志、配置、资产或 URL；不确定结果先查询，不盲目重签或回滚。
5. ApplicationFlow 只使用当前公开的 `Configure`／`Start`、节点完成委托、句柄和节点令牌；一个平台执行器管理全部应用操作，不另建项目级执行器。
6. 当前 UE5.8 网络钩子必须能把目标服务器认证的准入材料与真实 `UNetConnection` 唯一绑定。若验证发现引擎公开 API 无法满足此条件，停止提交/激活实现并报告具体缺口，不降级到客户端 AttemptId。

## 2. 当前实现证据与根因

- `Game/Plugins/DivineBeasts/DBAClient/Source/DivineBeastsApplicationFlowClient/Private/DivineBeastsApplicationFlowSubsystem.cpp` 仍使用 `RegisterNode`、`StartRun`、`BeginOperation`、`TransitionTo`、`OnSnapshotChanged` 等已不存在的接口；现行平台接口在 `Game/Plugins/GamePlatform/Application/GamePlatformApplicationFlow/Source/GamePlatformApplicationFlow/Public/API/GamePlatformApplicationFlowSubsystem.h`，执行节点契约在同插件 `Public/Interfaces/`。
- `GamePlatformOnline` 已有认证与资料的类型化在线服务，但不提供 Session/World Assignment 专属后端请求；项目流程还引用旧 `GamePlatformOnlineClientSubsystem`。实现前必须对照当前 Provider 装配，选定唯一认证上下文，不得通过公开原始令牌拼接请求。
- `Backend/internal/app/gateway/api.go` 当前没有玩家世界分配路由；`Gateway` 认证上下文已经能提供 `PlayerID` 和 `SessionID`，应成为玩家入口的身份来源。
- `Backend/internal/transport/httpadapter/gameservercontrol_server.go` 只有 register、heartbeat、ready、drain 路由套用内部 Bearer 中间件；allocate、assignment、transfer 和 match-result 路由未套用该中间件。
- `Backend/internal/app/gameservercontrol/service.go` 的 Assignment 运行时记录保存在进程内 map；生产装配中的世界分配器也使用当前进程的注册表。它不能证明多副本一致或重启可恢复。
- `Backend/internal/platform/database/postgresadmission/store.go` 与迁移实现准入数据库原子内核，但未被 HTTP/RPC 或生产业务装配调用；授权记录、实例注册与真实服务器连接身份的接线仍缺。
- `GamePlatformSession` 目前只有私有状态内核；文档明确没有公开服务、真实连接/准入适配器或服务端连接租约执行器。它不是可直接接入的完整会话服务。

以上均为源码静态证据。本设计阶段没有重新运行头文件审计、Go 检查、UE 构建或联机验证。

## 3. 架构与依赖方向

```text
DivineBeastsApplicationFlowClient（项目流程组合）
  ├── GamePlatformApplicationFlow（唯一流程执行器）
  ├── GamePlatformOnline（认证与资料；令牌不外泄）
  ├── GamePlatformSession（加入／迁移／重连／退出状态与客户端会话服务）
  ├── GamePlatformLoading + Data + DBAWorlds（必要资源和当前世界屏障）
  └── GamePlatformServer（服务器实例生命周期和真实连接准入适配）

Game Client → Gateway（验证 Bearer，派生玩家/会话身份）
  → GameServerControl（内部服务认证、选择已就绪目标、持久准入编排）
  → PostgreSQL admission kernel（Reserve/Claim/Commit/Release 原子状态）

目标 Dedicated Server（服务器服务身份 + 真实连接身份）
  → GameServerControl（Claim/Commit/Release）
  → GamePlatformServer（仅准入已验证连接；执行权威租约）
```

插件依赖维持单向：项目层依赖平台服务；Session 不导入 DivineBeasts；Online 持有凭据与在线 HTTP 传输，不向 Session 或项目代码返回访问令牌；Session 定义中立操作/后端能力契约，具体在线适配在允许的组合/适配层实现，不能构成插件循环。实际模块边在实施计划前以 `.uplugin`、`Build.cs` 和公开头复核。

## 4. 业务数据流

### 4.1 玩家请求目标世界

1. 项目组合提交世界加入意图和幂等操作身份；HTTP 请求只包含项目允许玩家声明的目标意图和必要版本/幂等字段，不允许指定 `PlayerID`、`SessionID`、服务器启动代次、连接ID、后端Epoch或权威端点。
2. Gateway 验证 Access Token，从 Identity 返回值取得 `PlayerID`／`SessionID`；读取 PlayerData，并验证所请求世界/体验、角色归属和新手路线资格。请求身份或项目输入不合规时拒绝，不回退为默认玩家或默认成功。
3. Gateway 通过受保护服务间调用将已验证的授权决策传给 GameServerControl。GameServerControl 选择自身注册表中的健康目标实例，核对三服务器角色、体验、世界、协议、版本和容量；生产选择不能只依赖进程内 map。
4. GameServerControl 创建短期授权记录及准入预留，随机生成至少 32 字节材料，仅持有原文到安全交付完成；数据库只存摘要。相同逻辑操作重试返回相同预留状态，不重复占容量或生成互不关联的材料。
5. 客户端得到最小目标连接信息与一次性材料，通过有界且已验证的安全传输交给目标连接；材料不放入 URL、命令行、日志、游戏存档或普通流程快照。具体 UE 传递方式必须先通过第 7 节引擎验证门禁。

### 4.2 目标服务器领取并提交

1. Dedicated Server 通过受认证服务身份确定 `InstanceID`、`BootID`、协议版本；真实握手钩子生成不可复用 `ConnectionID`，并将其绑定到当前 `UNetConnection`。服务器不能信任客户端自报连接标识。
2. 服务器适配器用真实连接身份和一次性材料调用 Claim；数据库只允许该实例/启动代次/Attempt 的摘要匹配，第二连接重放失败。
3. 完成后端提交并取得单调 `SessionEpoch` 后，服务器才激活该玩家权威状态；服务器在租约到期前停止权威并按确切身份续租或释放。租约无法保证时不得宣称避免双活。
4. 取消、超时或响应丢失时调用者保留不确定状态并查询；Cancel 若发现 Commit 已赢，必须转入查询/Leave，不能上报“取消成功”。退出、迁移来源释放与服务器排空遵循所有权顺序。

### 4.3 单一应用流程执行器

1. 项目组合按当前 Flow 公开合同，为每个等待用户输入或异步业务操作配置有限 DAG 阶段；阶段的真实操作由本次运行独立的 `UGamePlatformCallbackFlowNode`/`UGamePlatformFlowNode` 执行，不在项目子系统另存可推进业务的第二套节点状态机。
2. 节点从 `FGamePlatformFlowContext` 捕获 `Handle`、`NodeId`、`NodeGeneration` 并提供完成委托；异步完成只通过平台完成邮箱或 `SubmitEvent` 回投。过期句柄、重复回调、跨 GameInstance 回调不得影响新操作。
3. 用户暂停点以终态/输入状态呈现；后续用户动作启动同一平台子系统中的下一段流程，不修改执行器私有数据，不依赖旧 `TransitionTo`。业务资料、选中角色和服务返回值作为明确 Payload/领域快照管理；ViewState 是只读投影。
4. `OnFinished` 与 `GetSnapshot` 是状态来源；开始、取消、超时和反初始化都清理活动 HTTP 请求、节点委托、Session 操作和 Loading 租约。只有实际目标世界包、Experience/World 身份、角色控制器、必要玩法数据与后端准入事实匹配，才能向 UI 投影 InWorld/Ready。

## 5. 契约与后端业务约束

- Shared `GamePlatform` OpenAPI/Proto 是 UE-Go 唯一公共真源；新增世界准入/取消/查询及可信服务器 Claim/Commit/Release 操作前审查已发布字段号、错误码和兼容窗口。生成代码只由仓库锁定的工具链生成。
- Gateway 新玩家路由必须走 `requireAuth`，请求 DTO 使用字段白名单解析、请求大小限制、幂等键和脱敏错误；身份字段只由认证上下文注入。
- GameServerControl 的所有 `/internal/v1/gameservers/*` 路由均需服务端鉴权；服务器请求还核对已认证实例主体与请求实例。禁止将玩家接口直接映射到内网管理 API。
- 准入存储使用真实 PostgreSQL 生产适配与版本化迁移；不得使用进程内 map 或测试替身冒充生产 Reservation/Binding 唯一性。同步 server registry 与 `session_instances` 的 Ready/BootID/健康期限/容量事实要有明确事务/撤销边界。
- 当前已有 HMAC TransferTicket/Redis replay 与 PostgreSQL Session Admission 是两套不同模型。迁移必须选择唯一活动合同并给出兼容窗口；不同时让同一加入流程写两个准入真源，不直接删除旧字段、路由或迁移历史。
- GameServerControl 的统一 Assignment、内部控制 RPC、网关路由、OpenAPI 文档和错误语义同步更新；Swagger 中文说明清楚标记公网玩家接口、可信内部接口与服务器身份要求。
- 角色限定为 OpenWorld、Village、MainArena；大厅是 OpenWorld 体验。后端仍保持五薄入口，不创建第六服务或 DivineBeasts 专属的平台机制。

## 6. 错误、取消和安全语义

| 情况 | 必须行为 |
| --- | --- |
| Access Token 缺失、过期或主体不全 | Gateway 拒绝；不调用 GameServerControl；不向客户端泄漏下游正文。 |
| 重放不同操作内容的幂等键 | 返回稳定冲突错误；不改变既有预留或绑定。 |
| 目标实例未 Ready、BootID/Protocol 不符或容量不足 | 失败关闭；不产生客户端可用票据。 |
| 同一个 Claim 因网络重试 | 只对完全相同的真实服务器连接幂等成功；另一连接明确拒绝。 |
| 后端响应丢失，提交结果不确定 | 按授权主体查询；不盲重发不同材料、不把不确定改成已失败或已成功。 |
| UE 连接、地图或控制器准备失败 | 取消未提交预留；若提交已胜则发起受控 Leave/Release 并等待确认，不假设本地取消能撤回远端。 |
| 旧异步回调或跨世界回调 | 节点令牌/会话操作身份不匹配，拒绝提交且不触碰新操作。 |
| GameInstance、World 或服务器退出 | 先停止新请求，再注销委托/终结节点/撤销 Loading 租约，按所有权释放远端预留/租约。 |
| 准入材料缺失、日志异常或服务适配器不唯一 | 失败并给脱敏诊断；不自动切换旧明文路径或固定成功。 |

## 7. UE5.8 握手实现前置门禁

现有记录指出 UE5.8 `PreLoginAsync` 入参没有 `UNetConnection`，而 Session 数据库 Claim 必须绑定真实连接。实现计划的第一个技术调查必须重新针对本机锁定引擎头文件/源码、网络加密握手、连接对象生命周期和可安全传递的一次性材料完成证据闭环，至少证明：

1. 客户端与服务器能以 TLS/引擎加密保护的一次性通道交换材料，不把秘密放入 URL、命令行或可复制普通选项。
2. 服务器取得的身份来自已认证 Server Service Principal；其 `ConnectionID` 从正在准入的真实连接对象生成，而不是客户端 JSON/Options。
3. 一次性材料、服务器进程 BootID、目标 InstanceID、Reservation、玩家绑定和 Protocol 不能跨实例/连接重放。
4. UE 回调时序允许在玩家受权威激活前完成 Claim/Commit；失败和断开能确切取消或释放，竞态响应能查询收敛。

若任一项无法证明，实施可继续完成后端路由鉴权、持久预留内核与不宣称 Ready 的客户端请求阶段；不得实现“准入完成”、启用正式网络入口或称为端到端完成。必须先提出可审查的引擎集成方案与威胁边界。

## 8. 实施分段建议

1. **接口与安全边界盘点**：重新核对并行变化的 Online、Server、Backend 公开接口与 Git 工作树；调查锁定 UE5.8 真实握手钩子。输出字段来源图和不支持结论，不改代码。
2. **后端受保护玩家分配 API**：扩展 Shared 真源和生成物；增加 Gateway 认证路由/下游端口；封闭 GameServerControl 内部未鉴权路由；验证用户身份不受请求体冒充及所有内路由默认拒绝。
3. **持久目标与准入业务接线**：接入授权记录、服务器 Boot/Ready 注册、PostgreSQL reservation/claim/commit/release；处理生产 registry 一致性、幂等、取消与不确定结果。测试必须使用隔离的真实 PostgreSQL 适配，不把内存单测等同生产持久化。
4. **平台 Online/Session/Server 适配**：只在第 7 节通过后，暴露不含令牌的认证请求能力与 Session 客户端 API；接入服务器真实连接生命周期及权威租约。不让 GamePlatformSession 引入项目依赖。
5. **DBAClient Flow 迁移**：改为当前节点工厂/DAG/回调和 Flow 句柄；搬迁认证、资料、角色、世界分配和就绪操作；删除旧 API 和幻构 Session 类型引用，保持 UI 投影与现有 Loading 所有权。
6. **文档、生成、构建与验收**：更新 Backend/Shared 与插件细化目录说明、Gateway/GameServerControl 中文 Swagger、DBAClient/Online/Session/Server API、总体规划和执行记录。先运行共享生成检查、Go 单测/静态检查/竞态测试、真实隔离 PostgreSQL竞争测试，再跑 UE UHT 和 Editor/Client/Server 构建；只有真实网络连接/准入/退出联调才可声明端到端完成。

## 9. 变更范围与不包含项

预期可能涉及 `Shared/Contracts/GamePlatform/OpenAPI/` 与 `Proto/`、对应生成配置和 `Backend/generated/`、`Backend/internal/app/gateway/`、`Backend/internal/app/gameservercontrol/`、`Backend/internal/transport/`、`Backend/internal/platform/database/postgresadmission/`、`Backend/migrations/`、`GamePlatformOnline`、`GamePlatformSession`、`GamePlatformServer`、DBAClient 与 `Docs/`。实际文件清单须在实施计划前依据当前源码及 Git 状态确定，不把本清单当作直接建目录命令。

不包括：创建第六后端服务、改动三角色/五种竞技模式、引入新的认证系统或令牌格式、在公网/生产部署、应用数据库迁移到用户环境、改变账本/支付、通过 URL 传票据、接管项目内容资产，以及未经评审删除旧 TransferTicket 合同。

## 10. 设计自查

- **唯一流程执行器**：项目只注入节点/操作，不新增状态机执行器；符合平台 Flow 与根规则。
- **唯一身份来源**：Gateway 验证主体；服务器连接身份来自真实受认证服务器钩子；客户端不提交权威身份。
- **真实生产状态**：准入状态以 PostgreSQL 事务内核为准，不把内存 registry/map 或算法测试写成生产结果。
- **协议治理**：跨 UE/Go 字段只进 Shared 真源并经锁定生成器生成；兼容旧票据须独立决策。
- **未验证项明确停止**：UE握手连接绑定是实现硬门禁；本设计不预判引擎一定能支持。
- **验证边界清楚**：静态检查、Go单测、隔离数据库、UE编译、真实多端连接分别报告，不互相替代。

本规格待用户审阅通过后，才能编写任务级实施计划。用户审阅规格不等于允许生产部署；生产凭据、既有业务数据库迁移和正式发布仍需各自授权。
