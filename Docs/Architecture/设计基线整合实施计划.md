**目标：** 将工程增量整合到已批准的设计基线：40 个独立 GamePlatform 插件、4 个 DBA 项目插件、独立的 `MobaPresentation` 插件、OpenWorld/Village/MainArena 三类服务器角色，以及单一 UE 工程和统一 Server Target。插件描述总数为45。

**架构：** 保留每个插件独立 `.uplugin` 身份，按附件责任目录规范归位；项目专属身份、世界、客户端组合及服务器组合分别归四个 DBA 插件。协议以 Shared 为唯一真源，Go 保持现有五入口，按经过校验的角色 Profile 选择服务器职责。

**技术栈：** UE 5.8 C++ / UBT / UAT；Go；JSON Schema、Proto、OpenAPI 与仓库内 `Backend/internal/tools/contractcodegen`；PowerShell 7、Pester、Docker Compose。

## 全局约束

- 正式插件清单为40个GamePlatform + `DBAGameplay`、`DBAWorlds`、`DBAClient`、`DBAServer` + 独立的 `MobaPresentation`；总计45个描述。不得把 `MobaPresentation` 合并进 `DBAClient`，也不得增加其他插件。
- 正式 UE 工程为 `Game/DivineBeastsArena.uproject`；正式目标仅 Client、Server、Editor；三种服务器角色共用同一 Server Target 和程序，不建立 DevHost。
- 项目层只引用通用插件公开接口；服务器模块不引用客户端模块；共享模块不依赖任一端的专有实现；模块依赖无环。
- Shared 真源只改源契约。生成物只能通过 `Backend/internal/tools/contractcodegen` 生成或检查，不手改 `Backend/generated` 和 `Shared/Generated/Cpp`。
- 不覆盖现有目标文件的未提交修改；源目录只作为比对和缺失实现候选；每个碰撞文件先做差异合并。
- 旧插件只有在逐文件迁移、资产／反射／配置引用核对和可恢复快照均完成后才可退役；不先删后补。
- 不伪造 `.uasset`／`.umap`，不提交或打印凭据，不进行生产部署；未安装的 UE／Go 工具链不得声称已编译、烘焙或测试通过。
- 本次在当前用户指定工作树内实施，因为现有大量未提交和未跟踪文件不能安全丢失于新 worktree；不暂存或提交本轮以外的改动。
- 次级来源目录的 `AGENTS.md` 仍要求旧的 39 插件、三层目录和三角色规则，与用户刚批准的基线冲突；迁移时只把该文件当作来源工程证据，不复制其旧架构约束，最终统一修改当前工作区根规则和正式文档。

## 重点审查输入与失败路径

1. 服务器角色、体验或 Profile 不匹配：必须拒绝启动／准入，不能静默退回 OpenWorld。
2. 已删除的 Lobby 角色、重复注册或未知角色：生成检查和后端注册校验必须拒绝；既有主竞技场结果权限不能因大厅并入 OpenWorld 而放宽。
3. 源插件与目标同名文件内容不同：按目标现状逐项合并，不能以源目录覆盖；无法判断资产／类型身份时暂停对应迁移。
4. 客户端表现资产在 Server Cook 中被带入，或关闭竞技插件破坏通用世界：依赖审计与产物检查必须发现该边界错误。
5. 角色所需资源缺失与可选皮肤/VFX 缺失：前者阻止 Ready，后者只触发已验证基础回退且不能改变权威结果。
