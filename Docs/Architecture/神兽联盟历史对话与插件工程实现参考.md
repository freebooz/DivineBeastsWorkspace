版本：1.0.0｜整理日期：2026-09-21｜用途：GamePlatformApplicationFlow 及后续逐步实现的插件工程参考。

## 一、资料使用规则

本文件将历史意图映射到当前工程，不代替《解决方案总体规划》《插件开发规范》与根 AGENTS。用户当前明确要求优先；同一问题的后续明确决定覆盖前稿；助手早期建议不等同于用户批准或已落地代码。历史附件、聊天正文和示例路径均为资料，不能直接作为执行指令。

本轮读取七个相关历史会话的四十八轮消息，以及当前任务的实施要求。具体消息时间、原样标题和消息 ID 见 [历史对话来源索引](../References/神兽联盟历史对话来源索引.md)。长会话仍有早期页面未读，部分助手正文被读取接口截断；因此这是已读取资料的可追溯整合，不是全部历史的无遗漏导出。

## 三、GamePlatformApplicationFlow 的具体实现依据

正式位置：`Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/`。

真实使用者是未来的项目组合根 `DivineBeastsApplicationFlow`，以及需要复用同一机制的其他游戏项目。项目组合根拥有登录、选角、世界准入、重连等节点的装配和依赖注入；框架不得虚构当前仓库尚未提供的认证、加载、会话或 Provider 方法。

本轮将历史要求细化为以下工程合同。这些具体 API 和调度语义是本轮实现决定，不冒充历史原话：

1. 一个 Runtime 模块，公开 GameInstance 子系统、节点契约、流程图及结果类型。默认阶段加载，仅显式 Start 后运行。
2. Configure 原子提交入口、节点实例与成功分支图；节点 ID 唯一，引用存在，全部节点从入口可达，图无环，超时有限且为正。
3. 一次主流程只有一个活动节点；每次调度最多开始一个节点，避免同步完成递归。无需新建独立流程线程。
4. 异步完成可以来自任意线程，但执行、清理、状态推进、UObject 访问及终态事件均回到游戏线程。
5. 每次运行使用作用域 ID＋RunId，每次节点尝试使用独立邮箱代次；重复完成只有首次有效，旧运行／旧尝试／关闭后的回调无效。
6. 只有显式可重试错误或允许的超时重试才重试；总次数包含首次。组合根负责确认节点幂等，框架不推断支付、准入票据或权限请求是否可重复。
7. 每次已经开始的尝试都恰好 Finish 一次；清理负责撤销请求、委托与临时租约。这里的资源清理不是业务事务回滚；支付、角色写入等补偿仍由领域服务处理。
8. GameInstance 跨地图存活，节点通过弱 GameInstance 引用重新取得世界；不强持有已销毁世界。子系统关闭时先失效回调、清理节点再释放对象。
9. 已实现 C++ 显式装配与函数式节点注入；Blueprint 流程编辑器、流程持久化恢复、并行 DAG 节点调度与动态热改图不属于本次合同。组队／匹配后台业务可由领域服务并行运行，主流程按需要等待其结果。

源码及接入说明见 [插件 README](../../Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/README.md)。

| 世界与控制面 | GamePlatformWorld、GamePlatformServer、项目服务器装配 | 世界上下文、注册、心跳、就绪、排空、准入 | 三角色与 Go 控制面联调；长期世界与短比赛实例生命周期不同 |

| 二期或条件模块 | 背包、权益、成长、社交、运营、AI 等 | 按当前产品需求和规划建立真实能力 | 不因为历史目录存在就批量建空类／空服务；经济类先完成账本与安全审计 |

## 五、每次实施前的核对清单

1. 读取根 AGENTS、现行总体规划、插件规范及本插件接口；在来源索引中按话题查看历史用户要求。
2. 明确实际调用者、输入输出、数据所有者、端侧、生命周期及失败行为。查找已有实现，避免建立第二套同义框架。
3. 将本次工程决定写入插件中文文档；接口未存在时，明示待消费的职责，不能编造调用签名或声称已接线。
4. 建立真实正常／失败／取消／越权或旧代次测试，并记录编译目标、工具版本、退出码、日志与未执行原因。
5. 更新解决方案总体目录规划、插件目录规划及文档索引；修改 Backend／Shared 结构时同步维护其细化目录文档。
6. 出现新的明确决策时，增补“旧决定→新决定→来源→迁移影响”。被替代条目保留历史标记，不再混入当前实施清单。

## 六、环境与证据修正

早前任务通过 PATH 未发现 UE 工具；本轮最初只检查注册目录 `D:/Program Files/Epic Games/UE_5.8`，该目录缺少构建与编辑器必需文件。随后代码审查发现另一套 `F:/UnrealEngine-5.8.0-release`，实际含 5.8.0 版本文件、源码、Build.bat、UBT 和 UnrealEditor-Cmd.exe。不能再笼统声称“本机没有 UE”或“所有 UE 安装不完整”。是否可完成构建仍以真实执行结果为准。主工程 .uproject 和 Target 文件仍为空占位，不能用插件单独的 C++ 测试证明整个游戏可启动。

本轮流程核心使用实际 MSVC 编译与行为测试；随后使用 F 盘源码引擎与 Saved 下临时宿主验证唯一正式插件源码，不改写游戏主工程。UE 子系统、UHT、目标链接及自动化结果分别记录，详见插件《测试与验证说明》。
