# 插件测试门户 Implementation Plan

> 按已确认设计增量实施，使用 superpowers:executing-plans 和有意义的行为回归。

**Goal:** 登录首页「测试」进入门户，插件按钮直接打开对应独立测试页。

**Architecture:** 保留现有登录 Launcher、Catalog、Hub ViewModel、独立页及其清理合同。门户只投影 Catalog 快照并通过已有请求打开固定 PluginId；真实 UMG 由 Monolith 修改。保持客户端、服务器与 Editor 隔离。

**Tech Stack:** UE 5.8、C++、UMG、Monolith MCP、现有开发启动器。

**Spec:** `Docs/Implementation/PluginDemos/PluginPortal_Design_20261028.md`。

## 全局约束

- 首次快照加事件通知，禁止 UI Tick、常驻 Ticker 或定时器轮询业务。
- 不改其他工作者进行中的候选文件；保存现有用户数据与地图 PlayerStart。
- Cook/Bake、临时、Stage 和打包在当前工程目录，增量构建只覆盖受影响目标。
- Shipping/Test 隐藏开发入口；不得传递登录凭据，失败保留登录页。
- 真实 UMG 通过 Monolith 创建/修改、编译、保存和独立重载；自动结果不代替人工签收。

## 任务

- [ ] 核对当前 Hub 的真实数据、单击与键盘选择、独立页打开和返回/清理链。先补行为测试：稳定 ID、失活/旧来源、无效项、回调同步重入及固定页不接受跨插件导航。
- [ ] 增加门户项激活处理，鼠标和键盘激活共用现有 ViewModel 选择及请求路径；焦点移动仅选择、不自动进入。保留搜索筛选和旧独立页操作。
- [ ] 按目录真实元数据实现显示/筛选与可解释状态，动态数量、空结果、回页状态与键盘焦点；不将占位功能判成功。
- [ ] 直接 Monolith 保存、编译并重载门户布局、按钮行和登录入口文字；确保独立页现有控件树与业务流程不受破坏。
- [ ] 按锁定参数增量构建受影响 Editor/Client，运行所选原生回归及实际门户按钮、搜索、筛选、返回、失败场景；记录资产、构建、运行、人工验收各自结果。
