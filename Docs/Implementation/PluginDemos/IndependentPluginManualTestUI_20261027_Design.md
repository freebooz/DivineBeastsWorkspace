# SSLM逐插件独立人工测试界面设计

日期：2026-10-27。状态：用户已明确“确认设计并直接实施（包含必要构建）”。沿用既有《插件演示与人工核验中心设计规格》的方案A，不另建演示框架。

用户本次选择：从现有插件中心打开，每插件独立测试页，并可单独打开。

本次设计确认所包含的执行范围：编写必要代码、按锁定参数增量构建实际受影响目标、通过Monolith制作/编译/保存/重载真实UI，并进行实际界面验证；需要发布验证时才执行对应Cook/Stage。旧规格记录的“不构建”属于此前阶段限制，本次需用户明确确认上述范围后再实施，不把选定入口方式视为已授权改变该限制。不提交或推送，不关闭其他任务的编辑器，不把界面验证写成人工签收。

## 目标和覆盖范围

以本工程真实`.uplugin`和内容登记为准：当前70个插件，包含48个自研代码插件、20个内容插件、2个第三方编辑器插件。每个插件对应一份可寻址的真实UMG页面，插件中心可打开，受控开发启动参数也可直接打开指定插件页。

每个已经实现的功能都必须有人工可操作入口、参数、前置条件、预期结果、可观察状态和清理/恢复方式。功能按独立能力划分，不按函数数量或自动化测试数量凑覆盖率。盘点发现只有空模块的插件仍有独立页面，明确显示实际未实现的功能和来源依据，演示层不补造业务规则。

“页面已生成”“功能已接线”“真实运行通过”“人工验收通过”分别记录。完整交付要求70个独立页都能实际打开，已实现功能都具备真实接线；缺少适配器、资源或运行条件的项目不能计入已完成的功能测试。

## 界面和人工操作

每页锁定一个稳定PluginId，不使用显示名称猜测身份。页面包含下列区域：

| 区域 | 内容和操作 |
| --- | --- |
| 插件概要 | 中文用途、稳定身份、来源类型、运行端、依赖、实际功能审计状态 |
| 功能菜单 | 该插件的独立功能及正常、失败、取消、恢复等适用案例；能看见尚未接线的缺口 |
| 操作说明 | 准备步骤、真实资源/接口依据、操作顺序及预期现象 |
| 参数与控制 | 类型化输入、范围/单位校验；准备、执行、停止、恢复及该功能特有动作 |
| 可视样板 | 真实控件/三维世界对象/声音/资产预览；数值同时给出真实状态 |
| 诊断与证据 | 当前运行身份、来源版本、事件、错误、清理结果、截图/日志索引 |
| 人工结论 | 未测、通过、不通过、原因及证据；只有用户显式填写才能签收 |

复用现有玉石主题、固定字号、参数行和详情/控制/报告组件。鼠标、键盘及既有手柄导航使用同一操作链。窗口变化仅适配布局，不缩放整页掩盖可读性问题。

同一本地玩家同一时刻只有一个活动插件页；切换前停止并清理当前案例，清理失败时保留诊断并拒绝静默切走。不同客户端/World互相隔离。直接打开插件页和从中心进入执行相同的资格检查。

## 真实测试的宿主边界

| 功能类别 | 执行方式 |
| --- | --- |
| 客户端UI、输入、音画、镜头、资产预览 | 当前开发客户端或PIE，经现有平台公开能力运行，真实呈现结果 |
| 基础契约与本地服务 | 每案例独立夹具/租约，实际调用插件实现；保存只写本工程验证目录 |
| 服务器权威、GAS、战斗、AI | 使用具有真实权威的隔离案例或已登记的开发服务器；客户端页面不能直接写复制状态或伪造命中 |
| 联网、身份、背包、权益、商城等 | 先核对开发/沙箱端点和资格；无服务时明确阻塞，不读取生产凭据，不由演示页补业务权威 |
| PCG、材质制作、编辑器工具及第三方编辑器插件 | 页内选择操作和对象，经Editor专用桥调用既有编辑器实现；普通打包客户端显示所需宿主，不链接Editor模块 |
| 内容包 | 核对注册/撤销及资源加载，按包内容提供模型、材质、动画、图标、声音和世界检查；文件存在不代替真实预览 |

自动化测试可作为辅助验证，不能替代用户手动操作和视听观察。需要真实Village/MainArena联网验证时，先执行现有双端战斗版本与Cook/Stage门禁。

## 与现有实现的连接

1. `Docs/Implementation/PluginDemos/PluginDemoManifest.json`继续作为唯一人工维护的功能/案例作者源，补入实际70个身份与经源码核实的功能记录。独立页资产路径属于插件条目，不另建竞争清单。
2. 在既有`DivineBeastsDemoHubScreen`和`DivineBeastsDemoHubViewModel`链中增加固定插件上下文与直接打开路由；各页拥有独立页面生命周期，详情/控制/报告子页只借用该页唯一模型。
3. 保留`IDivineBeastsDemoScenarioAdapter`、每World运行状态和证据链。逐功能接入实际公开接口，类型化参数不能变成任意脚本文本或反射调用后门。
4. 通用机制继续归GamePlatform；项目编目、开发界面和适配归既有DBAClient；MOBA适配由竞技组合根注入。第三方只增加来源类型，不增加第四架构层。
5. UMG资产统一归`DBAUIPack_Core`既有开发资源范围，路径采用`/DBAUIPack_Core/Development/PluginDemos/UI/Plugins/WBP_DBA_PluginTest_<PluginId>`；复用既有`Development/PluginDemos/Definitions`下的页面定义合同。复用已存在的样板，避免复制70套视觉逻辑或空地图。
6. 所有状态更新使用首次快照加事件通知。取消、换页、换World、来源换代和销毁时成对解绑、清理自身对象/计时器/租约，迟到结果不能恢复旧界面。

## 方案比较和决策

已选方案是现有插件中心中的独立页面：复用现有目录、操作与证据链，支持直接打开，同时保持统一的输入、生命周期和主题。

另一种方案是每插件独立编辑器窗口，适合编辑器工具，却无法统一代表真实客户端和服务器表现；本次用户未选择。独立程序或第二工程会复制装配与构建职责，不符合当前单一正式工程规则，本次不采用。

## 实施与验收

按“功能盘点与清单校验→独立页导航与生命周期→各领域真实适配→Monolith原生资产→构建和运行验收”推进。盘点依据及缺口保存在本工程`Saved/Validation/PluginManualUI20261027/`，不把待审计插件显示成100%覆盖。

- 逐插件核对规范、Public接口、配置/定义、真实调用和已有测试，审计未完时保留partial。
- 逐功能验证正常、失败、非法参数、取消、停止/恢复、重复操作、迟到回调和World退出等适用项。
- 经直接Monolith MCP创建/修改70份真实UMG资产，编译、保存、独立重载，核对PluginId、父类、控件合同、焦点和导航。
- 验证从中心和直接入口都能打开对应页，插件禁用、宿主错误和资源缺失时有具体原因；跨插件不会串状态或命令。
- 完成受影响目标的锁定参数增量构建及最小有效原生回归；实际客户端视听和人工签收单独记录。Shipping/Server不暴露开发界面与开发命令。
- 所有Cook/Bake、中间文件、Stage、Package和证据均留在当前工程目录内，路径过长也只在工程内部使用短目录。保留既有工程、模型、对话及其他任务编辑状态，不关闭他人编辑器。

实施者可自行决定具体排版数值、逐插件顺序和已存在组件的复用细节；不得改变上述范围、唯一执行链或通过标准。新增的底层业务能力超出界面任务，应登记到所属插件，不能在演示层伪造实现。
