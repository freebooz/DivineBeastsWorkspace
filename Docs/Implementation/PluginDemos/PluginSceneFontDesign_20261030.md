# SSLM 插件演示关卡与统一 10 号字体设计

日期：2026-10-30。状态：用户已批准并要求继续实施。批准时尚未修改运行源码、现行配置或 UE 二进制资产。

## 意图与已确认范围

需要人工观察或试听的插件功能，应能从该插件独立测试页进入对应的真实演示关卡，操作、观察、停止并返回。用户已明确：统一 10 号字体同时包含插件编辑器界面和游戏运行时界面。

当前静态审查覆盖 70 份真实插件描述、288 项登记功能、211 个案例及 390 个审核用例。70 个独立插件页文件均存在；151 个案例指向 Hub，57 个未指定地图，3 个指向鸟群地图。文件引用检查无缺失，但未证明资源类型、场景内容或实际字体。完整逐插件关系见 [审查报告](PluginSceneFontAudit_20261030.md)。

本次确认的是场景和界面整改，不代表补齐所有插件尚未实现的业务功能；遇到业务或资源缺口必须在对应页面显示具体阻塞，不能在演示层伪造成功。

## 实施方式与替代方案

沿用已批准的 `PluginDemoCenterSpecification.md` 方案 A：唯一演示中心、每插件独立页、相关功能可共享场景、逐功能独立审核。补齐其关卡对应和字体合同，不创建新插件或第二套演示执行器。

替代方式一是为每个插件都复制一个独立地图。这会让纯诊断功能产生无意义空场景，也会重复维护相同光照、测试对象和宿主，因此不采用。替代方式二是所有效果继续留在 Hub，仅增加说明文字；它不能保证地形、水体、雪接触等有适合观察的真实对象，因此不满足要求。

实施时优先原生核验并复用已有合适地图；仅在场景缺失或不可用于当前功能时创建最小专用关卡。共享地图必须在编目中显式登记每个使用案例及插件归属，不能按文件名推测所有者或继承其他案例的审核结果。

## 关卡与插件页对应

`PluginDemoManifest.json` 继续作为唯一人工作者源；其现有 `feature_id`、`scenario_id`、`map_asset`、`widget_asset`、`adapter_id`、`review_case_ids` 表达功能、场景、页面、适配器与审核关系。Catalog/DataAsset、页面说明和校验均从它派生，不维护第二份运行时路由表。

功能选择后应清楚显示插件、功能、目标关卡和宿主资格。用户明确进入场景，成功加载目标 World 后再准备该案例。场景内保留对应插件的操作界面或轻量覆盖层、返回入口和停止操作；不得一直显示错误插件或失效案例的控制按钮。切换场景前执行既有 Stop；清理失败留在当前页并允许重试。

## 10 号字体合同

1. 项目插件自有文字统一使用 Unreal `FSlateFontInfo.Size = 10`：标题、正文、按钮文字、标签、列表行、搜索/输入、下拉框、状态、错误、提示、通知、HUD 和富文本的自有文本样式均在范围内。字号不保留标题例外。
2. 10 指字体属性值，不将其解释为 10 个屏幕像素；沿用实际 DPI/视口布局规则。不得通过 RenderScale、整页缩放或额外 Gamma/图像处理补偿字号。
3. 复用现有主题/文本样式与平台 UI 机制。核对 `bPreserveFontSize` 的真实调用链：资产自身已是 10 时可以保留；不能只将主题设为 10 而让旧资产和动态创建控件继续使用其他字号。
4. 修正当前 C++ 动态字体写入，包括相机演示的 14/18/13、技能快捷键的 12；审查其他直接及继承样式赋值。Slate 自有控件通过局部字体/样式设置为 10，不全局篡改引擎 AppStyle/CoreStyle。
5. 真实 UMG 源资产通过 Monolith 逐批修改、编译、保存、独立重载；检查 TextBlock Font、EditableTextBox `WidgetStyle.TextStyle.Font`、多行输入、ComboBox 的项目自有样式及 RichText 样式表。不能只修改旧的无效 Font 字段或仅在运行时覆盖来冒充资产已整改。
6. 同步当前作者配方、验证脚本和真实主题，撤换 `ValidateFrontEndInputFonts.py` 的 16 号断言与当前 Monolith 配方的 18/20/28 要求。历史审核记录保留原值和日期，不重写为本次已通过。
7. 第三方插件的项目自有菜单/面板在范围内；其借用的引擎图编辑器、用户图节点评论字号和引擎全局界面不作为插件字体整改的改写对象。若插件自有文字无法局部覆盖，登记确切控件和阻塞，不声称全覆盖。

现有 160 个 `WBP_*.uasset` 是磁盘文件名候选，不是 Widget 类的权威总数。实施时通过 AssetRegistry/Monolith 核对当前活动 WidgetBlueprint、其父类、嵌套控件和主题/文本样式，识别无 WBP 前缀或继承样式的资产；历史/退休资产不得重新发布为当前资源。

## 所有权、生命周期与风险控制

通用机制仍归 GamePlatform；MOBA 只提供可选竞技语义；项目适配归 DBAClient，公共视觉归 DBAUIPack_Core，世界/英雄资源留在各自内容包。演示调用现有平台服务、Data 租约、World/LocalPlayer 与清理状态机，不增加播放器、资产管理器或第二套权威实现。

UI 首次读取快照，此后通过现有通知更新。失活、切页、取消、世界退出和账号/角色代次变化解绑并清理自身工作；迟到回调不能恢复旧界面。不为本次整改新增 Tick、Ticker 或轮询计时器。

当前 `main` 有 17 个已修改文件和 6 个未跟踪项。实施前对目标文件再次核对 diff；用户已改的 Village 地图、植被资源、水体 Build.cs 等不整树覆盖。目标原生包有未保存编辑或内容分歧时，保留并停止该包的写入，完成其余无冲突工作。

全部资产修改使用当前正式工程的 Monolith；先核对工程、引擎、内容挂载和可加载类。保存前在工程内记录精确备份与指纹，原生重命名仅在单独影响检查后进行。当前 Monolith 返回编辑器未运行，实施首先需要建立可用的正式编辑器连接。

调试使用 `t.MaxFPS 0` 并检查实际状态；不主动开启 VSync 或设置正数上限，不覆盖玩家持久化偏好。进入实际 Village/MainArena 的验证另走 Client/Server 战斗版本门禁；本地独立演示不冒充网络准入。

## 验收与实施顺序

1. 从逐插件关系表生成需要视听核验的实际功能工作单；原生检查 Hub 动态舞台、已有候选地图和对应 UI 控件。明确可复用、需补对象、需新建关卡或被真实业务缺口阻塞，保留逐项依据。
2. 在现有机制上补场景和显式导航；更新唯一作者编目并派生目录/说明。运行既有结构与关系检查，补充缺场景、错插件/案例、缺资源、取消和返回的必要回归。
3. 统一当前活动资产、Slate 与 C++ 动态字体及作者/验证合同；原生回读所有实际有效字体，编译、保存并独立重载。运行相关字体及 UI 生命周期回归，不把文本扫描当作字体渲染验收。
4. 必要源码变更走既定 `Build/Game/BuildFoundation.ps1` 增量参数；完整目标、UE 自动化、资产原生操作、Cook/Stage 和运行分别记录。仅在资源/发布验证需要时执行受影响 Cook/Stage，全部输出、临时和备份均留在当前工程内。
5. 实际操作“插件页 → 功能 → 场景 → 执行/观察 → 停止/取消 → 返回”并记录真实目标 World、控件、操作结果、截图及必要动态视频/音频。检查字体 10、文字可读、输入光标/提示和布局无截断，至少覆盖 1920×1080 与较小窗口及 DPI 变化。
6. 用户逐项确认视听效果；测试脚本不得签人工通过。VFX 保留当前单技能人工审核顺序，不扩展新技能制作。GPU/性能未经测量保持未验证，不能以关卡或字体修改宣称可投产。

本阶段交付审查和设计；批准后编写按文件、接口与验证拆分的实施计划，并完成上述整改。未通过的关卡、字体、构建、Cook/Stage、运行或人工门禁应列明实际状态。
