# 《神兽联盟》十大业务领域用户界面目录与基础类实施说明

> 工作区：DivineBeastsWorkspace（神兽联盟工作空间）
> 目标：复用三层平台机制，按领域提供真实可继承的 C++ 页面、HUD、Panel 和只读 ViewModel。
> 实施日期：2026-10-09
> 交付类型：源码及测试；不在缺少有效 Monolith 编辑器会话时伪造 Widget Blueprint（控件蓝图）资源。

## 一、架构归属与可选边界

1. **GamePlatformUI（跨游戏平台界面层）**：`GamePlatformUIClient` 唯一负责 UCommonUserWidget / UCommonActivatableWidget（普通／激活控件）、RootLayout（根布局）、层栈、UIManager（界面管理）、通用加载/反馈/通知/世界投影、平台适配和 UI ViewModel 生命周期。
2. **GamePlatformArenaClient（MOBA 通用竞技界面层）**：保留 `GamePlatformMobaArenaScreenBase`、`GamePlatformMobaArenaHUDBase`、`GamePlatformArenaViewModel`。`MobaPresentation` 只提供 MOBA 表现事实映射，不建立第二套 UI 插件。
3. **DBAClient / DivineBeastsUIClient（项目非竞技客户端界面层）**：保存公共 UI 页面、世界/角色/战斗领域类和社交、系统、运营扩展类；公共视觉资源只放 `DBAUIPack_Core` 内容插件，不在 C++ 中动态伪造 Widget 树。
4. **DBAArena / DivineBeastsArenaClient（可选竞技客户端界面层）**：匹配、准备、竞技英雄选择、积分榜、赛后结算和竞技 HUD。关闭 DBAArena 后公共登录、世界、角色、任务和背包仍可运行。
5. **专业业务插件保持数据真源**：GamePlatformInventory/Quest/Settings/Input/CommerceUI/Online 和竞技运行层各自持有事实、缓存、命令、权限和权威；UI 只投影事实，禁止自己实现另一套设备设置、经济账本、社交后端或匹配判定。

## 三、十大业务域与基础类状态

- **Core（核心框架）**：复用 `UDivineBeastsUIScreen`、`UDivineBeastsRootLayout`、`UDivineBeastsViewModelBase`、平台路由/通知/加载；Boot、ErrorReconnect、LoadingTravel 的可视蓝图仍分别验收。
- **Account（账号）**：`UDivineBeastsAccountScreenBase` 新增已认证状态、忙碌、错误只读接口；`UDivineBeastsLoginScreen` 继承此类，仍通过原有命令端口认证。
- **World（世界）**：`UDivineBeastsWorldScreenBase` 提供世界标识投影，既有 QuestScreen 继承它；`UDivineBeastsWorldHUDBase` 统一 OpenWorld/Village/Tutorial/Training 四种 HUD；业务地图、任务详情和真实蓝图分批实现。
- **Character（角色）**：`UDivineBeastsCharacterScreenBase` 接入当前持久角色列表、可创建英雄和选中身份；现有 3D 角色预览基类作为中间层继承本类，创建和选择蓝图名称不变。
- **Inventory（背包）**：沿用已存在的 `UDivineBeastsInventoryScreen`；继续消费 `GamePlatformInventoryClient` 缓存事件，避免创建重复背包对象和命令接口。
- **Combat（战斗）**：`UDivineBeastsCombatPanelBase` 提供只有快照变化后才递增的表现修订与蓝图通知，玩家状态、技能条两类面板改为继承此类；战斗数值仍由现有战斗/GAS系统提供。
- **Social（社交）**：`UDivineBeastsSocialScreenBase` + `UDivineBeastsSocialViewModel` + `FDivineBeastsSocialUIProjection`；具备来源隔离、最新版本、队伍最多10人/好友最多256条的本地快照容量门禁。**当前未接入生产社交服务，不伪造好友或队伍数据。**
- **Arena（竞技）**：完全复用第二层 `GamePlatformMobaArenaScreenBase` 和 `DBAArena` 既有 `DivineBeastsArenaScreenBase`，不让公共DBAClient依赖Arena。实际竞技蓝图仍未交付。
- **System（系统）**：`UDivineBeastsSystemScreenBase` 复用 `UGamePlatformUIManagerSubsystem` 的无障碍偏好读写及平台校验；设备设置、键位映射和音效参数仍归领域服务，**尚未新增设置菜单蓝图**。
- **LiveOps（运营）**：`UDivineBeastsLiveOpsScreenBase` + `UDivineBeastsLiveOpsViewModel` + `FDivineBeastsLiveOpsUIProjection`，仅投影已发布公告/活动/邮件摘要，来源与修订隔离、单页最多128条；商城/购买/发奖仍交给 `GamePlatformCommerceUI` 及服务器。**当前尚未接入真实运营数据服务。**

## 四、生命周期、事件和资源边界

- `UDivineBeastsScopedDomainViewModelBase` 以 `BeginSourceScope(FGuid)`（开始数据源作用域）和 `ClearSourceScope()`（清除作用域）管理数据隔离；投送快照前必须验证 `SourceScopeId`（来源身份）、严格递增 `Revision`（修订号）、列表容量和业务字段。新账号登录后必须显式开启新作用域。
- 普通页面和HUD通过已有平台生命周期触发 `OnViewStateChanged`（视图变化事件）；离页即解绑。新ViewModel默认没有任何外部来源，不能仅凭类文件存在就宣称好友、设置或公告业务已接通。
- 文本、HUD、图标、资源条和响应式布局由 Monolith MCP 在真实编辑器中创建保存；不允许通过源码脚本伪造二进制资产。
- `NativeTick`（逐帧更新）、`AddToViewport`（业务直接挂载）和Widget直接HTTP继续禁止。UI不判断服务器角色权限、竞技胜负、背包移动及商城货币交易。
- 所有新增领域模块都留在现有 `DivineBeastsUIClient`，不新增虚假的社交、商城、MOBA或设置插件；Dedicated Server（专用服务器）不链接这些客户端类。

3. `Tests/Architecture/TestUIDeliveryInventory.ps1`：静态检查十大领域基类、20项现有登记和已有6控件+2纹理的实际文件存在情况。
4. UE5.8 `DivineBeastsUIClient` 定向构建与原生Automation；任何UE构建、PIE、Cook或真实客户端测试必须单独记录实际结果。
5. 尚未实施的业务接入和Widget Blueprint应列为待交付，不进入“已完成”统计；移动端、生产账号权限和网络容错仍需真实场景验证。
