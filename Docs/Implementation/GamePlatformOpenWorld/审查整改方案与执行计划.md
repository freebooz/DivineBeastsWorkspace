# GamePlatformOpenWorld 审查整改方案与执行计划

日期：2026-09-29  
对象：`Game/Plugins/GamePlatform/World/GamePlatformOpenWorld`

## 1. 审查结论

`GamePlatformOpenWorld（游戏平台开放世界上层策略候选插件）` 当前不具备可继续保留为正式代码插件的独立职责。

实际源码只有两个模块注册入口：

- `GamePlatformOpenWorld — Runtime（共享运行模块）`
- `GamePlatformOpenWorldServer — ServerOnly（仅服务器模块）`

没有公开契约、Definition（定义）、服务、组件、子系统、测试、真实资源或外部消费者。全工作空间引用扫描仅发现架构文档、基线审计与插件自身文件，没有运行时代码依赖该插件。

现有开放世界基础职责已经有明确所有者：

- `GamePlatformWorld`：世界身份、区域、流送、就绪与世界生命周期。
- `GamePlatformPCG`：程序化生成、烘焙与检查。
- `GamePlatformNavigation`：导航能力。
- `GamePlatformInteraction`：权威交互。
- `GamePlatformAI`：AI 机制。
- `DBAWorlds` 与项目 Definition／内容包：神兽联盟大厅、主城、野外和项目世界规则。

因此继续保留该空壳会造成“插件数量驱动设计”，并诱导后续把不相关能力聚合为万能 OpenWorld Manager，与既定高内聚、低耦合、禁止空插件规则冲突。

## 2. 三层架构判定

本次退休不改变三层架构：

`DivineBeasts（项目层） → MobaCommon（MOBA通用层） → GamePlatform（平台层）`

`OpenWorld` 仍然是正式服务器角色，但“服务器角色”不等于必须存在同名平台插件。项目 OpenWorld 策略继续由项目层组合平台能力，不把生肖、主城、大厅、野外活动等项目语义下沉到 GamePlatform。

退休后正式代码／机制基线调整为：

- GamePlatform 稳定身份：39 个，其中平台层 38 个、MobaCommon 中 `GamePlatformArena` 1 个。
- 独立 `MobaPresentation`：1 个。
- DivineBeasts 项目代码插件：5 个。
- 合计：45 个代码／机制插件；真实内容插件按 `ContentPackRegistry.json` 另计 N。

## 3. 发现的问题

### P0：空插件与正式基线冲突

插件只有模块入口，但被正式基线强制要求存在。该状态与“不得为占位创建空描述文件、空模块”的工程规则直接冲突。

### P0：职责重复风险

候选职责 Dynamic World Event（动态世界事件）、Zone Activity（区域活动）、Population Scheduler（人口调度）目前没有真实消费者。若直接实现，会与 World／PCG／AI／Interaction 等现有边界发生职责重叠。

### P1：端侧声明没有业务证明

`Runtime + ServerOnly` 只是宿主分类，不构成端侧设计。当前没有可验证的客户端／服务器数据边界、网络权威、复制、重连、状态恢复或资源隔离需求。

### P1：无法形成有效性能结论

插件没有 Tick、RPC、复制、异步任务、资源加载或运行态对象，因此不存在可优化的运行热点；真正的问题是无效模块与长期维护成本。

### P1：缺少独立测试和审查入口

没有自动化测试、Manual Review（人工审核）、API 文档或真实消费者，无法达到重要插件最低验收标准。

## 4. 最佳修改方案

采用“正式退休空壳”而不是“为了保留身份补代码”。

1. 从正式 GamePlatform World 分类与结构基线中移除 `GamePlatformOpenWorld`。
2. 删除空 `.uplugin`、两个空模块及其 README。
3. 更新 DesignBaselineAudit（设计基线审计）与行为测试，新的基线拒绝再次出现该插件。
4. 同步 AGENTS、插件规范、总体规划、插件清单、目录规划、核心要求和 P0 审计。
5. 保留 `OpenWorld` 服务器角色以及 `GamePlatformWorld` 等现有能力，不修改 Shared 协议、服务器角色、地图身份或资产身份。
6. 未来若出现至少一个真实跨项目消费者，并能明确输入／输出、数据所有权、生命周期、网络权威、端侧与验收方式，再新建立项；不得直接恢复旧空壳。

## 5. 未来重新立项门槛

只有同时满足以下条件才允许新增开放世界上层通用插件：

- 至少一个真实项目消费者，且需求不能合理归入现有 World／PCG／Navigation／Interaction／AI／Quest／Gameplay。
- 职责可用一句话准确描述，并能定义稳定公开契约。
- 能证明跨项目复用价值，而不是神兽联盟项目语义下沉。
- 能明确 Dedicated Server 权威、复制／恢复、跨地图清理和多 PIE 生命周期。
- 有独立自动化测试或 Review Harness（审核宿主）入口。
- Client／Server／Editor 目标与 Cook／Stage 边界可被真实验证。

- 源码与工程声明搜索未发现 GamePlatformOpenWorld 运行引用；Shared 契约搜索同样为0。

## 8. 回退策略

本插件没有运行时消费者、反射公开类型、资产或协议身份，因此退休不需要 Core Redirect、资产迁移或协议版本升级。若回退，只能通过版本控制恢复本次删除的空壳文件和对应基线条目；不得把旧空壳误标记为已实现功能。
