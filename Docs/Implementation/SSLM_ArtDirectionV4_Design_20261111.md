# SSLM全局美术艺术指导与视觉质量体系 V4.0 设计规格

版本：V1.0｜日期：2026-11-11｜目标版本：SSLM V4.0

## 1. 目标

在V3.0已确认的明快自然配色、山水画式场景构图、新手村湖边群山与峭壁专属基准和全场景柔和艺术光照基础上，建立覆盖构图、形态、光色、材质、生态、水体建筑、战斗可读性和实时性能的全域美术规范。让“每一个游戏画面都是一幅山水画、爽心悦目”从审美目标转为可执行、可复用、可验收的制作体系。

## 2. 用户已确认的视觉方向

- 全部场景光照柔和，突出光影艺术美感。
- 每个游戏画面都应具有山水画式构图和舒适悦目的观感。
- 用户2026-11-11提供的参考图只作为新手村湖边群山与峭壁专属基准，不复制到其他地图。
- 保留东方幻想、艺术化写实、自然明快色彩和战斗可读性。
- 场景美感不得牺牲玩法、公平、实时性能和多端适配。

## 3. V4.0范围

- 八大艺术体系：山水构图、形态语言、柔和光照、区域色彩脚本、艺术化PBR、自然生态、水体建筑融合、战斗视觉可读性。
- 五项高级技术：Painterly PBR、Regional Color Script、Art-directed Lighting、Multi-scale Detail、Visual Readability。
- UE5.8实现方法：Lumen/VSM/SMRT/天空大气/雾效/RVT/Nanite/PCG/SpeedTree/水体/性能分析。
- Lighting Lab映射：L1光照曝光基线为当前V1范围；L2—L8为后续扩展任务，分别覆盖材质、地形峭壁、植被、水体、战斗镜头、天气时间和多平台性能。
- 区域艺术指导卡、统一视觉验收等级、否决条件和资产生产流程。

## 4. 非目标

- 不强制所有地图使用新手村的湖山、青碧湖、桃林或晨雾。
- 不把概念图、文档、JSON候选当作原生UE资产或人工验收。
- 不未经测试强制启用Lumen Hardware、Nanite Foliage、GPU PCG、Volumetric Fog或任何Beta/Experimental功能。
- 不在V4.0中擅自新增正式HEX色值、材质参数、GPU预算或帧率承诺。
- 不改变战斗逻辑、阵营语义、UI功能和项目三层插件职责。

## 5. 方案比较与决定

- **方案A：在V3.0文档原位扩写为V4.0。** 优点是路径稳定；缺点是历史版本边界模糊，V3.0引用与V4.0新内容混在一起。
- **方案B：建立V4.0唯一权威主文档，V3.0保留为历史色彩基线。** 优点是版本治理清晰，V3.0原始色板与历史决策可追溯；AGENTS/README明确只指向V4.0。采用此方案。
- **方案C：将八大体系拆成多个独立权威文档。** 初期容易分工，但容易形成色彩、光照、材质和场景构图多套互相冲突的标准；不采用。专项文档只负责实现细节，不争夺全局艺术真源。

## 6. 技术约束

- 引擎：Unreal Engine 5.8；现有插件职责保持GamePlatform→MobaCommon→DivineBeasts。
- 色彩：继承V3.0初始sRGB参考值；新增颜色须固定曝光校准和人工审核。
- 光照：所有场景柔和但有方向、有体积、有接触阴影；按目标平台选择渲染路径。
- 植被：Nanite Foliage/PCG GPU等实验能力必须明确标记并验证。
- 性能：使用stat unit/stat gpu/profilegpu/Unreal Insights/RenderDoc等工具形成真实数据；具体预算由目标平台性能规范决定。
- Lighting Lab：现有V1仅覆盖光照候选；L2—L8不能在没有原生UE执行前标记完成。

## 7. 交付与验收

V4.0主规范、设计规格、实施计划、Lighting Lab映射表、Docs入口和AGENTS强制入口必须一致。所有区域艺术指导卡按八大体系检查；关键战斗可读性、原生资产保存/冷重载、目标设备性能和人工签收为硬门禁。

本次云端文档更新不等于UE场景或资产已完成改造。
