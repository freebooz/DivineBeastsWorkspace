## 阶段二：基础 UI 可靠性（P0）
- 优先修复移动端未交付蓝图变体的错误软路径；平台页面类异步加载失败时安全回退已交付的默认类，最多重试一次，并保障取消、页面代次及资源租约清理。
- 为 ErrorReconnect（错误/重连页面）补齐事件驱动 C++ 父类，与现有通用 ViewModel 的 Retry（重试）命令复用；不在 Widget 保存账号凭据、不绕过后端。
- Boot（启动）、LoadingTravel（加载/切服）、ErrorReconnect（错误/重连）蓝图须通过 Monolith 创建；必须编译、保存、回读并与实际焦点、命令和加载快照绑定。
- 验收：缺失页面明确失败不崩溃、不重复提交命令、不无限打开；资源成功时跳转有反馈。

## 阶段三：竞技界面运行接线（P0）
- DBAArena（神兽联盟竞技插件）持有自己的 UI 生命周期：竞技状态事件 → 共享只读 ViewModel → 平台界面管理器 → 真实页面/HUD；不得覆盖 DBAClient 的公共主页面所有权。
- 对同步失败、异步取消、状态快速切换、World/PlayerController 退出、缺失蓝图及重复事件设置保护；仅在活跃竞技条件下尝试打开界面，不使用业务 Tick（逐帧扫描）。
- 匹配、准备、竞技选人、记分板、结算、竞技 HUD 的视觉资产统一归 DBAArena；蓝图未交付时保留可审计的缺失状态，不伪称完成。
- 验收：UI 自动化与多世界关闭清理、1v1 至 5v5 事件快照和 Client/Editor 编译。

## 阶段四：核心世界／战斗 UI（P1）
- 补齐 OpenWorld（开放世界）、Village（新手村）、Tutorial（教学）、Training（训练）、Arena（竞技）五类 HUD；先实现玩家生命/护盾/气势、技能条、任务追踪、交互提示、名称板、伤害飘字和屏幕通知。
- Inventory（背包）与 Quest（任务）直接消费现有平台缓存与事件，不另建权威数据模型；其他 Profile（角色信息）、Equipment（装备）、Map（地图）、Party（队伍）按真正客户端数据源逐域接入。
- 验收：Widget 树、命名控件、生命周期、PC/触屏输入、移动端安全区、背包/任务事件响应、战斗性能与真实资源烘焙。

## 阶段五：系统、社交、运营界面（P2）
- 设置、音频、图形、语言与无障碍复用 GamePlatformSettings/Input/UI/SFX；好友、队伍、聊天和公会复用 Online/Party/Chat 业务客户端协议。
- 邮件、活动、奖励、成就与商城复用 LiveOps/CommerceUI 原有模板与事实，不在 UI 计算价格、余额或服务端权益。
- 按需分批生产各类蓝图，严禁为凑数量生成没有数据来源的空面板。
- 验收：权限、后端错误、空数据、断线重连、跨游戏复用，以及完整中文视觉文案。
