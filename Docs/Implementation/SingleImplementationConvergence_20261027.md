# 同功能唯一实现与当前版本目录收敛实施方案

用户依据2026-10-27审查明确要求整改，并同步修改版本目录或命名。本方案落实审查F01—F06及相关副本漂移风险，不另增一套播放器、结算器或平行业务版本。

## 范围与决定

- 魔法施法保留一套权威执行；正式/开发身份只作为输入适配，不分别持有目标冻结、连发、取消状态机。公共执行代码按职责命名；已序列化的类/技能ID若需保留，仅作为薄适配或迁移入口。
- VFX当前绑定采用一个工具合同，作者、资产验收及Cook闭包读取同一合同；旧作者不再能回写历史绑定。已批准火球/冰箭施法与飞行从Review/V3路径迁移到职责目录，系统名称不再包含Review、ConceptReview或V3。
- 原生资产只通过正式UE5.8/Monolith重命名、更新引用、保存及重载；先备份并查引用。旧路径若仍需兼容，只保留引擎redirector，不复制真实执行资产。旧系统退出活动发布；原图、历史审查记录及备份不直接删除。
- 身份Refresh采用同一轮换/到期规则，兼容游客登录入口而不保留不同的会话生命周期。
- 匹配和分服读取同一模式人数定义，不手工维护两份表。
- 临时槽位的内容差异保持各自身份；复用技能的服务器规则与默认值沿唯一源同步/引用，防止只同步弹速而遗漏连发等字段。

## 实施与验证顺序

1. 后端：先补失败回归，统一Refresh与竞技人数来源，运行受影响Go测试与必要架构检查。
2. 战斗：先保留/补齐两条现有入口的原生回归，将共同施法状态移至唯一实现，旧类型变薄适配；完整Editor及受影响Client/Server增量构建，运行目标冻结、连发、取消、换代、能量与施法窗口回归。
3. VFX工具：建立单一当前绑定合同，停用旧写入入口，修改旧验收脚本与Cook包含/排除规则，增加非UE静态回归。
4. UE资产：在正确工程与服务身份下备份、查引用，将九个当前法术阶段统一至职责目录；其中四个火冰系统退出Review/V3目录，并迁移必要依赖，使用无版本名称。只迁移当前实现，不重新制作视觉；保存、独立重载及实际Niagara编译。资产迁移后同步唯一合同及全部真实消费者。
5. 集成：按实际变化执行最小有效检查与必要Cook。全部Cook、Stage及临时目录留在当前工作空间内；不复制工程至外部短路径。不重启现有游戏、服务器或后端；编辑器仅在相关任务交还、没有在途操作且确认干净后，为完整构建受控关闭并恢复原审图地图。
6. 审查：逐项复核F01—F06，给出源码、原生资产、构建、Cook的分层证据；未完成的运行和人工验收明确列出。

## 协作与保留

后端、战斗C++、VFX源工具分别分区修改；只有本任务主代理操作Monolith。当前ThirdParty/GlooPrint及其他任务未提交内容保持原状。共用正式工程，以避免UE资产写入工作副本；源码任务不得自行启动构建或编辑器。无提交/推送要求，不自动提交。

任务进度与变更清单记录在Saved/Validation/SingleImplementationConvergence20261027/。新增、重命名、删除正式文件同步总体目录规划；对稳定资源身份的兼容说明保留于本文件。
