# SSLM 共用VFX视觉与性能重制实施方案 V2

日期：2026-10-18。依据：用户已确认的五张设计板，以及对首张单体护盾原生图“与设计图相差太远、没有细节”的明确否决。

最新范围覆盖：用户随后明确要求先实现一个攻击技能、人工审核通过后再做其他。当前唯一新候选为[攻击弧刃V2](SSLM攻击弧刃V2审核样本_20261018.md)；下文护盾优先是历史制作次序，已由攻击优先替代。新样本原生保存/冷加载和生命周期已核实，人工视觉与打包性能尚未验收。

本方案替代上一版依靠参数化基础几何直接扩展20模板的制作路径。当前产物全部属于被拒绝原型；停止批量作者流程，保留证据，不绑定正式技能、不覆盖既有治疗资源。下一轮先完成一个单体护盾V2，通过逐层原生视觉审核后再扩展。

综合结论：使用逐图定制的三维主体、少量有明确职责的材质层与事件驱动动画取得画质；在每个样板阶段即对实例/Emitter、透明覆盖和CPU/GPU进行测量。共享机制、构件和材质函数，各效果保留独立设计轮廓。以High实时画面为美术基准，再派生保留关键形态的质量档。

## 二、先把一张单体护盾做成完整美术资产

### 1. 按原图建立可核对的造型图

以防御设计板左上面板为唯一造型参考，保留完整原图RGB。确定相机后，以人物身高归一化比较轮廓和结构位置；真实空间大小仍取技能/角色合同，不能从图猜米数。

交付一张原图结构分解板，逐条标出：

- 外轮廓与人物头顶、脚底的相对位置。
- 银蓝主弧线的起点、终点、最大宽度处、收尖处和相互遮挡关系。
- 金色叶形构件的实际轮廓、厚度与嵌入位置。
- 护膜上可见的大尺度云纹、亮边和留白区域。
- 地面接触环、中央叶形符号与角色脚底的关系。

从同一控制点清单生成网格、UV路径和材质遮罩，避免三套形状各自画一遍而错位。背面采用与正面同一视觉语言补全，并在多角度灰模中检查；原图没有提供的部分明确记录为补充设计。

### 2. 用可编辑曲线和定制截面制作网格

使用DCC中的Bezier曲线、宽度/渐细控制和定制扁椭圆/刀翼截面。保存可继续编辑的 `.blend` 曲线源与导出网格，不只交付一份烘死的OBJ。

拟制网格：

| 资源后缀 | 形体要求 |
| --- | --- |
| `ShieldV2_Membrane` | 独立透明壳体，正确UV/切线/法线；无重复共面、无多层透明球堆叠 |
| `ShieldV2_SilverBlades` | 按原图逐条拟合的宽银蓝流线，截面有厚度和圆滑倒角，宽度沿曲线变化，末端自然收尖 |
| `ShieldV2_GoldInlays` | 叶片/卷曲形金色实体，独立几何厚度及倒角，构造在主弧线上而非均匀金色钢管 |
| `ShieldV2_EdgeBands` | 与主结构共享控制路径的窄发光沿边，避免全身均匀发光 |
| `ShieldV2_FootSeal` | 原图的接触环及叶形符号，留白清晰、不填满整块地面 |

不得通过增加随机雕刻或颗粒制造“细节”。本轮需要的细节是准确的大曲线、宽窄关系、倒角、嵌金结构、云纹与分层高光。

**造型门槛：** 先在无自发光灰模下并排比较正面、侧面、俯视与游戏视角。主弧线或金饰轮廓不匹配时不进入材质阶段。

### 3. 建立真正承担细节的UV与贴图

护盾首轮建议使用2048级技术遮罩和独立切线法线作为制作起点，最终按游戏显示尺寸缩减。所有技术贴图线性采样、正确压缩；不把完整概念图作为运行时贴片。

- `T_DBA_ShieldV2_ShellMask`：R为大云纹分布，G为局部能量亮带，B为涟漪可见区域，A为显露/消隐控制。每个通道对应明确视觉职责。
- `T_DBA_ShieldV2_ShellNormal`：只表达大尺度平滑起伏与细腻曲面变化，不含砂砾、碎裂或密集凹凸。
- `T_DBA_ShieldV2_Flow`：RG记录沿主云纹方向的流动；静态结构和流动路径共用UV基准，不随机扭曲整体护膜。
- 金色构件优先用几何法线与材质参数产生高光；仅有必要的色阶/粗糙度变化，避免把复杂度转成噪声。

遮罩先以黑白/通道色在真实网格上审核，检查UV拉伸、接缝、镜像和背面，再接入正式颜色。

### 4. 分职责重建材质

| 材质 | 原生实现与检查 |
| --- | --- |
| `M_DBA_ShieldV2_Gold` | Opaque、Default Lit，使用几何倒角、金属度与宽连续高光；在固定环境反射下调校，不用透明加色代替金属 |
| `M_DBA_ShieldV2_Silver` | 光洁银蓝主体，保持受光明暗与结构厚度；自发光只强调沿边，不吞掉实体轮廓 |
| `M_DBA_ShieldV2_Membrane` | 单层薄透明外观，Fresnel只负责角度变化，叠加有来源的云纹/亮带遮罩、宽而连续的镜面响应；中心保留人物可见性 |
| `M_DBA_ShieldV2_EnergyEdge` | 精确沿结构的窄能量边，宽度、主芯与外晕分层可控；限制Bloom和白色过曝 |
| `M_DBA_ShieldV2_FootSeal` | 接触环/叶形符号按独立遮罩管理，与地面真实关系和视觉范围合同一致 |

透明护膜先验证 `Surface ForwardShading` 的逐像素高光与反射能力及目标RHI支持；它只用于确实需要此响应的透明表面，不套给全部粒子。该模式成本较高，必须测量后决定保留或采用低成本变体。参考 [Epic Lit Translucency](https://dev.epicgames.com/documentation/en-us/unreal-engine/lit-translucency-in-unreal-engine) 和 [Material Properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-material-properties)。

实际颜色仍引用V3.0主规范，并按原图在固定曝光下调校；不改变全局曝光、Gamma或颜色滤镜去掩盖错误材质。单独检查BaseColor、反射、Opacity与Emissive，明确高光来自哪里。

**材质门槛：** 无Bloom状态仍能读出宽弧线、金边倒角、通透护膜和云纹；打开锁定Bloom后只增强已有形体，不把它变成发白光球。

### 5. 校准审核场景

第一步先在灰卡、灰球、金属测试件和透明测试件上确认主光、天光、环境反射、曝光及显示转换。记录校准值，之后禁止为单个效果另调曝光。

使用暖灰石地、白天柔和光照和中性训练角色，与确认稿的主要观察条件接近。先固定对照镜头，再验证真实游戏镜头；人物不能保持黑色剪影。角色/背景只提供相同观察条件，不扩大成场景重建任务。

以可信PIE/RHI或已对齐后处理的原生RenderTarget输出对照。SceneCapture与真实视口逐项比较曝光、后处理及显示转换；没有测量前不能把偏暗直接归因于Gamma，也不能用图像后期调亮验收。

### 6. 最后接入Niagara动态

先取得静止峰值外观一致，再接入动画。Niagara复用已完成的几何与材质，只控制实例、阶段参数、附着和结束，不承担新的Gameplay。

- 出现：按结构路径显露，金边/主弧线/护膜有明确先后，实际时长位于既有技能窗口内。
- 持续：护膜云纹缓慢沿既定方向流动；几何主体保持稳定，避免整体转动破坏设计轮廓。
- 命中：由实际命中通知提供位置和时间，只在接触区域形成一圈或少量宽涟漪，不反复Spawn完整护盾。
- 结束/取消：按真实状态事件停止，云纹和能量边先后收敛，清理实例/租约；不保留空循环。
- 质量档：降低流动/涟漪/装饰复杂度时保留主弧线、金色构件、保护边界和角色可读性。

细分几何层不要求机械新增同数量Emitter；同生命周期的Mesh可共享原生模拟/Renderer，最终以测量决定合并。只使用现有GamePlatformVFX执行链。

## 三、先交付六组证据，再扩展其他效果

1. 原图上的结构分解与逐条控制曲线。
2. 无光灰模：正面、侧面、俯视、真实游戏镜头。
3. 材质分层：银蓝结构、金属、护膜云纹、能量边分别显示。
4. 同机位峰值：原图面板与UE原生结果并排，并提供仅用于诊断的轮廓叠加；原生图不能后期润色。
5. 真实连续动画：出现、持续、一次局部命中、取消/结束全过程。
6. 独立保存后重载的相同画面、原生编译/Shader状态和初步Overdraw/GPU记录。

造型、材质、动态分别检查。用户认为仍像基础球壳/钢管、云纹缺失、金属不成立或高光不连续，即判未通过。不得以0错误编译、资源数量、低成本或“可参数化”覆盖视觉否决。

只有单体护盾V2视觉通过，才以其真实资产形成可复用构件。其余三种防御效果仍按各自面板重建轮廓，不直接把同一椭球缩放成盾墙。

## 五、代码与资产整改范围

- 旧 `BuildCommonSkillVFXSources.py` 保留作被拒绝几何原型，停止作为正式20模板造型生成器；V2使用逐图控制点/截面合同与可编辑DCC源。
- 旧 `AuthorCommonSkillVFXUE.py::materials()` 的三种统一透明材质不作为V2母材质；在 `CommonSkillVFX/Review/V2/DefenseShield` 独占路径创建新候选，真实编译、保存和重载。
- 旧 `NM_DBA_CommonVFXMotion` 不当作所有效果的完整运动设计；仅保留可复用的生命周期/参数经验，分阶段制作每类所需运动。
- `CaptureCommonSkillVFXUE.py` 先完成光照/反射/灰卡及相机链路校准，再作为视觉证据工具；不得把原始无校准场景继续复制20份。
- 新资产、源文件、修订、引用及验收状态登记到项目内容包清单；未通过资源不进入正式目录/技能绑定。
- 平台层不增加生肖类、专用播放器、资产管理器或预算系统；MOBA层不引用项目美术；项目资源归DBAPresentationPack_Core，后续生肖覆盖归各DBAHeroPack。

## 六、执行顺序与停止条件

顺序固定为：单体护盾结构分解 → 灰模 → UV/遮罩 → 分职责材质 → 校准场景中的静态峰值 → Niagara完整动态 → 冷加载/性能初检 → 用户视觉签收 → 扩展其余19种。

每步都有可见产物；前一步未通过不进入后一步。首轮只需要完整单体护盾V2及上述六组证据，不批量创建其余候选来增加完成数量。任何与原图关键曲线、材质响应或层次明显不符的结果先修正；不以图像生成润色实机截图、不以改曝光或加Bloom取代资产制作。

本次仅完成差距复核和重制方案，没有继续制作原生资产。最终一致性由真实游戏相机下的具体造型、材质、色彩、运动对照及用户签收决定，不承诺未经实机确认的逐像素相同。

## 七、历史要求的合并与采用顺序

本次读取了可访问的历史对话《设计Niagara特效流程》《设计五款冰箭特效》《重新导入治疗法术VFX》，以及正式历史索引、治疗重导、冰箭审核和现行AGENTS/配色/VFX规范。可访问的部分对话正文只返回引用标记或有限历史页，不声称已恢复全部历史消息；以下决策同时以现行工程规范和可读证据核对。

| 已确认要求或经验 | 本方案落实方式 |
| --- | --- |
| 历史VFX设计参考魔法的施法、释放、飞行、命中、持续和消散表达 | 每个模板分别设计真实存在的阶段，清晰区分状态；不因静态图缺失动画就仅做整体旋转缩放 |
| 高品质、电影级、光洁温润、线条完整、低噪声；东方自然/玉石视觉 | 细节来自优美轮廓、叶形/云纹、倒角和层次；禁止用颗粒、砂砾、密集闪点或锐化堆质感 |
| 当前五张图已确认，首张原生护盾被明确否决 | 五张图是目标；否决原型不成为低画质基准，不直接继续派生19种 |
| 原生治疗效果曾因导入后不如原项目被要求重导 | 复用必须保留源资产/公式/参数/贴图和依赖，采用同条件原生渲染对照，不用简化重写替换已确认原版 |
| 原生治疗历史要求同时考虑性能 | High保留确认原貌，中低档先减少装饰与透明覆盖；现有204/54/41粒子记录仅属于该治疗系统，不作为新20模板配额 |
| 冰箭已有三维主体、地面起手与连续轨迹的具体合同 | 对实际属于地面起手的法阵保持地面挂点；飞行遵循真实位置和方向；不将既有控制/头顶状态标记一概搬到地面 |
| 真实UI/表现状态更新采用事件通知 | 技能、命中、解除、移动与镜头事实来自既有通知/引擎组件；不加项目级Tick轮询来驱动业务 |

## 八、画质与性能联合设计

### 1. 核心与装饰必须分开

每模板在合同中显式列出不可丢失核心：三维主体、方向/起终点、真实范围、危险持续时间和必要状态标记。可以降低的内容是辅助雾、花粉、碎片、额外尾迹、装饰光和高成本折射。

模型高质量不等于高面数。主弧线、倒角和叶片截面按实际屏幕像素分配几何，平滑法线负责连续表面；同一主体可用多材质槽承载实体与透明部分。不同主体、材质和生命周期保留必要边界，不为了“一个Mesh”制造透明排序错误。

### 2. 修正当前原型的粒度与模拟选择

- 普通模板以一个受控核心System为审查起点，通常先尝试1—3个有职责的Emitter；不是每个美术层一个Emitter，也不是每一段动画新建System。最终数量由真实外观与测量确定。
- 少量Mesh的变换/显露优先比较CPU Niagara与材质动画；大量可选碎屑/叶片才评估GPU。GPU模拟仍有System/Emitter的CPU开销，不能因“GPU”名称推断更快。
- 同生命周期、相同位置/运动的构件优先共享粒子或模拟，可使用多材质Mesh/多个Renderer，但仍统计真实Draw Call、材质槽和透明覆盖；不能把Emitter减少当成全部成本下降。
- 持续护盾/治疗/控制保留一个明确所有者的实例，命中局部参数更新不重复Spawn整个护盾，DoT/HoT每跳不重复创建整套特效。
- 沿用Niagara原生AutoRelease/池化与现有句柄；不新建池、预算服务、玩家扫描器或另一资产加载器。

技术依据：[Epic Niagara伸缩与最佳实践](https://dev.epicgames.com/documentation/en-us/unreal-engine/scalability-and-best-practices-for-niagara)明确说明System/Emitter开销、少量粒子的CPU/GPU权衡以及原生池化。上述配置是待实测选择，不是已取得的性能结果。

### 3. 优先控制透明覆盖与昂贵材质

- 金色实体使用Opaque，透明膜只保留必要一层；不堆双面重叠球壳、大屏Sprite和多层光晕。
- 膜中心留白、能量集中在关键曲线和边缘；与设计稿一致的透明留白本身也有助于控制过绘。
- Surface ForwardShading仅对确有收益的透明表面做High/Epic A/B测量；不为所有粒子启用，不为实现高光添加大量动态粒子灯。
- 默认不增加SceneColor折射、长时扭曲和额外动态光；需要时单独证明视觉收益与GPU成本。
- 技术遮罩线性、可共享通道；法线独立正确采样。颜色图保留sRGB链路，主色由V3.0统一管理；不为每英雄复制同一套纹理。

### 4. 每模板有自己的有效包围盒

弃用旧原型统一填入的1800厘米大包围盒。对每模板按最大合法Radius/Length/Width/Scale组合、轨迹和Renderer尺寸计算包络，并用原生Bounds显示与极值参数验证。避免Bounds过小导致突然消失，也避免过大导致离屏仍长期更新。

主干几何的LOD与材质质量变体以游戏实际显示尺寸判定；远距优先减少看不出的倒角段数、云纹层、装饰和折射，保持关键曲线/标记的足够像素宽度。敌方危险信息不因距离或低画质被裁掉。

### 5. 四档合同

| 画质 | 必须保持 | 允许降级 |
| --- | --- | --- |
| Epic | 完整确认造型、材质、动态和关键提示 | 仅按实测保留额外装饰，120FPS单独验证 |
| High | 作为实时视觉签收基准，关键曲线/金属/护膜/动态完整 | 控制装饰数量与透明覆盖 |
| Medium | 相同主要轮廓、颜色语义、范围、方向和状态信息 | 减少云纹/涟漪层、少量装饰、材质成本与远景几何 |
| Low | 保留立体主体及必要边界，整体光洁、清晰、无噪声 | 简化透明膜/反射、关闭雾花粉折射及次级尾迹，不退回被拒绝基础球壳 |

### 6. 沿用现行候选预算，不设另一真源

下表只摘录现行核心规范以便执行，不构成设备承诺或本轮实测：

| 指标 | Epic | High | Medium | Low |
| --- | --- | --- | --- | --- |
| 单客户端World真实活跃System总数候选 | 120 | 80 | 58 | 40 |
| VFX GPU候选预算 | ≤2.0ms | ≤1.5ms | ≤1.0ms | ≤0.8ms |
| VFX CPU候选预算 | ≤0.8ms | ≤0.6ms | ≤0.5ms | ≤0.4ms |

以上适用于MainArena配套场景，统计包含环境、动画通知、共享Reader和其他入口；20模板数量不等于同时活跃20个System。平台追踪请求256/512不是System总数。High候选整帧P95≤16.67ms、P99≤20ms；Epic 120FPS需要独立8.33ms整帧预算。CPU/GPU数据分别分析，不能直接相加。

七类Effect Type、每资产实例限制、场景ExperienceId匹配、动态恢复滞后与距离策略继续引用核心规范；不得降低全平台设置去误伤Village/OpenWorld。NDC保持默认关闭，待真实Channel/Reader/Shader、空间上下文与打包GPU验证后再引入，不能为本轮画质重制先增加不稳定链路。

## 九、联合实施与验收顺序

### A. 单体护盾静态完整度

逐图造型、UV/遮罩、实体金属、透明膜、沿边能量、环境校准分别产出可视结果；完成同机位静态峰值，达到确认稿的曲线、材质和层次再进入动态。保留低成本技术验证，但不对外声称其是最终美术。

### B. 同步测量样板成本

在同一设备/RHI/分辨率/画质/相机下记录无效果基线、1个护盾、10个护盾，比较CPU/GPU模拟、透明材质与Emitter组织方案。保存GPU时间、游戏/渲染线程、Draw Call、活跃System/Emitter、Overdraw与内存；以GPU事件归因结合整帧对照，不能只做不受控的帧率相减。

测量发现成本超标时，优先修正透明层和实例/Emitter组织，保留确认轮廓。只有视觉收益和预算都成立才冻结样板，不先复制19份再发现结构性成本问题。

### C. 完整动态与五类样板

护盾完成出现、持续、局部命中和结束/取消后，接着做弧刃、治疗再生、真实轨迹冲刺、束缚四个代表样板。每个重复A/B门槛，避免把护盾材质机械套给所有类型。旧治疗的高质量构件可在保留来源及原貌的前提下复用；新设计不同之处仍需专门制作。

### D. 扩展20模板与通用资源交付

五个样板确认后才扩展20模板；制作原生Definitions及参数白名单、QualityVariants、EffectType和对应软引用。所有资产由Monolith创建/保存，独立重载验证；不绑定虚构的生产技能身份。十二生肖专用技能扩展仍为后续范围。

### E. 实际发布验证

先在单发/十实例的可控负载下检查，再执行现行发布门禁要求的真实打包客户端四档、1v1—5v5、十人集中施放、每秒至少150短命中、AOE叠加、10分钟稳定以及预测/确认/取消/断线重连/换World。新增内容对应Cook/Shader/Client容器与专服剥离必须重验，不复用旧包证明新资源交付。

每项状态分别记录：视觉通过、原生编译/保存/冷加载、生命周期/参数、客户端Cook、实际GPU性能、人工签收。未满足的项保留未完成，不以静态数量、视频编码帧率或粒子减少比例代替。

## 十、两种“一致性”的验收差别

原生源项目迁移复用：可在同场景、相机、阶段、曝光和种子下进行像素对照，检查重导是否改变原貌；历史治疗的1/255结果仅是其受控对照证据。

新AI概念到实时三维：原图没有完整几何、动画和渲染参数，使用逐层结构、轮廓、材质响应、颜色与连续运动对照并由用户签收；不套用治疗的逐像素误差承诺。两者都要求最终真实游戏镜头可读、四档核心保留和性能门禁通过。
