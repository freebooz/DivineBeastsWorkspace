> **For agentic workers:** REQUIRED SUB-SKILL: 使用 `superpowers:executing-plans` 在当前会话逐任务执行；同一UE编辑器的资产修改串行提交。未经用户另行要求，不启动并行代理制作同一资产。

**Tech Stack:** 锁定UE5.8.0、Monolith MCP、Niagara Mesh/Ribbon/Decal、材质实例、现有Definition/Catalog、真实PIE与打包客户端取证。

## Global Constraints

- 工作空间唯一根名 `DivineBeastsWorkspace`，主工程 `Game/DivineBeastsArena.uproject`；不另建工程、插件树或播放器。
- 依赖方向 `DivineBeasts → MobaCommon → GamePlatform`；项目公共表现可直接消费平台中立接口，非竞技场景不强制依赖MOBA。
- 共用VFX美术归 `DBAPresentationPack_Core`，专属美术归既有 `DBAHeroPack_*`。五类是内容模板分类，不是五个新插件。
- `FDivineBeastsHeroVFXProfile` 仅描述视觉语言，不放UObject、Niagara路径或具体资源绑定。
- 伤害、治疗、控制、护盾、真实范围、位移、冷却和技能时序仍由服务器Gameplay/GAS决定；不从效果图推算或修改数值。
- UI及状态更新均使用事件通知；不得用项目Tick或常驻定时器扫描业务状态。Niagara自身模拟和材质时间动画只消费已给定的表现参数。
- `.uasset/.umap` 由正确工程中的Monolith/UE原生工具创建、编译、保存和独立重载；本地脚本可准备源网格与技术遮罩，导入及资产写入通过Monolith执行引擎流程。
- 颜色唯一真源是配色V3.0主规范；初始HEX是屏幕sRGB参考，必须正确转换到线性参数并固定曝光校准。不创建另一套权威色板。
- 禁止颗粒噪声、砂砾、密集碎光、粗糙高频纹理、过曝白核和锐化补偿；连续高光、平滑透明过渡与清晰体积是必检项。
- 保留已存在的治疗、冰箭及其他资源和稳定身份；新候选在独立Review路径制作，通过后再切换对应引用，不整树覆盖。
- Dedicated Server不依赖或Cook纯客户端Niagara、美术材质、贴图、Mesh和人工审核地图。
- 固定既有构建参数：UE5.8、Win64/Development、`-NoSharedPCH -NoUBA -MaxParallelActions 8`；Editor另用 `-UsePrecompiled -AdditionalPlugins DBAServer`，Client/Server不使用UsePrecompiled。只构建受影响目标，发布内容变化才执行对应Cook/Stage。

## Review Focus

1. 概念画面只提供瞬间：关键帧相似但起手、转向、遮挡和消散不合理；P0分镜与P2/P3连续动画共同验证。

3. 技能缩放、角色挂点或地面变化导致预警范围错位：P4使用真实参数，验证不同体型、方向、地形与有效范围。
4. 预测确认双播、取消后尾迹残留或换World旧回调复活：P4沿用实例句柄、代次及去重，覆盖各终态。

## 一、采用的制作路线

采用“定制几何和材质还原确认稿 → 五个样板逐项签收 → 扩展20模板 → 真实技能映射 → 打包客户端验证”的路线。已有库用于复用明确匹配的构件和技术能力；复用前仍逐层对照。图中的主体弧线、护罩拱线、叶瓣及轨迹均需有可编辑源几何或曲线。

Niagara的Mesh和Ribbon Renderer可承载网格主体与带状轨迹；本方案据此选择Mesh表现体积、Ribbon表现运动历史，局部Decal/Mesh表现范围。相关原生能力见[Epic Renderer说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/render-module-reference-for-niagara-effects-in-unreal-engine)。这项选择是本方案的制作决策，不表示任意现成Niagara资产可以直接还原设计图。

核心按四层制作，逐层开关审核：

1. **主体层：** 可辨识的弧刃、护罩支撑、束缚带、叶瓣、轨迹。先以无光灰模确认体积和剪影。
2. **材质层：** 大尺度明暗、宽而连续的高光、可控透明度、柔和边缘。高光和金色实体边缘各自有明确材质职责。
3. **运动层：** 按真实阶段驱动凝聚、展开、飞行、命中、持续、结束与消散；动态曲线在现有权威时间窗内调校。
4. **装饰层：** 少量叶片、局部亮点或短拖尾；可关闭，不承担范围、方向、危险和关键状态。

护罩重点使用清晰壳体和宽支撑弧线控制形态；弧刃用有厚度的弯曲网格及短尾迹；治疗叶片有真实弯曲和法线；移动残影数量有界且不混淆终点。避免用大面积加色透明片把所有形体填成光团。

## 二、视觉合同与对照方法

每个模板建立一张可回读的视觉合同，包含：原图/面板位置及SHA-256、必保轮廓、主辅层级、人物比例、挂点、方向、范围边界、透明度层次、目标色彩语义、禁止新增的细节、动态分镜、各质量档保留内容和签收记录。

原图每张1536×1024，属于四格设计板。20个面板分别登记；提取审核ROI只用于对照，保留完整原稿RGB与原始文件。边框、文字、人物与场景是展示上下文；技能的可实现几何、关键形状和视觉语言是还原目标。概念中的示意路径箭头不自动成为伤害预警；闪现仅在真实起终点表现，不创建不存在的连续碰撞路径。

### 固定审核环境

- 一套暖灰石地与少量自然草地的审核场景，使用不抢眼的现有训练角色；优先复用已有审核地图/资源，必要时在内容包内建立单一CommonSkillVFX审核地图。
- 建立“确认稿对照镜头”和“真实游戏镜头”。前者依据人物高度、地平面与透视关系校准相机；提示词中的50度只作起点，不能当成图中实际已标定角度。
- 记录相机Transform、投影方式、FOV、分辨率、曝光、白平衡、灯光、Bloom、抗锯齿、画质、RHI、种子、预热方式和实际时间。相机/曝光一经锁定，同轮不为单个效果另调。
- 固定背景/无效果基线与VFX渲染各保存一份。材质调试用无泛光视图检查实际主体；正式对照继续使用锁定的游戏后处理。
- 固定种子、固定步长和可重复的预热；在各阶段实际时长内取开始、四分之一、峰值、四分之三和结束/取消点。短促效果与循环效果分别登记阶段时间，不把全部技能强制设为同一秒数。
- 保存完整连续播放和多角度观察，防止只在一个镜头下成立；支持暂停看厚度、弧线、遮挡、尾迹断点与透明排序。

正式视觉证据使用可信原生客户端截图/原生RenderTarget或RHI链路。可复用现有FinalColorLDR脚本结构，但应逐项匹配真实相机、后处理、预热和显示转换；SceneCapture的存在不证明与游戏画面一致。MRQ仅供额外展示，不能用电影级超采样或特有后处理替代实时验收。Epic文档说明MRQ可以覆盖色彩输出、Tone Curve及实时不适用的渲染设置，参见[电影渲染画质设置](https://dev.epicgames.com/documentation/en-us/unreal-engine/cinematic-rendering-image-quality-settings-in-unreal-engine)。

### 必须通过的视觉检查

| 检查 | 通过条件 | 证据 |
| --- | --- | --- |
| 主体剪影与体积 | 核心弧线、支撑结构、叶瓣、路径及比例与确认稿一致；侧面和游戏镜头仍可辨识 | 无光灰模、多角度、原图与引擎峰值并排 |
| 色彩与材质 | 主辅色和明暗层次一致，角色可透视/可辨识，高光连续，没有泛白或噪点堆积 | 固定曝光彩色/无泛光/灰度对照 |
| 空间信息 | 方向、起终点、附着点及真实生效边界准确，预警与生效能区分 | 真实技能参数与边界叠加调试图 |
| 动态质量 | 凝聚、展开、运动、命中和消散符合签收分镜，无跳变、错误残影或尾迹断裂 | 原生连续动画及关键帧 |
| 游戏尺度 | 原尺寸和真实显示尺寸都清晰，低档保留主体与关键提示 | 真实游戏相机四档对照 |
| 最终一致性 | 技术项通过后，用户逐模板确认视觉；未确认者保留候选状态 | 每模板签收记录和未通过差异清单 |

数值比较只作为诊断：先对齐相机、阶段、尺度和VFX区域，再看轮廓/颜色/高光分布。不能拿两幅不同背景的整图SSIM或“相似度95%”当成验收。概念图不能提供所有动态事实，P0必须把缺失的分镜与真实技能约束收敛到一个可审核版本。

每轮按轮廓/体积 → 色彩/透明度 → 运动/尾迹 → 少量装饰的顺序修正。保存主要三项差异、修改资源、修改前后原生图；连续三轮主要差异无改善时重新检查几何、材质或相机假设，不继续盲调亮度。

### 参数与绑定合同

已核对平台现有参数名：`User.PrimaryColor`、`User.SecondaryColor`、`User.CoreColor`、`User.Intensity`、`User.Duration`、`User.Radius`、`User.Length`、`User.Width`、`User.Speed`、`User.Seed`、`User.SourcePosition`、`User.TargetPosition`、`User.Direction`、`User.Scale`。各模板只声明自身真正使用的ParameterSchema，不声称所有渲染器自动接收全部参数。颜色用合法线性值；UE空间参数显式使用厘米，时间使用秒。

每次接入先验证参数是否实际传到System、Emitter和材质绑定；用两个明显不同且合法的输入值确认画面变化，并验证越界/缺失参数按既有Schema拒绝或回退。范围来自Gameplay，不用视觉Scale改变命中资格。

拟新增目录入口为 `FDivineBeastsPresentationProjectCatalog::BuildCommonSkillVFXFragment()`，返回已有 `FGamePlatformPresentationCatalogFragment`。仅在P4确认现有注册方式后实现；若已存在同职责入口则原位增量，不再新增平行入口。真实Niagara路径由Definition软引用拥有，Catalog映射逻辑Definition身份。

技能映射台账必须逐条记录真实HeroDefinitionId、AbilityId、当前开发/生产资格、真实效果分类、触发阶段、模板、Definition、真实参数来源、取消/结束来源、专属覆盖与回退。不能按技能名字猜测分类，也不能把五个槽位直接等同五类VFX。无可见反馈的被动明确记为无需持续特效；没有真实技能事实或批准身份的项目记为阻塞，不能伪造“全部绑定”。
