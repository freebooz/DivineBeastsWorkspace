# SSLM 火冰双掌前摇、飞行特效与数字1视觉替换｜Monolith MCP执行提示词

## 目标与授权
在 DivineBeastsWorkspace（神兽联盟工作空间）中通过 Monolith MCP（虚幻编辑器工具协议）实际制作火、冰两种双掌聚集/蓄力及大火球、冰晶飞行。用户本轮授权将新火法表现替换数字1对应技能的视觉，不授权更改伤害、冷却、技能身份、服务器施法窗口、弹道或碰撞。禁止提交/推送。原V1人工驳回、V2及F1临时材质实验未通过最终美术验收，不能直接作为成品发布。

当前源码证据：DefaultInput.ini 中 One（数字1）→DBA.PrimaryAbility（主技能输入）；角色输入转为 Platform.Ability.Input.DivineBeasts.Primary。BindDirectedMissileSlot1HealingSlot5UE.py 表明占位技能1=DirectedMissile（定向飞弹），2=Fireball（火焰弹），3=Frostbolt（寒冰箭）。实施前必须读取真实 AbilitySet（技能授权集）与 CDO（类默认对象）再次核对，不能仅凭此脚本推断当前生效资产。

## 架构选择
复用 GamePlatformPresentation（平台表现请求）与 GamePlatformVFX（平台特效服务），不新建粒子播放器、第二条弹道或全局逐帧轮询器。公共单掌系统在左右真实掌心挂点分别播放；火与冰共享聚集运动但使用不同材质、形态、装饰与凝结/燃烧规则。冰法已有地面法阵不得改挂到手上。

新资源统一目标目录：/DBAPresentationPack_Core/VFX/OrbProjectile/Review/V3/CastFlight（项目内容包内独立审核目录）。拟创建四套系统：NS_DBA_FirePalmCast_V3（单掌热能聚集蓄力）、NS_DBA_IcePalmCast_V3（单掌冷气聚集蓄力）、NS_DBA_FireOrbFlight_V3（大火球飞行与历史拖尾）、NS_DBA_IceCrystalFlight_V3（冰晶飞行与冷雾历史拖尾）。这些是计划名字，实际创建之前不得标记完成。

## 提示词A：公共单掌运动与参数
读取已存在的NM_VFX_Vortex（旋涡运动）和模块接口，复用可验证部分。生成阶段记录稳定粒子编号、随机相位和起始半径；更新阶段实现三维螺旋向心收缩，禁止每帧随机跳变或机械等距圆环。左右手允许相反旋向，手掌局部坐标系与实际角色骨架一致。单掌系统本地原点就是掌心，不继承旧FireMage模板的+65/+135厘米偏移。少量外围流线向心聚集，接近掌心后减速、压缩并形成元素主体。

参数为美术初值，并非从静态母图恢复的客观数据：GatherRadiusCm（聚集半径）火18–26/冰20–30；InnerRadiusCm（收束半径）火3–6/冰4–7；SpiralTurns（粒子生命周期圈数）火1.3–2.1/冰1.0–1.6；HandSideSign（左右旋向）±1；CoreDiameterCm（核心直径）火6→14/冰5→12；AccentRate（装饰强度）低；OpacityScale（透明度倍率）分层校准，不盲目提高；CastDurationSec（施法窗口秒）、ElapsedAtStartSec（开始时已过去秒）来自既有复制事实。一个系统参数覆盖控制在现有平台白名单上限内，先核实再登记。

归一化阶段p=clamp((系统运行秒+开始偏移)/真实施法窗口,0,1)。前25%唤醒吸附，中间45%旋涡压缩，后30%稳定蓄力；以上只是客户端视觉分段，不延长服务器前摇。取消、死亡、切地图、Avatar代次变化、资源加载迟到时正确撤销两掌实例及各自请求。

## 提示词B：火法双掌初燃与蓄力
必须表达“热能卷吸→高温压缩→厚实燃烧”，不是两团静止火或橙色光球。火焰内核局部暖白，中层金黄，外层橙红，主体具有连续卷燃与向上翻卷的火舌。发射器职责建议 GatherFlow（热流汇入）、PalmFlame（主体燃烧）、HotCore（受控热核）、EmberAccent（少量余烬）。可以合并低成本层，避免为了数量拆分。

纹理优先使用可核实且连续的火焰图集，不能把概念图直接当动态贴图。已知旧图集为4×4时，Renderer.SubImageSize必须为(4,4)，SubImageIndex必须随时间变化，帧间混合须与材质采样方式同时验证。不能只设置Renderer开关而母材质仍普通采样整张图集。输出纹理列行数、帧数、材质采样节点、播放索引范围及冷重载回读证据。避免碎焰簇、塑料高光、过曝、强锐化与黑边。

## 提示词C：冰法寒气初聚与冰霜蓄力
必须表达“蓝白寒气卷吸→冷雾压缩→霜粒/微冰晶凝结”。复用已存在寒雾、冰晶纹理与PBR（基于物理渲染）冰材质，不能把火焰染蓝。发射器职责建议 ColdGather（寒气聚集）、FrostCondense（凝霜）、CrystalSeed（少量晶种）、ColdCore（柔和冷核）。寒雾低频柔和，不遮住手掌；晶体用局部棱面反光与冷色厚度，避免不透明蓝石和密集亮点。保留地面法阵独立请求及位置。

## 提示词D：大火球与冰晶飞行
主体附着既有权威弹体根组件，由既有复制飞行事实控制开始/结束；Niagara内部只能做局部卷燃、晶面自旋和装饰漂移，禁止再积分一条独立弹道。火球保留近球形燃烧主体，暖白热核局部可读，外围金橙流焰有体积；冰晶保持不规则有厚度晶簇，不换成旧细长冰箭、不用方盒或蓝色火球。

飞行结构：FireBody（火球主体）/FireVeil（外卷火焰）/FireRibbon（主热流历史带）/Embers（少量余烬）；IceBody（实体冰晶）/FrostRibbon（主寒雾历史带）/MistWake（滞留冷雾）/IceShards（少量冰片）。核心使用局部空间，拖尾与滞留碎屑使用世界空间。清晰区分中心主体与后方尾迹。

Ribbon（带状粒子）必须使用原生Ribbon Renderer。生成阶段显式初始化同一弹体实例的RibbonID（分组身份）和严格递增RibbonLinkOrder（链接序号）；LinkOrder不能全部默认0，也不能按每帧重排的执行索引连接。GPU/CPU和默认NiagaraID数据类型以原生模块实际编译支持为准。更新阶段只控制宽度/颜色/透明度和允许的微扰，不把所有旧粒子重置到当前弹体坐标。用调试不透明高对比材质先证明带状几何连续，再换回火/冰材质。校验UV方向、宽度绑定、朝向、曲线细分、有效Bounds（包围盒）、正常Tick和可见性；不靠提高亮度掩盖连线错误。

审核初值：尾宽火14–28cm/冰15–30cm；寿命火0.15–0.30s/冰0.18–0.36s；按距离采样火12–24cm/冰15–28cm；未支持按距离的初版65粒子/秒只作调试基准。尾长由实际速度×寿命形成，母图不提供确定米数。网络位置修正/瞬移断开旧带并新开RibbonID，正常结束允许短淡出，销毁/切图立即清理所属实例与池化历史。

## 提示词E：数字1视觉替换与回退
先读真实授权集、输入标签、AbilityId（技能身份）、PresentationStyleId（表现样式）、Cast/Flight语义、最终Definition（表现定义）和Niagara路径。当前数字1若确认为DirectedMissile，只改其Cast/Flight表现引用或项目适配，不改技能授予、GA（GAS技能类）、数据表伤害、冷却、服务器飞行、数字2映射。需要双掌时，在既有施法客户端生命周期中增加左右独立锚点与句柄，或使用经验证的骨架采样方式；不得用固定左手偏移伪造双手跟踪。

修改前保存最小映射快照与资产哈希；修改时核对资产未被其他会话改变；保存后独立冷重载回读。若目标是多个生肖共享样式，明确影响所有使用该样式的1号技能；其他非该样式技能不改变。原绑定保留可回退。新资源无法编译、真实不可见或清理不正确时，不把失败版本挂到1号键。

## 分步执行与证据
- [ ] M0：真实1号输入/技能/样式/表现路由、Monolith版本与动作schema只读审查，记录脏树与并发编辑。
- [ ] M1：创建上述提示词与计划，备份准确原绑定；先建立四系统/双掌挂点/图集/Ribbon失败检查。
- [ ] M2：通过Monolith当前原生动作制作资源，每个动作读取真实schema；不猜字段名，不用文本伪装.uasset。
- [ ] M3：逐套编译、保存、冷加载、实际粒子/材质/历史尾迹验证；正常游戏距离、白天和暗背景至少各一次；输出原生截图与连续视频。
- [ ] M4：新火法技术可用后执行数字1可回滚视觉替换，验证按键→前摇→双掌→发射→飞行→结束，并验证取消/死亡/切图；记录视觉仍待用户验收，不将本次执行授权冒充质量签收。

## 不可绕过的边界
此前附件地址校验拒绝与Niagara作者脚本安全拒绝不能通过换路径、编码、传输渠道绕过。新的正常Monolith动作若被拒绝，记录实际操作与原因并停止该操作。不能把临时材质预览当成Niagara效果，不能把脚本轨迹当作服务器真实弹体接线，不能把零编译错误当成美术验收。未完成项必须逐项报告。

## 技术依据与假设
项目源码为本轮绑定依据，用户V3母图/验收文档为视觉依据。Epic UE5.8文档说明SubImageSize、SubImageIndex与帧混合，以及RibbonID/LinkOrder绑定；默认LinkOrder缺失时为0，因此本轮将其作为可测前置条件。以上尺寸、数量与阶段比例是工程候选，不宣称为母图原始参数。
