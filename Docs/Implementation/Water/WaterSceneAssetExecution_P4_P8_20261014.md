# SSLM 水体系统 P4—P8 场景资源实施清单（2026-10-14）

## 目标与代码边界

正式水域：虚幻引擎UE5.8官方Water（湖泊、河流）+ 项目自定义瀑布网格与Niagara；任何 Village（新手村）、OpenWorld（开放世界）、MainArena（主竞技地图）均不得依赖 Fluid Flux。角色工作室 `L_DBA_CharacterStudio`（本地角色选择/创建关卡）保留现有天然水景网格与材质，未来可选Fluid Flux必须是可移除的前端客户端适配，不得成为项目或水体运行模块的必需依赖。

权威水域查询保留于`GamePlatformWaterRuntime`（平台双端水域模块），可见水面仅客户端。VFX播放由`GamePlatformVFX`（平台特效服务）处理，不在水体模块中复制第二套Niagara播放器。雨、风、湿润由`GamePlatformWeather`（天气）与`GamePlatformSurface`（地表）提供，PCG岸线逻辑复用`GamePlatformPCG`（程序化场景）。

## P4｜独立水体审核地图

目标资产：`/Game/Development/Water/Maps/L_GP_WaterReview`（水体审核关卡）。禁止直接修改正式`L_Village_Start`（新手村起始地图），先通过独立验证。

| 审核对象 | 实际引擎对象或资源 | 首次建议位置（厘米，仅测试地图） | 功能和门禁 |
|---|---|---|---|
| 主湖 | `AWaterBodyLake`（官方湖体） | (0,0,0) | 默认关闭地形自动雕刻；湖面材质来自原生Water，静态底床先人工布置 |
| 水域规则 | `AGamePlatformWaterRegion`（平台权威水域） | (0,0,0) | 稳定RegionId=Review.Lake；Box范围与湖面重合，水域几何不从渲染波浪计算 |
| 溪流 | `AWaterBodyRiver`（官方河体） | (-2400,-2000,0) | 只在审核地图调试样条与流向，使用官方River材质实例 |
| 水幕 | `BP_GP_WaterfallVisual`（通用瀑布表现蓝图） | (2000,800,450) | 网格可见且有正式材质；水雾/飞溅/泡沫不得自动引起服务器碰撞 |
| 岸边交互 | `NS_GP_WaterRipple`（涟漪）、`GamePlatformWaterInteractor`（交互组件） | (450,200,0) | 只有双端水域规则确认浸水后才发送本地表现请求 |
| 性能摄像机 | `ACameraActor`（镜头） | 三个观测点 | 同镜头对比打开/关闭水体、白天/夜晚/雨天的GPU与CPU帧时 |

第一道验收：地图资产真实保存并回读；蓝图、Niagara、材质编译没有错误；角色进入浅水触发本地水波，不同步GPU粒子；关卡反复打开没有水体重复注册。

## P5｜新手村“湖心三岛”集成清单

目标：`/DBAWorldPack_Village/Maps/L_Village_Start`（正式新手村地图），先做外部测试副本，验收后再增量迁入，不覆盖原高程/PCG生成结果。

- 主湖只允许一套WaterZone（区域渲染管理）及湖泊主体网格；湖面深浅材料实例采用`MI_DBA_Village_Lake`（新手村湖泊水材质）。
- 岛屿岸线分三类：岩岸、浅滩、码头。每类分别记录PCG Exclusion（排除区域）、岸线泡沫、湿润参数和潜在出生碰撞。
- 3—6处瀑布首先实例化通用`BP_GP_WaterfallVisual`（通用瀑布蓝图），每处只通过实例参数改变水幕尺度、落水水雾及裁剪距离，不创建重复蓝图类。
- 溪流与码头使用流向贴图、官方River网格或复用样条网格，不调用Fluid Flux实时仿真。
- PCG按优先级“河道水域与碰撞 → 水岸空洞与排除 → 岩石/道路 → 农田与聚落 → 植被”处理；水面下方不能生成遮挡的农田、树木或建筑。
- 深湖、落水潭和危险瀑布需分开权威游戏水域配置；水面颜色或Niagara白沫绝不能充当服务器深度规则。

## P6｜水体交互与网络

- 玩家涉水组件由`GamePlatformWaterRuntime`（通用运行模块）拥有，权威服务器判断水深/流向，仅在状态改变时发布可靠水域状态；客户端接收后向项目已装配的表现服务提交“Water.Ripple/Water.Splash”（水波/飞溅）语义。
- 近景可以在AnimNotify（动画通知）触发脚步涟漪，但不得每帧查询或每Tick播放粒子。
- 跨地图/退出必须解绑交互委托、撤销世界请求、归还特效实例；无水视觉资产时Gameplay照常执行。
- 船只波纹是后续表现增强，不把整套刚体流体放入服务器。

## P7｜角色选择和创建关卡Fluid Flux隔离门禁

正式原生方案优先复用：`/DBAFrontEndPack/Maps/L_DBA_CharacterStudio`（角色工作室），`M_DBA_Sanctuary_Water`（水面材质）、`M_DBA_Sanctuary_Waterfall`（瀑布材质）和原有水体/瀑布网格。

可选 Fluid Flux 仅作为PC高配角色展示的独立适配，必须满足：

1. 由受控、实际安装且UE5.8编译通过的版本提供依赖，否则保持完全禁用。
2. 不在主`.uproject`（工程配置）、`GamePlatformWaterRuntime`（权威水域）和世界内容包硬启用；禁止引入服务器Cook。
3. 只替换角色工作室视觉模块，身份、创建流程、玩家存档和角色物理不依赖它。
4. 降级与退出时停止流体模拟，并清理场景资源；对比GPU帧时、显存与切换100次后的资源残留。
5. 在拿到可兼容的插件和真实测试记录前，不创建伪造的Fluid Flux蓝图资产，也不宣称运行已支持。

## P8｜性能与质量分级（项目初始预算，非测量结果）

- 高：水面主材质、近距瀑布与局部涟漪；目标水体GPU增量不超过约2ms。
- 中：降低瀑布透明叠层、粒子生成率和岸线细节；目标约1.5ms。
- 低：远瀑布只保留水幕、关闭高级粒子与交互水面；目标约1ms。
- 移动端：单独简化材质，以目标设备30FPS测量为准。
- 所有档位同时记录`stat gpu`（GPU时间）、`stat unit`（CPU/GPU帧时间）和`stat water`（水体统计），区分无水基线、仅Water主湖、瀑布主体、完整粒子、雨天场景，避免将图形指标伪报成已达成。
