# 材质函数库：第三层接入、迁移与回滚策略

## 前提检查

1. 读取当前Git（版本管理）分支、工作区差异、并行任务与真正UE Asset Registry（资产注册表）的引用者集合；没有这些证据只允许增量新增文档/不冲突资源，不可批量替换生产材质。
2. 所有既有发布MF、M、MPC路径保持不变；对项目源贴图和实例执行只读哈希或引擎资产依赖对照。
3. 不从`SourceArt`（纹理源文件）误判UE Texture2D（引擎纹理）已真实导入。

## 迁移流程

`审查父级和依赖 → 建新中性函数/母版/材质实例 → UE编译保存回读 → 中性审核地图A/B对照 → 项目单实例灰度替换 → 客户端启动与世界切换 → 真实Cook/Stage剥离审查 → 人工验收 → 按需扩大范围`。

不移动已发布资源；首次验证使用新文件名/独立路径，保持原村落、登录、角色选择和正式战斗资源不变。独立测试材质的默认输入必须明确，不能在正式Cook中不慎携带Development（开发演示）内容。

## 回滚机制

记录修改前的Git SHA（提交哈希）、资源包路径、母版父级、参数差异、所有引用者及原项目实例快照。若某批次Shader失败、效果不符合要求或客户端/服务器Cook异常，停止扩散，恢复原MI父级或切换回保留的原资产，不批量删除源资源、Redirector或已被其他工作引用的.uasset。

## 验收留证

每批次需要保留：新旧材质路径与用途、UE资产类型、图节点统计、Shader结果、截图、ProfileGPU（GPU采样/成本）数据、客户端Cook包含与专用服务器剥离清单，以及人工批准标识。无人签收时不标记Production Ready（生产可用）。
