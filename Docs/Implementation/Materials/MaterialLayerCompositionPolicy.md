# 雪、苔藓、湿润、冰霜与积水：材质覆盖层物理规则

## 一、避免简单按固定次序硬叠加

已存在的Surface架构文档（基础→苔藓→积雪→湿润→积水）和可选苔藓积雪PBR制作文档（基础→苔藓→湿润→积雪）分别适合不同场景，不能选一条当作通用物理规则。统一采用**语义遮罩/遮蔽关系**控制最终可见覆盖。

1. 基底：PBR（基于物理的渲染）属性与宏微细节保持真实原貌。
2. 附着：苔藓、地衣、污垢根据坡度、接触、湿度和预烘焙遮罩决定区域。**苔藓先作用于基底，雪会遮蔽苔藓，但不应无条件移除苔藓分布数据**。
3. 湿润：只修改可被雨水接触的暴露表面，适度调暗基础色、降低粗糙度、调节微法线；雨水本身不应让雪层变成镜面。
4. 雪/霜/冰：根据局部坡度、高度、温度可视值、覆盖遮罩和用户配置计算雪盖/霜盖/冰盖；冰冻优先决定雨水和积水的外观，不改变服务器碰撞。
5. 积水：受朝向、低洼/沟槽遮罩和雨水供给控制，仅在允许储水、未被实体积雪或冰层遮蔽的区域可见。
6. 室内、檐下、干燥物：必须提供明确的曝光/遮蔽遮罩，禁止通过“全局雨=1”给所有墙体和家具施加积水。

## 二、推荐遮罩关系（描述设计目标，不是已运行Shader）

所有值在0至1间，函数名为便于团队对照的语义伪代码：

```text
M = saturate(局部苔藓因子 × 全局苔藓影响 × 湿度亲和 × 增长空间遮罩)
W = saturate(局部湿润 × 全局湿润 × 天气曝光 × 非防水遮罩)
S = saturate(积雪分布 × 全局积雪量 × 高度限制 × 坡度限制 × 曝光)
I = saturate(结冰意图 × 温度条件 × 结冰介质遮罩)
P = saturate(局部低洼 × 水平面约束 × 全局积水量 × 曝光)
湿润基底 = Blend(原表面, WetLayer, W)
雪可见 = S × (1 - 冰层遮挡)
冰可见 = I × (1 - 不兼容冰层遮挡)
水面可见 = P × (1 - 雪可见) × (1 - 冰可见)
最终表面 = Blend(Blend(湿润基底, FrostOrIce, 冰可见), Snow, 雪可见)
最终表面 = Blend(最终表面, Puddle, 水面可见)
```

这里`Blend`（按遮罩混合）应针对BaseColor（基础色）、Normal（法线）、Roughness（粗糙度）、AO（环境遮蔽）等属性选择正确混合算法。法线不得直接做不归一化线性叠加；积雪、结冰水面与普通湿润采用不同着色/材质模型时需独立母版。真实几何积雪深度、脚印、融雪永久遮罩另由几何或持久化机制实现。

## 三、按测试用例验收

| 用例 | 期望结果 | 禁止现象 |
|---|---|---|
| 雨中裸岩 | 局部变暗、粗糙度变化、无屋顶/墙面无条件水镜 | 仅颜色变暗而粗糙度不变 |
| 雪覆苔藓 | 雪优先视觉覆盖，融化后原苔藓恢复 | 苔藓分布被永久删除 |
| 雨与雪同时出现 | 实际降水按天气权威值驱动，雪区不自动变镜面 | P值直接涂满雪层 |
| 冰冻积水 | 外观从液态向冰态过渡，由专用外观模型控制 | 直接改变服务器摩擦/碰撞 |
| 屋檐/洞内 | 显式曝光遮罩阻止雨雪入侵 | 室内全表面同步湿雪 |
| 坡面和立面 | 依材质/表面类型控制坡面分布 | 所有立面出现积水 |
| 角色局部受击 | 仅影响该对象材质实例或对象参数 | 全世界因单角色受击发光 |
