# 插件架构优化实施计划（2026-10-12）

## 目标与实施选择
根据已完成的只读审查及用户“给出实施计划最佳方案，然后按计划执行”授权，保留现有三层结构，逐项修复已确认的资源、生命周期、接口与证据问题。基线 main @ 7d44194333cda24f8a14495695e1d478deef5a97，47个代码插件、17个内容包。最终交付为可审查的工作区变更、真实验证证据和剩余前置条件，不以规划数量代替完成。

## 架构与技术栈
UE 5.8 C++，现有 GamePlatformData 资产管理器/租约服务，AssetRegistry（资产注册表），PowerShell 7 与 Python 验证脚本，单一 DivineBeastsArena.uproject 与 Client/Server/Editor 目标。
选择保留三层边界与现有插件身份的局部整改。全面重拆插件会扩大反射、资源路径及构建兼容风险；删除空壳模块不能解决当前加载和打包问题；仅修文档也无法封闭实际资源路径。

## 共同约束与实施决策
1. 用户已明确授权计划后执行，本计划直接进入实施。
2. 使用原工作区增量实施，保护当前其他 PCG 任务的未提交修改；变更按文件独占分工，共享文件由主代理协调。保存起始状态及变更证据，不提交/推送、不删除工作区。
3. 47个代码插件、17个真实内容包、稳定模块/反射/资源身份及三层依赖保持。平台不写项目资源根，不新建第二主工程或 DevHost。
4. GamePlatformData 仍为身份、加载、请求合并与租约唯一所有者；保留外部加载兼容基线，调用者只释放自身请求。
5. 不虚构正式技能ID、数值、资产或批准记录。缺少批准的正式内容必须保留门禁并明确输入条件。
6. 结构化源文件编辑带版本栅栏；所有新建/移动文件登记总体目录规划。独立任务可并行，UE构建、Automation和Cook统一串行执行。
7. .uasset/.umap只接受真实UE工具；UI资产必须Monolith。真实资产/视觉验收不能由源码检查替代。
