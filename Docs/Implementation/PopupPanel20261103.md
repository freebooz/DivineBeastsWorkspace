> 执行方式：当前会话按 superpowers:executing-plans 串行实施。用户已明确要求给出计划后直接实施，不新增确认关卡。当前共享正式工程按现有编辑器租约操作，不切换分支、不复制第二套工程、不提交其他任务改动。

**Goal:** 将用户 2026-11-03 提供的木框九宫格设计落成 SSLM 全部现有弹窗的统一背景，保留现有功能。

**Architecture:** GamePlatformUI 继续负责通用主题、CommonUI 层栈、事件与输入；DBAClient 继续负责项目页面语义；DBAUIPack_Core 拥有唯一背景纹理、UI 材质和现有 BP_DBA_BorderStyle_Panel。逐页背景接入同一 CommonBorderStyle，不新增弹窗管理器、轮询或第二套窗口。

**Tech Stack:** 锁定 UE 5.8，Monolith MCP，UMG/CommonUI/Slate 原生 Box 九宫格，PNG RGBA 与线性 Alpha，现有本地构建、UI RHI、Cook 工具。

## 视觉合同与实现选择

- 使用深棕木质包边、细暖金镶边、四角金属护角、温润浅米色内衬。保留参考图外观语言，控制颗粒、高频雕刻和碎片高光。
- 仅提取窗口底板。示例标题、说明、网格线、图标、按钮、山水插图和示例“60”设置均不烘入纹理，也不作为业务指令。
- 外部透明；内衬不透出世界。背景白乘色，颜色 sRGB 解码一次，Alpha 线性；无调色或 Gamma 补偿。
- 四角固定，四边单轴拉伸，中心填充；不用整图 ScaleBox 拉伸文字/控件。初始三种检查尺寸 320×220、640×440、1000×420，另核对现有各页真实尺寸。
- 浅内衬上的正文使用清晰深棕色，保留按钮标签、错误/警告语义、既定字号和业务控件尺寸；标题按实际位置核验。
- 实现比较：逐窗口复制纹理会形成多版本；新建弹窗服务会重复框架；采用现有共享 CommonBorderStyle + 一份底板资源。

## Global Constraints

- 所有真实 .uasset 必须由 Monolith 在正式工程创建、修改、编译、保存、回读；不能文本伪造。
- 共享编辑器顺序：按钮任务 → 头像任务（含冷读/RHI/Client Cook）→ 本任务。释放前只在根 Saved/Validation/PopupPanel20261103 制作候选，不修改插件 Content/SourceArt/Docs、代码或配置。
- 保留当前用户游戏端、Village/MainArena 服务器和其他任务的未提交修改。
- 所有临时与 Cook/Stage 输出必须在本工程内；不用 HWebCodex。
- 前端启动前必须绑定实际 Village/MainArena 进程核验战斗版本；调试 t.MaxFPS 0、r.VSync 0。资产预览不冒充联机或人工验收。
- 优先纯资产改动；若既有回归硬编码旧图/UV，更新精确断言并执行受影响目标增量构建，不关闭或弱化测试。

## Review Focus

1. 小窗口/超宽窗口边角是否变形、接缝或挤压：原生三尺寸渲染及像素检查。
2. CommonBorder 覆盖按钮命中区或挡住内容：核对原布局、ZOrder、Visibility 和点击/关闭焦点。
3. 页面主题在激活后覆盖新背景或文字：检查 ThemeBindings、StyleClass、真实实例，不能只看模板。
4. 错误与重连/邀请弹窗未接统一风格：按所有真实 Widget 和目录审计，登记豁免的全屏登录/加载/HUD/列表条目。
5. 新颜色在 RHI/打包后变色或旧作者复活：源图 hash、导入合同、冷重载、GPU 颜色与 Cook 资源引用审计。
