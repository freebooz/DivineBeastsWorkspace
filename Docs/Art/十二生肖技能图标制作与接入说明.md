# 十二生肖技能图标制作与接入说明

## 用户确认的范围

2026-10-09 用户明确选择每个生肖五枚，共六十枚：普攻、被动、主动一、主动二、终极。图像使用内置 image_gen 单资产生成，沿用现行 `ZodiacSkillVFXArchitecture.md` 的生肖视觉语言。技能正式名称、逻辑编号和玩法资产尚未登记，因此本次交付美术槽位资源，不制造技能授权、伤害、成本、冷却或协议身份。

## 三层归属与调用边界

- GamePlatform（平台层）：继续提供通用槽位状态、异步数据加载与界面机制。平台不保存生肖图像、不引用英雄包。
- MobaCommon（可选 MOBA 层）：继续提供竞技语义和通用竞技界面；本次不新增中间层图像或空模块。
- DivineBeasts（项目层）：现有 `DBAClient/DivineBeastsUIClient` 的 `UDivineBeastsAbilityUIProfile` 提供客户端图标软引用契约；各 `DBAHeroPack_*` 拥有本生肖五枚图像和真实 Texture2D。内容包是项目层内部资源所有者。

来源文件：`Game/Plugins/DivineBeasts/ContentPacks/Heroes/DBAHeroPack_<Hero>/SourceArt/UI/SkillIcons/*.png`（可维护原始图源）。

引擎资产：同包 `Content/UI/Abilities/T_DBA_<Hero>_<Slot>_<ArtMotif>_V1.uasset`（Monolith 导入的纹理）。沿用 `AbilityBarAutoBinding.md` 已约定的 UI/Abilities 路径。既有 Boar 插件身份保持不变。

`ArtMotif` 仅为可检索的视觉主题；`BasicAttack`、`Passive`、`Active01`、`Active02`、`Ultimate` 是美术槽位。它们不能替代正式 AbilityId，也不能通过命名自动给玩家授予技能。

## 制作与执行顺序

1. 核对主工程、当前修改、十二个已登记英雄包、现行图标软引用契约与编辑器版本。仅新增本次资源与说明，保留当前工作区其他任务的未提交修改。
2. 将完整六十条提示词记录在同目录 `ZodiacSkillIconPrompts.json`，逐枚生成。统一暗色背景、清晰主体、无字无边框；五种槽位用动作轮廓区分，终极图标使用最大视觉张力。
3. 检查每枚图像主体、生肖辨识、槽位动作、文字残留和小尺寸可读性，再将选定图源保存到唯一英雄包。失败或不合格项目不得记作已交付。
4. 在锁定 UE5.8 的 `Game/DivineBeastsArena.uproject` 中核对 Monolith 身份和动作目录，通过 Monolith 用户界面纹理导入能力生成真实资产，并保存、重载、回读尺寸、纹理组和保存状态。
5. 各包 `Docs/MonolithGenerationManifest.json` 记录图源摘要、引擎资产、具体导入动作、实际设置和验证结果；总体目录规划同步本次新增目录和文件。
6. 正式 AbilityId 批准后，再由客户端 UI Profile 的 Entries.Icon 使用软引用绑定这些纹理；不得从服务器 HeroDefinition/AbilityDefinition 硬引用纯 UI。图源保存完成和引擎纹理导入完成分别记录。

## 性能与验收边界

生成图源保留原始尺寸，客户端纹理采用 UI 用途和明确的最大分辨率；实际设置以 Monolith 回读证据为准。预览缩小检查辅助审核轮廓，不构成设备验收。未经真实 Cook 和产物审计，不宣称专用服务器已剥离资源。正式技能、真实 HUD 绑定、联机授权、移动端显存与客户端 Cook 不因制作图标自动完成。

本次没有界面布局或 Widget 蓝图修改，控件树、焦点、导航和 Blueprint 编译不适用于独立 Texture2D；资产身份、保存、重载和纹理设置仍必须验证。编辑器或 Monolith 阻塞时保留真实 PNG 并明确列出尚未生成的引擎资产，禁止文本伪造 uasset。

## 实际交付结果

图源阶段已完成：十二个英雄包各五枚，共60枚真实PNG，实际源尺寸均为1254×1254，合计145,805,342字节。每枚源图的SHA256、尺寸和路径记录在逐包清单，四页预览用于人工检查视觉语言与64像素轮廓。提示词中请求1024×1024，实际生成器输出1254×1254，因此保留实际图源尺寸；导入后再次校验六十枚图源SHA256均未改变。

引擎纹理阶段已完成：在真实 `Game/DivineBeastsArena.uproject`、UE `5.8.0-0+UE5` 和 Monolith `0.23.0` 中，使用 `ui.import_texture_from_bytes` 顺序生成并保存60个真实Texture2D。全部目标路径精确匹配清单，无自动重名后缀；纹理源回读1254×1254、不透明。实际设置全部为UI组、sRGB、TC_EditorIcon、NoMipmaps、MaxTextureSize=256。1254源尺寸在引擎上限处理后，实际运行纹理尺寸全部为156×156，不能把最大上限256描述为实际输出256。

全部60个自有包通过 `unreal.EditorLoadingAndSavingUtils.reload_packages` 原生批量重载，返回有包重载且无错误，随后再次读取全部资产类型、设置与保存状态，六十个包均dirty=false。首枚单包预试因首次重载耗时超过代理30秒而丢失工具响应，编辑器日志确认成功；最终60包批量重载收到真实成功响应。证据位于 `Saved/Validation/ZodiacSkillIcons-2026-10-09/`，包括身份、导入/保存、原生重载、重载后回读、原生源像素检查与二进制文件摘要。

本次仅交付五种美术槽位的纹理，没有生成正式技能名称、AbilityId、技能授权或空UI Profile；十二个清单中的AbilityId均保持null。独立Texture2D不适用Widget树、层栈、焦点、导航或Blueprint编译，真实HUD绑定、客户端运行、设备/色觉适配和Cook仍待后续验收。

专用服务器配置已补齐十二个英雄包UI/Abilities的NeverCook声明和同路径窄Pak排除，不排整个英雄包的玩法定义或权威动画；声明检查不等于Cook或产物审计，ClientCookVerified、ServerCookExclusionVerified和GameplayBindingVerified继续为false。编辑器初始日志存在未具名的Condition failed记录，本次纹理验证不代表全Editor/自动化测试通过；其他任务的未保存界面包没有由本任务保存或重载。
