# SSLM 全局美术配色策略与色彩设计规范 V3.0

> **正式权威色彩策略**｜登记日期：2026-10-18｜适用：DivineBeastsWorkspace / Unreal Engine 5.8（虚幻引擎）｜来源：用户2026-10-18 V3.0原稿与现行工程规范整合。  
> **状态**：正式设计约束；下面的HEX均为**待UE固定曝光校准及人工验收的初始sRGB屏幕参考**，不是《王者荣耀》官方采样，不是UE线性材质BaseColor的直接数值，更不代表已制作的引擎DataAsset（数据资产）或正式场景已经修改。  
> **唯一真源约定**：本文是全局色彩语义及视觉方向唯一权威文档；[派生颜色索引](SSLMColorRegistry_V3.json)仅用于检索/未来配置输入；专项地形/材质/PCG/UI/VFX文档仍管各自实现与性能，不另设相互冲突的色彩真源。

## 一、视觉定位与优先级

**参考《王者荣耀》经典王者峡谷地形、地面、草地、道路、岩石、水体、自然植被及场景物品的明快自然配色方法，建立具有东方神话气质的独立3D游戏风格。**目标为明亮、鲜艳、自然、通透、唯美、精致，兼顾艺术化写实、真实PBR（基于物理的渲染）和高质量电影级空间光照；不得复制第三方资产、地图或自称取得对方官方色样。

全局划分五套颜色语义系统：
1. **环境色彩**：草地、土壤、岩壁、水、植物和自然生态，以生态连贯性与明快度优先。
2. **建筑物品色彩**：木构、屋瓦、石材、桥梁、围栏、农具、装饰及可交互物，与场景地质/生态协调。
3. **角色怪物色彩**：生肖英雄、NPC、怪物、装备和皮肤，以角色轮廓、材质及身份辨识优先。
4. **战斗技能色彩**：技能的元素视觉、威胁范围和敌我状态，以公平与可读性优先，不由环境滤镜覆盖。
5. **UI品牌色彩**：登录、角色选建、HUD、背包、任务、社交与系统界面，以玄墨青、碧玉、鎏金为主；**不得据此将整个世界地形、水体、植被统一染成品牌玉色**。

强制层级：**敌我与危险边界、关键玩法状态 > 角色及技能主体 > 交互提示 > 普通装饰环境**。严禁荧光绿、过曝白、灰黑浑浊与过饱和噪声；自然环境宜丰富而不争夺战斗视线。须同时通过实际游戏镜头、近中远景与色觉辅助审核，不得单纯靠颜色区分关键状态。

## 二、环境标准色板（初始屏幕sRGB）

### 2.1 草地：鲜活、舒适、层次自然
- 标准草地 **#6B9956**；阳光草地 **#86AD62**；嫩绿草地 **#A6BC76**；林地草地 **#4F7B52**；草地阴影 **#426D51**。
- 采用黄绿、翠绿、青绿的和谐过渡。朝阳略暖、背光略冷；地形贴图和PCG（程序化内容生成）草簇应匹配，不使用随机大色块、纯色荧光、塑料反射、脏灰植被。远景与近景保持同一生态语义。

### 2.2 泥土与自然道路：暖色通行引导
- 浅黄土地 **#C5AD83**；标准泥土 **#A88F6D**；林间小路 **#B7A181**；湿润泥土 **#79705C**。
- 以自然黄褐、浅褐、灰褐为主，交通道路与草地适度明度区分；湿度/踩踏/坡度的变化局部控制，边缘以泥土、草、碎石、苔藓渐变融合；避免整体灰黑或浓艳红褐。

### 2.3 石板道路与广场：明亮温润
- 暖灰石板 **#C8C5AD**；米灰石材 **#B9B6A0**；冷灰石材 **#8F9D94**；石缝苔绿 **#64836A**。
- 村落、主城和竞技场可有不同质感，但不能大面积灰黑；色差克制，真实法线/粗糙度，按真实俯视摄像机控制纹理频率，防止道路细节抢占技能视觉。

### 2.4 岩石与悬崖：灰青/暖灰，和地形一致
- 灰青岩石 **#89988C**；暖灰岩石 **#A8A38C**；深灰青岩 **#63776F**；苔藓岩石 **#718B68**。
- Nanite（虚拟微多边形）岩石、Landscape（地形系统）石层和RVT（运行时虚拟纹理）边缘自然衔接。亮面与背阴有真实冷暖差，苔藓出现在裂缝、根部与合理坡面而非整座山涂绿；防止过度锐化、灰暗与来源不同的石包突兀割裂。

### 2.5 苔藓、湿润和积雪
- 苔藓取自然黄绿、翠绿、湿青绿；雪用自然白/冷白与柔和蓝灰阴影。覆盖受坡度、高度、接触、朝向、气候控制，不强制把全部石材染绿。
- 湿润必须联动 BaseColor（基础色）、Roughness（粗糙度）和必要的法线，不仅压黑颜色。继续复用现有GamePlatformSurface通用函数与材质层组合；其 [AssetAuthoring（材质资产制作规范）](../../Game/Plugins/GamePlatform/Presentation/GamePlatformSurface/Docs/AssetAuthoring.md) 管理真实函数合同。

## 三、自然植被与桃花生态

- 树冠上层阳光黄绿/翠绿、中层自然绿、内层深绿/灰绿，阴影稍冷青但不发黑。SpeedTree树木、PCG灌木与Landscape草面保持协调；同类植物只作小幅、有规则的色差，不用不受控的随机颜色。
- 桃树专属色：浅桃粉 **#E8B6BD**，柔粉 **#D99EA9**，桃花暖白 **#F1D5CF**，桃叶青绿 **#779D68**。树冠有体积，粉花、翠绿草坪、青碧湖面形成层次；禁止荧光粉、过紫和泛白。落花、根际草、湿岩融入生境。
- 灌木略深于草，花卉只使用小面积白、黄、粉、蓝紫点缀。生态分布由现有ProjectPCG（项目程序化内容生成）和生境数据资产控制，外部植被包导入须先校准色彩、贴图和LOD。

## 四、水域：青碧清澈、深浅可辨

- 浅水青绿 **#6DBCB0**；标准青碧水 **#4A9F9F**；深水青蓝 **#287984**；水花泡沫 **#DAEDE6**。
- 实际水色取决于水深、河床/湖底、透射散射、环境反射与时间天气；禁止整片纯蓝不透明贴色、高自发光、塑料反射、过曝白斑。河流、湖泊、溪水与瀑布使用统一色彩语言；岸线湿岩、植被与水顺滑衔接。
- SSLM湖心三岛桃花新手村重点建立**清澈青碧深湖 + 粉白桃林 + 翠绿草地 + 暖木建筑 + 柔和晨雾**的标志性环境，不用浓雾掩盖材质或缺陷。

## 五、建筑与普通场景物品

- 暖木色 **#997C5E**；深木色 **#685541**；青灰瓦色 **#627B79**；浅灰石材 **#BDBBAB**；装饰鎏金 **#C6A569**。
- 房屋木构、木桥、围栏、树桩、货车、木桶、农具、耕地、草垛、岩石雕塑、台阶、石灯、石碑、神龛、宝箱和资源点遵循所在生态的材质和冷暖。金属需真实 Metallic（金属度）与粗糙度；重要建筑可少量鎏金，但不能以金色/自发光堆出虚假高级感。
- 交互对象只使用局部高亮、轮廓、图标或适量发光以区别环境；普通摆件应克制，不要大量高饱和装饰。导入第三方资产时校验许可证、Albedo（基础颜色）、法线、ORM和色彩空间。

## 六、十二生肖、五行**视觉**与Niagara特效

- 十二生肖人物**第一眼神兽英雄、第二眼生肖血统**；不同英雄可有独特装备主色和特效色，但轮廓与身份不能只凭色相识别；不得掩盖角色与敌我信息。
- 木·翠青绿 **#47B986**；火·朱焰橙 **#F16B46**；土·赭金 **#D5AA65**；金·银青 **#B5CADC**；水·寒渊蓝 **#409CE5**。**以上是可选技能/艺术视觉色板，并非五行伤害类型、技能ID或战斗判定。**目前AGENTS.md明确禁用旧五行机制及“破元/共鸣”玩法；用户V3.0的相关历史措辞不得用于恢复已废弃数值和规则。
- Niagara（粒子特效）分为元素主体色、能量核心高光、少量辅助粒子色、独立敌我/威胁语义色。普通与终极技能允许不同表现层级，禁止无限抬升Emissive（自发光）、Bloom（泛光）或System/Emitter/透明片数量。1v1—5v5强并发时关键主体与危险边界必须可见，低端降级先减装饰。具体生命周期、Effect Type（特效类型）、NDC（数据通道）、性能阈值仅引用[现行十二生肖VFX专项规范](../Architecture/SSLM十二生肖技能VFX性能与视觉质量规范.md)，不复制第二套执行/预算真源。

## 七、SSLM品牌UI与HUD状态（强制）

品牌UI：
- 玄墨青 **#10282D**；深碧玉 **#227E70**；灵玉青 **#68D7B4**；鎏金 **#D9B773**；玉脂白 **#E8F0E7**；警示朱红 **#E46A5C**。
- 配合当前已确认的自然、藤蔓、叶片、温润玉石、远古意象主题，表面光洁、低噪声、不过度磨砂锐化。**品牌色限于UI及有意义的项目装饰，不得作为所有地面和世界物品的全局Tint（染色）。**
- 状态语义：**生命=绿色；能量=蓝色，显示在生命条下方；气势=独立暖金色；施法进度=亮玉青色；友方/敌方=稳定统一标识；禁用/冷却=低强调状态并辅以文字图标或形状。**本次源文件未给这些状态各自唯一HEX，不能擅自当作已批准的功能HEX。
- 旧版[Nature UI（自然主题）](../Implementation/NatureUIFinalTheme.md)曾把蓝条标为气势；现行2026-10-18[技能栏制作合同](../../Game/Plugins/DivineBeasts/ContentPacks/Presentation/DBAUIPack_Core/Docs/SkillBarDelivery_20261018.md)具有已保存的真实纹理/Widget（控件蓝图）。**本规范更新色彩语义，不宣称旧蓝条或已审核的技能栏纹理/几何已经重制；后续须单独Monolith（编辑器自动操作）与人工视觉签收后才能变更资产。**
- 原稿资产须保留源RGB、Alpha和已确认尺寸；彩色原稿启用sRGB，线性遮罩关闭；UI Brush（画刷）默认白色乘色。禁止通过调亮/调暗、过度锐化或全局色彩滤镜补偿错误Gamma。现行Monolith 0.23.0 的 widget 截图链存在额外Gamma编码，严禁作为最终颜色证据；依[UI颜色链路](../Implementation/UIColorPipeline.md)及[UI纹理视觉规范](../Implementation/UITextureVisualPolicy.md)使用真实RHI（渲染硬件接口）线性回读或可信原生客户端截图。

## 八、场景光照、颜色空间与画质层级

- 顺序：**正确纹理/PBR材质基础色 → 主光、天光、反射、雾、曝光与白平衡 → 最后克制的Color Grading（色彩分级）**。不允许强泛光、全屏滤镜或不受控自动曝光掩饰贴图缺陷。
- 所有HEX为**sRGB屏幕目标色**。Base Color彩色贴图按sRGB解码后在UE线性计算；Normal（法线）、ORM（遮蔽/粗糙度/金属度）、蒙版等按线性数据处理。FLinearColor（线性颜色）参数需进行合法的sRGB→线性转换与最终显示校准，不能把HEX除255当作UE线性颜色直接硬写。
- 固定美术审核场景须记录UE5.8版本、平台/RHI、渲染分辨率、Lumen（动态全局光照）、Directional Light（方向光）、Sky Light（天空光）、Sky Atmosphere（天空大气）、Exponential Height Fog（高度雾）、Post Process Volume（后处理体积）、Tone Mapping（色调映射）、Exposure（曝光）、White Balance（白平衡）、Bloom及是否自动曝光。
- 优先固定曝光比对参考，再检查清晨/黄昏/夜间、天气和自动曝光；PC与移动端可用不同渲染实现，但低、中、高、史诗画质必须保持颜色语义、角色轮廓与危险区辨识。评审使用真实游戏摄像机，而不只以静态材质球判断。

## 九、区域氛围和生态预设

- **Village（新手村）**：明亮晨光、翠绿草、粉桃树、青碧湖、暖色古木构、薄瀑雾。
- **OpenWorld（常驻世界与主城）**：主城明亮自然光、浅灰石板、青灰瓦、温暖木、翠绿园林与少量鎏金；开放世界森林、草原、雪山、沙漠、遗迹与秘境应符合当地生态，不强制同一色板。
- **MainArena（多人竞技场）**：借鉴明快峡谷的草地、道路、野区和河道分区，强调目标/危险范围/英雄与地面的对比；1v1—5v5均审视觉公平。
- 夜景、特殊剧情、地下城、火山、雨雪等例外允许偏离日间参考色，但必须登记范围、原因、责任人与人工审核结论；不得改变生命/能量/气势/阵营语义。

## 十、三层插件职责和真实资源归属

现行技术边界是**GamePlatform（平台层）→ MobaCommon（MOBA通用层）→ DivineBeasts（项目层）**按消费者向下依赖；“GameFoundation”仅为用户原稿中的通用平台称谓，不是工程正式插件名，禁止为统一颜色另建GameFoundation插件、第二套PCG/VFX/UI或重命名现有模块。

- GamePlatform：通用颜色语义基础、材质函数、贴图属性/资产验证；GamePlatformSurface（表面材质）、GamePlatformWater（水体）、GamePlatformPCG（PCG）、GamePlatformVFX（特效）、GamePlatformUI（界面）保持各自既有机制所有权。
- MobaCommon：通用敌我与预警的竞技表现语义，不持有生肖项目颜色、不调用服务器以外的权威判定，不复活五行克制玩法。
- DivineBeasts：SSLM品牌/生肖视觉色、生境与场景主题/气势色，材质实例与资源按现有DBAWorldPack_*（项目世界内容包）、DBAUIPack_Core（项目公共界面包）、DBAPresentationPack_Core（项目公共表现包）、DBAHeroPack_*（英雄包）持有；项目可下行消费平台接口，基础层不可引用项目色板/内容包。
- 数据驱动链建议：颜色语义ID→项目色板/主题定义→Material Instance（材质实例）/UI样式/Niagara User Parameter（用户参数）→局部审定资产。只有全世界确需同步的环境参数可以复用Material Parameter Collection（MPC，材质参数集合），大量局部颜色与不同生境优先使用MI（材质实例）和DataAsset（数据资产）。此处只确立未来合同，**不宣称已落地蓝图/数据资产/运行时接线**。

## 十一、标准化资产台账与质量门禁

每项色彩定义需具备**语义标识、中文名称、HEX与sRGB来源、使用范围、可调整范围（须审核批准，不伪造）、资产归属、实际实例配置路径、版本、审核人、审核状态**。派生索引中的“待绑定”不等于UE资产存在；真正落地需通过UE5.8编辑器保存、Shader（着色器）编译、冷重载与真实目标Cook（内容烘焙）。

**设计门禁**：世界明快自然且不同生境合理，建筑/场景物品与地形协调。  
**资源门禁**：材质/纹理/PBR/sRGB/Normal/ORM等属性正确，原稿/许可证可追溯，外部资源导入先审。  
**场景门禁**：地形与PCG草木、Nanite岩石/RVT、水岸、建筑、近中远景匹配，固定曝光及昼夜天气下可复核。  
**战斗门禁**：角色轮廓、敌我、施法、AOE（区域范围）、命中反馈在10人技能并发和低档画质均清楚，兼顾色觉辅助。  
**性能门禁**：检查Shader Complexity（着色器复杂度）、Quad Overdraw（透明过绘）、材质采样、动态灯光、GPU/CPU/内存与帧时间，不能以颜色调整为由损伤主机/移动端预算。  
**人工门禁**：每项视觉变更必须提供“修改前—参考目标—修改后”真实截图、场景镜头/设备、实际更改项、GPU影响、审核人/结论与整改记录；无人签收不得标记正式通过。

标准审核场景应至少涵盖：十基础地形代表区域、草/灌/乔木、石崖、桃林、湖和瀑布、建筑道具、十二生肖代表角色、施法/命中、正式游戏相机，以及标准日间/晨昏/夜间/天气、多画质、灰度和色觉辅助检查。
