# 业务服务说明

适用范围：当前 `Backend/cmd` 下五个薄应用入口及其本地、生产装配边界。本文依据实际 Composition、HTTP 适配器和领域模块说明职责，不把预留领域目录或未来基础设施当作已运行服务。

## 1. 服务总览

| 服务 | 本地 HTTP 端口 | 主要职责 | 对外边界 |
| --- | --- | --- | --- |
| GatewayService | `28080`（容器内 `8080`） | 统一接入、请求追踪、Bearer 认证上下文、下游 HTTP 调用。 | 唯一面向游戏客户端的当前公网接口；本地 Swagger 位于 `/swagger/`。 |
| IdentityService | `8081` | Guest 登录、会话创建、Access Token 验证。 | 仅内部 HTTP；不能直接暴露到客户端。 |
| PlayerDataService | `8082` | 跨局长期玩家资料读取。 | 仅内部 HTTP；不承载实时战斗状态。 |
| MatchService | `8083` | 当前已实现创建 Party 与匹配票据；领域层还承载比赛编排边界。 | 仅内部 HTTP；玩家身份由 Gateway 认证后传递。 |
| GameServerControlService | `8084` | Dedicated Server 注册、状态、世界/竞技场分配、迁移票据、权威比赛结果。 | 仅供可信后端、编排适配器和 Dedicated Server 使用。 |

每个服务都由 `Backend/internal/app/servicehost` 统一提供 `/health/live`、`/health/ready` 和 `/version`。本地启动脚本轮询所有五个就绪端点及 Swagger 文档入口。

## 2. 调用关系与数据所有权

```text
游戏客户端
  → GatewayService
      → IdentityService（登录、令牌验证）
      → PlayerDataService（长期资料）
      → MatchService（组队、匹配票据）

可信 Match/编排流程
  → GameServerControlService（MainArena 分配、迁移、比赛结果）
      → Outbox → NATS JetStream（仅生产依赖装配）
```

- **身份与会话**由 IdentityService 拥有；Gateway 只建立认证上下文，不伪造令牌或会话事实。
- **长期玩家资料**由 PlayerDataService 拥有；客户端不得提交权威余额、隐藏分、比赛结果或实时战斗状态。
- **赛前 Party 与匹配票据**由 MatchService 拥有；Party 是不可拆分的匹配原子单元，单人可直接匹配。
- **服务器注册、容量、Assignment、迁移票据和竞技场释放**由 GameServerControlService 编排；三种正式服务器角色仅为 OpenWorld、Village、MainArena。
- **比赛结果**只能由匹配 Assignment 对应的 MainArena Dedicated Server 提交，成功后进入持久化和 Outbox 流程。

## 3. 本地与生产依赖差异

| 依赖 | 本地 Docker Compose | 生产依赖装配 | 责任与限制 |
| --- | --- | --- | --- |
| PostgreSQL | 未部署；使用内存仓储 | 结果、事务发件箱和业务持久化 | 生产写入必须有迁移、备份、回退、授权和一致性验证。 |
| Redis | 未部署 | 缓存、会话或协调的生产适配器 | 不得把内存替身误报为分布式一致性实现。 |
| NATS JetStream | 未部署；本地仅记录发布日志 | Outbox 持久发布适配器 | 当前只有 `Match.Completed` 发布代码；消费者/Stream 配置尚未实现，见 `Docs/Backend/消息总线订阅说明.md`。 |
| Agones | 未部署 | MainArena 实例分配适配器 | 常驻世界实例、容量和跨服由控制面管理；不能以本地内存分配替代生产编排。 |
| Dedicated Server | 未启动 | UE Server 目标与真实世界/竞技场实例 | 本地 HTTP 健康通过不等同客户端准入、网络复制、五种模式或跨世界迁移完成。 |

生产配置由 `Backend/configs/production.env.example` 说明变量名称。真实 PostgreSQL、Redis、NATS、Agones 地址、证书、服务器凭据和迁移票据密钥不得提交到仓库或客户端配置。

## 4. 生命周期与运行操作

本地一键启动：

```powershell
powershell -ExecutionPolicy Bypass -File Deploy/Local/StartBackendDevelopment.ps1
```

脚本通过 `Deploy/Docker/docker-compose.backend.local.yml` 构建并启动五个服务。它保留容器并复用本地网络；不创建生产数据库、消息基础设施、支付事务或真实游戏服务器。

查看状态与日志：

```powershell
docker compose --project-directory . -f Deploy/Docker/docker-compose.backend.local.yml ps
docker compose --project-directory . -f Deploy/Docker/docker-compose.backend.local.yml logs --tail 200
```

停止本地服务：

```powershell
powershell -ExecutionPolicy Bypass -File Deploy/Local/StopBackendDevelopment.ps1
```

停止脚本使用 Compose `down --remove-orphans`，不会附加 `-v`，避免删除不属于本次本地服务的卷。对生产环境的下线、扩容、数据库操作、凭据更新和发布必须走独立审批与回退流程。

## 5. 验证与限制

```powershell
powershell -ExecutionPolicy Bypass -File Tests/Contracts/ValidateBackendApiDocumentation.ps1
powershell -ExecutionPolicy Bypass -File Tests/Deployment/ValidateBackendDevelopmentDeployment.ps1
powershell -ExecutionPolicy Bypass -File Tests/Deployment/StartBackendDevelopmentIntegration.ps1
```

这些检查覆盖 OpenAPI 与已注册 HTTP 路由、Compose 结构、本地 Swagger 文档入口以及服务就绪状态。它们不替代 Go 生产依赖构建、真实 NATS JetStream 消费、PostgreSQL 事务、Redis 协调、Agones 分配、UE 编译/Cook、Dedicated Server 联调、跨世界清理或生产发布验收。
