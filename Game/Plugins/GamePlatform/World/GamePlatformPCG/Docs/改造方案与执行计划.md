# GamePlatformPCG（游戏平台程序化内容生成插件）1.0 改造方案与执行计划

版本：1.0  
规划日期：2026-09-29  
适用工程：DivineBeastsWorkspace（神兽联盟工作空间）  
正式插件：`Game/Plugins/GamePlatform/World/GamePlatformPCG`

> 本文是当前 `GamePlatformPCG 0.1.0` 向 1.0 环境 PCG（程序化内容生成）操作系统底座演进的正式实施基线。本文不代表下列 C++、PCG Graph（PCG图）、Data Asset（数据资产）或地图资产已经实现。

---

## 一、改造目标

在不创建第二套 PCG 插件、不破坏现有三层架构的前提下，将当前“有限 Profile（配置）+ 固定图白名单 + 有界运行生成 + Bake Manifest（烘焙清单）”升级为可服务 3A 开放世界的统一环境 PCG 底座。

1.0 平台能力覆盖：

- Schema v1（属性协议）。
- P0～P9 Primitive（原语）稳定编号。
- P1 Scatter（散布）、P2 Linear（线性）、P3 Connector（连接件接口）、P4 Parcel（地块）、P6 InterfaceBand（界面带）的主路径。
- ExecPreset（执行预设）、MeshSet（网格集合）、SpawnPolicy（生成策略）、Layer（层）、Biome（群系）、Road（道路）、Enclosure（围合）、Parcel（地块）、Crop（作物）、Connector（连接件）等通用 Definition（定义）。
- PriorityCarve（优先级挖洞）统一互斥。
- 基础放置器 Actor（实体）家族。
- WorldDirector（世界生成编排器）。
- Template Contract（模板合同）式 Graph Validation（图校验）。
- Editor Validator（编辑器校验器）、CI（持续集成）门禁、Bake Manifest（烘焙清单）和确定性验证。

1.0 不交付：

- Landscape（地形）高度/图层写入。
- 自动桥求交、自动路堑。
- 完整城市街区、室内、洞穴。
- 砍伐/收割/毁桥运行态持久化。
- RuntimeAuthoritative（运行时权威 PCG）。
- 以“同 Seed（种子）”替代服务器权威或 Bake（烘焙）一致性证明。

## 二、当前真实基线与必须保留的能力

### 2.1 插件身份与模块

保持：

```text
GamePlatformPCG             # Runtime（共享运行模块）
GamePlatformPCGEditor       # Editor（编辑器模块）
```

不创建：

```text
ProjectPCG
DivineBeastsPCG
GamePlatformPCGCore
GamePlatformPCGNodes
GamePlatformPCGWorld
GamePlatformPCGNetwork
GamePlatformPCGConnector
GamePlatformPCGParcel
GamePlatformPCGBiome
```

除非未来有真实的编译边界、端侧隔离或依赖闭包需求，否则不为目录整齐机械拆模块。

### 2.2 已有代码资产

必须增量复用，而不是重写：

- `UGamePlatformPCGProfileDefinition（PCG配置定义）`。
- `UGamePlatformPCGBakeManifest（PCG烘焙清单）`。
- `FGamePlatformPCGRequest/Handle/Snapshot（PCG请求/句柄/快照）`。
- `IGamePlatformPCGService（PCG运行服务）`。
- `UGamePlatformPCGWorldSubsystem（PCG世界子系统）`。
- `GamePlatformPCGInspection（PCG审查适配器）`。
- `GamePlatformPCGPolicy（PCG策略）`。
- `UGamePlatformPCGEditorLibrary（PCG编辑器工具库）`。
- Source Fingerprint（源指纹）与 Output Fingerprint（输出指纹）机制。

### 2.3 当前限制

当前 `PCGGraphInspection.cpp（PCG图检查实现）`只允许：

```text
CreatePointsGrid
→ TransformPoints
→ DensityFilter
→ StaticMeshSpawner
→ Output
```

并明确拒绝：

- Hierarchical Generation（分层生成）。
- GPU（图形处理器）节点。
- 子图。
- 蓝图 Element（元素）。
- 任意参数旁路。
- 多网格目录。
- Landscape（地形）采样。
- 排除、道路、农田、围栏等外部输入。

此白名单不能直接删除；必须迁移为更一般、但仍可审计的 Template Contract（模板合同）。

## 三、三层架构修改方案

### 3.1 GamePlatform（游戏平台层）

拥有所有跨项目稳定机制：

- Schema（协议）。
- Primitive（原语）。
- Definition（通用定义）。
- Priority（优先级）。
- PCG Node（PCG节点）。
- 基础 Actor（实体）。
- WorldDirector（世界编排）。
- Runtime/Editor 执行边界。
- Template（模板）规则。
- Bake/Manifest（烘焙/清单）。
- Validator/CI（校验器/持续集成）。
- World Partition/HiGen（世界分区/分层生成）适配。

禁止包含：

- 神兽联盟名称或生肖语义。
- 桃花新手村、主城、MainArena（主竞技场）特定规则。
- 具体桃树、麦田、竹林、门楼、木桥资产。
- 项目 Quest/UI/VFX（任务/界面/视觉特效）语义。

### 3.2 MobaCommon（MOBA通用层）

M0～M4 均不新增 PCG 插件或模块。

只有未来多个 MOBA 项目共同出现稳定的竞技场空间协议，例如兵线槽位、塔位、野区槽位、竞技场对称生成，才单独评审是否需要中间层扩展。

### 3.3 DivineBeasts（神兽联盟项目层）

`DBAWorlds（神兽联盟项目世界插件）`只负责项目世界组合和 Definition（定义）校验。

真实 PCG 内容归：

```text
ContentPacks/Worlds/
├── DBAWorldPack_OpenWorld/
├── DBAWorldPack_Village/
└── DBAWorldPack_MainArena/
```

其中 Village（新手村）的桃林、农田、道路、围栏、码头周边、桥排除和资源点应最终由 `DBAWorldPack_Village（神兽联盟新手村世界内容包）`持有。

纯参数差异使用 Data Asset（数据资产）或 Graph Instance（图实例）；没有新增结构时禁止新建项目 C++ 子类。

## 五、Schema v1 修改方案

### 5.1 新增稳定代码契约

计划新增：

- `FGamePlatformPCGSchemaVersion（PCG协议版本）`。
- `FGamePlatformPCGSchema（PCG字段注册与校验）`。
- `FGamePlatformPCGAttr（PCG属性访问器）`。

禁止业务代码直接散落：

```cpp
TEXT("Pcg.Biome.Id")
TEXT("Pcg.Exclude.Mask")
```

必须统一通过 `FGamePlatformPCGAttr` 访问。

### 5.2 Schema v1 字段

保留用户定义的核心协议：

- `Pcg.Biome.Id（群系ID）`
- `Pcg.Biome.Weight（群系权重）`
- `Pcg.Biome.Priority（群系优先级）`
- `Pcg.Layer.Name（层名称）`
- `Pcg.Layer.Index（层序）`
- `Pcg.Spawn.MeshSetId（网格集合ID）`
- `Pcg.Spawn.ClassId（生成类ID）`
- `Pcg.Spawn.Flags（生成标志）`
- `Pcg.Rule.Slope（坡度）`
- `Pcg.Rule.Height（海拔）`
- `Pcg.Rule.Wetness（湿度）`
- `Pcg.Exclude.Mask（排除权重）`
- `Pcg.Exclude.Source（排除来源）`
- `Pcg.Exec.GridBand（网格带）`
- `Pcg.Exec.LodBand（细节级别带）`
- `Pcg.Exec.Seed（执行种子）`
- `Pcg.Encl.Kind（围合类型）`
- `Pcg.Connector.Type（连接件类型）`
- `Pcg.Mutable.Id（可变对象稳定ID）`

资产字段优先使用稳定目录 ID，而不是允许图携带任意 SoftPath（软路径）。

### 5.3 缺字段策略

节点缺少必需字段时：

1. 返回稳定 Warning/Error Code（警告/错误码）。
2. 输出安全空数据。
3. 不崩溃。
4. Shipping Gate（发行门禁）可将关键 Schema 缺失升级为 Error（错误）。

## 十、PriorityCarve（优先级挖洞）方案

所有“谁切谁”的互斥统一走 PriorityCarve，不再为道路排树、农田排树、围栏避路、桥排作物分别实现逻辑。

默认优先级仍采用 100～5 分层，但最终运行应由 `UGamePlatformPCGPriorityTableDefinition（优先级表定义）`版本化持有；`DefaultGamePlatformPCG.ini（默认PCG配置）`只提供工程缺省值。

稳定原则：

- ManualLock（手工锁定）最高。
- 高优先级切低优先级。
- 低优先级不能反切高优先级。
- 同优先级采用稳定 Tie Break（决胜规则）。
- 不确定时不生成，人工 Override（覆盖）优先。

## 十二、WorldDirector（世界编排器）边界

WorldDirector 只负责：

- 阶段编排。

- DirtyBounds（脏区域）管理。
- Priority Bus（优先级总线）。
- 批次与阶段依赖。
- Bake 状态汇总。
- 验证入口。

它不重新实现当前 `UGamePlatformPCGWorldSubsystem` 已有的请求生命周期、异步清理和所有权模型。

关系固定为：

```text
WorldDirector（世界编排）
        ↓
GamePlatformPCGWorldSubsystem（世界生命周期）
        ↓
Official PCG（官方PCG）
```

## 十三、Graph Inspection（图检查）迁移方案

### 阶段 A：保留旧白名单

M0 初期继续允许当前四节点开发夹具，确保回退路径存在。

### 阶段 B：引入 Template Contract（模板合同）

新增：

- TemplateId（模板ID）
- TemplateVersion（模板版本）
- RequiredSchemaVersion（所需协议版本）
- AllowedNodePolicy（允许节点策略）
- RequiredPinContract（必要引脚合同）
- OutputUsage（输出用途）

Validator（校验器）检查：

- 图是批准模板或模板实例。
- Schema/Template 版本兼容。
- 禁止未知 Blueprint Element（蓝图元素）。
- 禁止未经批准的资产加载。
- 禁止未知 `Pcg.*` 字段。
- 随机节点必须有显式 Seed。
- GPU 节点受 ExecPreset 控制。
- 输出用途与碰撞/Nav/Replication（导航/复制）边界一致。

### 阶段 C：删除“恰好四节点”作为生产唯一规则

只有 M0/M1 新模板完成 Editor/Client/Server 构建和自动化验证后，旧固定四节点检查才从“生产唯一规则”降为“开发夹具兼容规则”。

## 十五、环境主路径实施方案

### 15.1 森林

FieldRead → Biome → Canopy → PriorityCarve → Scatter → Understory → GroundCover。

Layer Children（层子项）必须：

- 检测循环引用。
- 设置最大递归深度，建议 8。
- 禁止 A→B→A。

### 15.2 道路

Spline → RoadProfile → Networks → PriorityCarve → InterfaceBand。

1.0 不写 Landscape，不做自动路堑。

### 15.3 农田

Polygon → Inset（内缩）→ BuildRows → CropPolicy → AssignMeshSet → OuterEnclosure → BreakSpans → Gate。

### 15.4 围合

Spline/Parcel Edge（样条/地块边）→ FitPostsToSpline → Span（跨度）→ BreakSpansByTags → Gate Connector（门连接件）。

### 15.5 手摆桥

Connector + Exclusion（连接件+排除）实现树/麦排除；1.0 不做自动桥求交。

### 15.6 资源点

复用 P1 Scatter（散布）采样链，输出低密度 GameplayAnchor（玩法锚点）和稳定 Mutable.Id（可变ID）；是否 Realize Mesh（实例化网格）由项目内容决定。

## 十六、运行时、Dedicated Server 与权威边界

继续保留当前安全规则：

- Dedicated Server（专用服务器）不执行 Runtime Cosmetic PCG。
- Listen Server（监听服务器）不执行纯装饰 PCG。
- Runtime Cosmetic 不得产生碰撞、Overlap（重叠）、Nav（导航）、Replication（复制）或玩法状态。
- RuntimeAuthoritative（运行时权威）1.0 返回 Unsupported。

影响玩法的：

- Road Collision（道路碰撞）
- Bridge（桥）
- GameplayAnchor（玩法锚点）
- Resource Anchor（资源锚点）
- Navigation Obstacle（导航障碍）
- Building Collision（建筑碰撞）

优先采用：

```text
Editor Generation
→ Bake
→ Validation
→ Save World
→ Client/Server Cook
```

## 二十三、风险与对策

### 风险 1：一次性重构导致旧 PCG 基线失效

对策：保留现有 Profile 和四节点开发夹具，按 M0→M1 渐进迁移；每阶段保留可构建回退点。

### 风险 2：WorldDirector 变成超级管理器

对策：Director 只做阶段/脏区/优先级编排；执行生命周期仍属于 WorldSubsystem。

### 风险 3：Schema 变成字符串野生协议

对策：统一 FGamePlatformPCGAttr；CI 扫描未经注册的 `Pcg.*` 字符串。

### 风险 4：项目资源污染平台层

对策：GamePlatformPCG 不引用 DivineBeasts；实际 Mesh/Graph Instance 放世界 ContentPack。

### 风险 5：HiGen 过早引入导致定位困难

对策：M0/M1 先普通 Editor Static；HiGen 只在 M2 打开。

### 风险 6：客户端 PCG 产生玩法差异

对策：Runtime Cosmetic 强制无 Collision/Overlap/Nav/Replication；玩法结果来自 Bake/权威数据。

### 风险 7：自动化推导产生不可控结果

对策：保守生成；ManualLock/Override（手工锁定/覆盖）优先；不确定时不生成。

## 二十四、版本与迁移规则

- Major（主版本）：Schema 或稳定原语合同不兼容变化。
- Minor（次版本）：新增兼容 Primitive 实现、节点、模板。
- Patch（补丁）：不改变协议语义的缺陷修复。

每个生产模板必须记录：

- TemplateId。
- TemplateVersion。
- RequiredSchemaVersion。

Bake Manifest 必须记录可复现条件。

现有 `0.1.0` 的 Profile/Graph 不得无迁移记录直接删除；每次公开字段变更要检查 PrimaryAsset（主资产）身份、DataVersion（数据版本）和现有软引用。
