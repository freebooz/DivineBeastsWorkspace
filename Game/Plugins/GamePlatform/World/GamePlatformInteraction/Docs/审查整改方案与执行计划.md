# GamePlatformInteraction（游戏平台交互插件）审查整改方案与执行计划

版本：0.2.1  
范围：`Game/Plugins/GamePlatform/World/GamePlatformInteraction`

## 一、审查目标

本次审查以真实源码和现行工程规则为准，检查三层架构边界、插件复用性、依赖方向、服务器权威、RPC（远程过程调用）幂等、并发会话、生命周期、性能、Dedicated Server（专用服务器）兼容、编码规范和中文注释。所有修改均为原插件增量整改，不建立第二套交互系统，不改动无关插件。

## 二、发现的问题与处理

1. **正式路径与文档分类不一致**：历史文档将插件描述为 GameFoundation/Gameplay，而真实正式目录位于 GamePlatform/World。已统一为 `Game/Plugins/GamePlatform/World/GamePlatformInteraction`，并将 uplugin Category（插件分类）改为 `GamePlatform/World`。
2. **公开依赖过宽**：Build.cs（模块构建规则）把实现层依赖全部放入 PublicDependency。已将 `GamePlatformGameplay（通用玩法）`和 `NetCore（网络核心）`收敛为 PrivateDependency，移除未使用的 `GamePlatformCore（平台核心）`。
3. **Begin 重试先消耗限流**：重复 RequestId（请求ID）可能被 RateLimited（限流）覆盖原结果。已改为“合法ID → 幂等缓存/活动同请求 → 限流 → 新请求验证”。
4. **Cancel 重试不幂等**：终态会话再次取消原来返回 SessionNotFound（会话不存在）。现优先回放已缓存终态。
5. **同一 Actor 多交互点不正确**：原实现使用 FindComponentByClass（查找首个组件），与 TargetInstanceId（目标实例ID）契约不一致。客户端与服务器均改为组件实例级选择/解析。
6. **Shared 并发被 Revision 误杀**：第一个共享会话成功提交会推进 Revision，导致其他已获准共享会话失效。现将 Revision 定义为 Begin 阶段乐观并发令牌；活动会话持续校验 Generation、活动占用、资格、距离和视线，真正的配置/可用性改变通过显式 CancelActiveSessions（取消活动会话）失效。
7. **失效弱引用占用并发名额**：ActiveSessions 使用 WeakObjectPtr（弱对象指针），异常销毁后可能残留。TryAcquireSession（尝试占用会话）前增加清理并重算 OccupancyCount（占用数）。
8. **Commit 幂等不完整**：原逻辑记住已提交 SessionId，但重复提交返回“已完成错误”，不能回放首次成功结果。现缓存完整 Result（结果），重复 Commit 不再执行副作用并返回首次终态。
9. **Hold 缺少上限**：新增 MaxHoldDuration（最大长按时长），同时在初始配置、Begin 服务器验证和本地候选过滤中执行。
10. **Begin/Cancel 共用一个窗口时长**：新增 CancelRequestWindowSeconds（取消请求窗口），两类请求独立统计。
11. **Provider 解析遗漏 Controller→Pawn**：Interactor 挂在 PlayerController 时现在会继续检查其受控 Pawn。
12. **Hold 校验失败重复验证**：原流程先发现失败再调用 CommitCurrentSession 重新验证。现直接映射取消原因并 CancelSession（取消会话）。
13. **计数器有长期溢出风险**：TargetGeneration/TargetRevision 改用正整数安全推进，到 int32 上限后回绕到 1。
14. **世界时间回退风险**：本地节流、服务器限流和幂等缓存 TTL（存活时间）现在能识别 WorldTime（世界时间）回退并重置窗口/过期缓存。
15. **空 Owner（拥有者）保护不足**：服务器 Authority API 与目标生命周期关键路径补充 IsValid（有效性）保护。
16. **EndPlay 仍存在代次计数溢出残留**：`AdvanceTargetGeneration（推进目标代次）`已使用安全回绕，但 `EndPlay（结束生命周期）`仍直接 `++TargetGeneration`。现统一改为 `AdvancePositiveCounter（安全正整数计数器）`，保证生命周期路径与显式代次推进一致。
17. **Custom 提交默认成功属于 Fail-Open（失败开放）**：`IGamePlatformInteractable::CommitInteraction（可交互接口提交）`原默认返回 true，目标即使没有实现任何业务副作用也会被判定为成功。现改为默认 false；自定义交互必须显式实现提交逻辑，避免“协议成功、业务未发生”的静默错误。

## 三、保留的设计边界

- 不使用 Tick（每帧轮询）；Focus（焦点）与 Hold（长按复验）使用 Timer（定时器）。
- Focus 只做一次视线射线并检查命中 Actor 上的交互组件，不进行世界 Actor 扫描。
- 客户端 FocusSnapshot（焦点快照）只用于体验提示，不是授权事实。
- 服务器始终重新验证角色资格、目标身份、代次、Begin Revision、选项、距离、视线与并发。
- Input/UI/Character/Combat/Inventory/Quest/Presentation/VFX（输入/界面/角色/战斗/背包/任务/表现/特效）继续通过组合层或各自插件接入。
- 不新增 Go API、永久奖励和持久化职责。
