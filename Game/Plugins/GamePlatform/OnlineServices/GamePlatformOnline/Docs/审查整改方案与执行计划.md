# GamePlatformOnline（游戏平台在线插件）审查整改方案与执行计划

## 1. 文档目的

本文基于 2026-09-29 对 `GamePlatformOnline（游戏平台在线插件）` 的真实源码审查，作为当前 `0.2.0` 版本后续整改、验证和验收的统一执行基线。

目标不是为《神兽联盟》单独实现一套登录代码，而是把 `GamePlatformOnline` 建设为第一层 `GamePlatform（游戏平台基础层）` 的跨游戏通用在线能力插件，并满足以下工程要求：

- 符合 `DivineBeasts → MobaCommon → GamePlatform` 三层依赖方向。
- 平台层不包含生肖、OpenWorld（开放世界）、Village（新手村）、MainArena（主竞技场）等项目语义。
- 认证状态、Token（令牌）生命周期、401 刷新、重试、超时、并发预算、安全 HTTP 传输只维护一套生产实现。
- UI（用户界面）、ApplicationFlow（应用流程）、Telemetry（遥测）、Session（会话）均不得读取或长期保存 AccessToken（访问令牌）/RefreshToken（刷新令牌）原文。
- 代码以事件驱动、有界资源、失败关闭、明确结果语义和中文注释为基本工程规则。
- Dedicated Server（专用服务器）控制面与游戏连接重连继续分别由 `GamePlatformServer（平台服务器插件）`、`GamePlatformSession（平台会话插件）` 负责。

## 2. 审查结论

当前插件的分层方向已经基本正确，旧项目层 `FDivineBeastsGatewayAuthProvider（神兽联盟网关认证提供者）` 已退出正式架构，`GamePlatformOnlineServer（在线服务器空模块）` 已删除，正式客户端正在统一到：

```text
DivineBeastsApplicationFlow（神兽联盟应用流程）
        ↓ 只注入部署配置和业务路径
IGamePlatformOnlineService（统一在线服务门面）
        ↓
UGamePlatformOnlineClientSubsystem（在线客户端子系统）
        ↓
FGamePlatformGatewayAuthProvider（平台私有网关传输）
        ↓
GatewayService（统一接入服务）
```

当前正式运行时已经避免同时运行两套认证状态机；历史 `Private/Requests/OnlineSession` 已通过 `GAMEPLATFORM_ONLINE_NATIVE_TEST（在线原生测试宏）` 编译期门禁限制为回归模型，不进入 UE（虚幻引擎）正式运行时。

但完整工程验收仍未结束，重点剩余风险集中在 UE5.8 自动化执行、Client/Editor/Server（三目标）构建、真实 HTTPS Gateway（安全网关）联调和网络异常验证。

## 3. 已发现问题及整改优先级

### 3.1 P0：必须阻断发布的问题

1. 公共 `IGamePlatformOnlineService（统一在线服务门面）` 必须始终指向真实 `GameInstance（游戏实例）` Online 子系统，禁止主工程通过门面取得空服务或第二套实现。
2. 登录并发必须保证“被拒绝的第二次 Login（登录）”无权推进认证代次、清除 Token 或取消首个合法登录；无效参数的并发登录也必须先返回 `AuthenticationBusy（认证繁忙）`。
3. 401 处理必须区分安全读取、幂等写和非幂等写：
   - GET/HEAD（安全读取）允许刷新后最多重放一次。
   - 写请求只有具备业务 `Idempotency-Key（幂等键）` 时允许刷新后重放一次。
   - 非幂等写不自动重放；请求可能已到服务端时返回 `OutcomeUnknown（结果不确定）`。
4. Token 只能保存在平台私有传输对象内，外部授权接口必须验证目标 URL 与已配置 `ServiceOrigin（服务源地址）` 同源，禁止把 Bearer Token（持有者令牌）注入任意外域请求。
5. 敏感 HTTP 请求必须拒绝自动重定向；目标 HTTP 后端不支持 `SetRedirectPolicy(Reject)（拒绝重定向策略）` 时必须失败关闭。
6. 响应正文必须在接收过程中实施 `MaxResponseBytes（最大响应字节数）` 上限，不能先完整缓存再检查。
7. 不允许遗留未启用但仍可被误接入的 `GamePlatformOnlineServer（在线服务器模块）` 或项目层旧认证 Provider。

### 3.2 P1：正式联调前必须完成的问题

1. 生产路径需要覆盖 `MaxReadRetries（最大读取重试次数）`、`RetryBaseDelaySeconds（重试基础延迟）`、`MaxRetryDelaySeconds（最大重试延迟）` 和 `Retry-After（服务端重试等待）`。
2. Login（登录）、Refresh（刷新）、Logout（退出）、受保护请求都必须有总 `Deadline（截止时间）` 和 Owner/World（拥有者/世界）生命周期取消。
3. Refresh（刷新）必须 single-flight（单次共享刷新），所有等待者共享一次轮换；轮换响应丢失或 SessionId（会话标识）/PlayerId（玩家标识）变化时进入重新认证，不允许盲重发旧 RefreshToken。
4. Profile（玩家资料）缓存只能接受相同主体和 GameId（游戏标识），Revision（修订号）只能单调前进。
5. `GamePlatformTelemetry（平台遥测插件）` 等基础插件只能使用请求授权能力，不得获得 Token 字符串。
6. 生产 UE 自动化必须覆盖公共门面、真实 GameInstance 子系统、401 重放、读取重试、幂等校验、非幂等写、退出、同源授权和实例清理。

### 3.3 P2：性能与长期维护优化

1. ReadyQueue（就绪队列）使用 HeadIndex（头索引）批量消费，避免 `RemoveAt(0)` 造成 O(n) 搬移。
2. 只在存在活动/等待请求时注册低频 `FTSTicker（核心计时器）`，空闲时保持零 Tick。
3. 并发请求、排队请求、刷新等待者、请求/响应大小都必须有硬上限，禁止无界增长。
4. 可进一步复用请求扫描临时数组，减少高频临时分配；在实测需要前不做过度优化。
5. 请求正文可在后续优化为一次 UTF-8（统一编码）序列化后直接发送，减少重复编码。
6. `FGamePlatformAuthSnapshot（客户端认证快照）` 仅作为 Blueprint/UI（蓝图/界面）投影；跨模块正式认证真源固定为 `FGamePlatformOnlineAuthSnapshot（平台在线认证快照）`，禁止再演化成第二权威状态机。

## 4. 最佳目标架构

### 4.1 GamePlatformOnline（平台在线公共核心模块）

职责：

- `IGamePlatformOnlineService（统一在线服务门面）`。
- `FGamePlatformOnlineConfiguration（在线配置）`。
- 公共 Request/Result/Profile/Authentication/Diagnostics（请求/结果/资料/认证/诊断）类型。
- GameInstance（游戏实例）服务注册与反注册。
- 不依赖 HTTP（超文本传输）、JSON（结构化数据）和项目配置。
- 不读取环境变量，不内置具体游戏地址和 `divine-beasts` 等项目身份。

### 4.2 GamePlatformOnlineClient（平台在线客户端模块）

职责：

- Client/Editor（客户端/编辑器）专用。
- `UGamePlatformOnlineClientSubsystem（在线客户端子系统）` 作为唯一正式生产状态机。
- 实现 `IGamePlatformOnlineService`。
- 管理 GameInstance 生命周期、GT（游戏线程）状态提交、请求调度、Refresh single-flight（刷新单飞）、Retry（重试）、Deadline（截止时间）、Cancel（取消）和 Blueprint/UI 投影。
- 不把 Token 原文暴露给项目层。

### 4.3 Private/Transport（私有传输层）

`FGamePlatformGatewayAuthProvider（平台网关认证提供者）` 仅负责：

- UE HTTP（虚幻 HTTP）创建与取消。
- HTTPS/开发回环地址约束。
- Redirect Reject（拒绝重定向）。
- 流式响应大小限制。
- JSON 编解码。
- Token 私有内存保存。
- Authorization（认证头）和 Idempotency-Key（幂等键）注入。
- HTTP 状态到平台稳定错误分类的映射。

它不能访问 UI、ApplicationFlow、GamePlatformSession 或项目业务状态。

## 5. 已执行整改

当前工作区已经完成以下整改：

- `GamePlatformOnline.uplugin（在线插件描述）` 收敛为 `Runtime（运行时） + ClientOnly（仅客户端）` 两模块，`CanContainContent=false（禁止内容资产）`。
- 删除 `GamePlatformOnlineServer（在线服务器空模块）` 源码和插件模块声明。
- `UGamePlatformOnlineClientSubsystem` 实现 `IGamePlatformOnlineService`，按 GameInstance 注册/反注册统一门面。
- 项目层旧 `FDivineBeastsGatewayAuthProvider` 已退出正式架构，登录配置由项目组合根显式注入平台 Online。
- Token 保存、HTTP/JSON、安全策略下沉到平台私有 Gateway Provider。
- 修复并发第二次 Login 误伤首个合法登录的问题，并增加“并发无效登录也只能返回 AuthenticationBusy”回归。
- 实现 401 single-flight、一次认证重放、非幂等写不自动重放。
- 对可能已到服务端的非幂等写网络失败返回 `OutcomeUnknown`。
- 增加 Retry-After、读取有限重试、指数退避与抖动。
- ReadyQueue 改为 HeadIndex 消费，避免频繁 `RemoveAt(0)`。
- 增加同源授权校验，外域 HTTP 请求禁止附加 Bearer Token。
- 接入 Redirect Reject 和流式响应字节上限。
- 旧 `OnlineSession` 已降级为仅 CMake/CTest（构建/测试）使用的历史回归模型，禁止 UE 正式运行时引用。
- README、Architecture、TestingAndEvidence、目录规划、历史断点和项目登录文档已按当前架构更新。

## 7. 性能设计基线

性能要求不是“尽量快”，而是“有界、事件驱动、可预测”。

- 默认最大并发网络尝试：由 `MaxConcurrentRequests（最大并发请求）` 控制。
- 排队请求：由 `MaxQueuedRequests（最大排队请求）` 控制。
- 刷新等待：由 `MaxRefreshWaiters（最大刷新等待者）` 控制。
- 响应正文：网络接收阶段即受 `MaxResponseBytes（最大响应字节数）` 控制。
- 请求正文：发送前受 `MaxRequestBytes（最大请求字节数）` 控制。
- Retry（重试）只允许安全读取，受次数、最大延迟和总 Deadline 同时限制。
- 登录和 Refresh 不自动网络重试，避免凭据轮换产生不可判定结果。
- Ticker 仅活动期存在，默认 0.1 秒低频调度，不做每帧 HTTP 查询。
- 后续优化必须以 Unreal Insights（虚幻性能分析）或可重复压测证据驱动，不为“理论性能”增加复杂结构。

## 8. 通用性与可复用性约束

以下内容禁止进入 GamePlatformOnline：

- DivineBeasts（神兽联盟）命名空间或业务类。
- 十二生肖、英雄定义、角色创建规则。
- Village/OpenWorld/MainArena 的世界规则。
- 项目固定 Gateway 地址。
- 项目固定账号体系或 UI 错误文案。
- ApplicationFlow 节点名称。
- Session/Server 的连接和控制面状态机。

允许由项目层注入：

- ServiceOrigin（服务源地址）。
- GameId（游戏标识）。
- ClientVersion（客户端版本）。
- 业务相对路径和业务 JSON 载荷。
- 对业务结果的项目级解释。

## 9. 编码与中文注释规范

- 所有公共类、接口、枚举、状态机关键分支必须有中文说明。
- 英文类名、模块名、协议名第一次出现时附中文说明。
- 禁止把多步状态迁移压缩到不可审阅的单行代码。
- 复杂认证状态变化必须解释“为什么”，而不是只复述代码动作。
- 不记录密码、AccessToken、RefreshToken、Authorization 头和原始敏感响应。
- 不在日志、诊断快照、Blueprint/UI 状态中暴露秘密。
- Build.cs（构建规则）必须声明真实直接依赖，禁止依赖传递链接侥幸编译。

## 10. 最终完成定义

只有同时满足以下条件，才能把 `GamePlatformOnline 0.2.x` 标记为工程完成：

- 公共门面与真实客户端子系统为同一 GameInstance 实例。
- 不存在第二套生产认证 Provider/Token 状态机。
- 原生回归全部通过。
- `GamePlatform.Online.*` UE 自动化全部通过。
- Editor/Client/Server 三目标构建全部成功。
- Server 目标不携带客户端 Online HTTP 实现。
- 真实 HTTPS Gateway 联调通过。
- 401/403/429/5xx、断网、超时、大响应和刷新不确定场景验证通过。
- 《神兽联盟》登录 → 角色 → 世界分配 → Session 主链路可完整运行。
- README、Architecture、TestingAndEvidence、本执行计划与实际源码一致。
