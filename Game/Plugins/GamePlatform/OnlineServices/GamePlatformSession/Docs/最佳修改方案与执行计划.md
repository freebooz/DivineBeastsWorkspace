# GamePlatformSession（游戏平台会话与跨服插件）最佳修改方案与执行计划

> 文档状态：执行中  
> 更新日期：2026-09-29  
> 适用工程：DivineBeastsWorkspace（神兽联盟工作空间）  
> 适用插件：GamePlatformSession（游戏平台会话与跨服插件）  
> 关联插件：GamePlatformOnline（平台在线认证插件）、GamePlatformServer（游戏平台服务器控制面插件）、DBAClient（神兽联盟客户端项目层插件）

## 1. 修改目标

本次修改以审查发现的问题为基线，不重建插件、不复制第二套会话框架，采用“平台公共契约稳定化 → 会话状态恢复闭环 → Backend公共入口收口 → 服务器可信准入 → 最后接真实UE Transport（传输适配器）”的顺序增量实施。

最终目标不是“能调用 ClientTravel（客户端旅行）”即可，而是保证以下链路真实、可恢复、可审计：

Online认证 → Gateway（统一接入服务）校验玩家与当前角色 → GameServerControl（游戏服务器控制服务）分配目标服务器并签发一次性TransferTicket（迁移票据） → Session（会话）建立Pending Binding（待确认连接绑定） → UE网络旅行 → Dedicated Server（专用服务器）可信Admission（准入） → NetworkConnected（网络已连接）+ AdmissionConfirmed（准入已确认）+ TargetWorldLoaded（目标世界已加载）+ ControllerReady（控制器已就绪） → Ready（可玩就绪）。

任何无法证明的中间状态必须 Fail Closed（失败关闭），禁止用固定值、客户端自报值或“假成功回调”补齐。

## 2. 架构原则

1. 三层依赖保持单向：
   - DivineBeasts（项目层） → GamePlatform（平台层）。
   - GamePlatformSession不得依赖DBAClient、生肖角色、OpenWorld/Village/MainArena项目规则。
   - MainArena等项目语义只存在于项目目录/后端业务或上层映射，不下沉到Session状态内核。

2. 客户端与服务器职责分离：
   - GamePlatformSession负责客户端会话状态、恢复语义和Transport抽象。
   - GamePlatformServer负责Dedicated Server生命周期与Admission边界。
   - 不在Session中复制Server控制面，也不新建“Session微服务”。

3. 权威事实分级：
   - NetworkConnected、AdmissionConfirmed只能由真实Transport/服务器链路报告。
   - TargetWorldLoaded、ControllerReady可由本地可信系统报告。
   - ApplicationFlow（应用流程）只能消费公开Snapshot（快照），不能直接修改私有状态机。

4. 敏感信息最小化：
   - TransferTicket不进入公开Snapshot、不写日志、不拼接URL、不长期持久化。
   - Endpoint（连接端点）必须做结构校验，禁止查询参数、控制字符和凭据注入。
   - Admission Credential（准入凭据）仅在C++安全边界短期持有，并主动清零。

5. 恢复优先于“自动重试”：
   - Cancel（取消）、Timeout（超时）、Travel后失败不能一律直接重试。
   - 结果不确定时进入 ReconciliationRequired（需要远端对账），确认远端状态后才能开启下一次操作。

## 3. 最佳目标架构

### 3.1 GamePlatformSession（客户端平台层）

公开能力：

- UGamePlatformSessionClientSubsystem（游戏平台会话客户端子系统）
- EGamePlatformSessionIntent（会话意图）：Join / Transfer / Reconnect
- EGamePlatformSessionRecoveryState（恢复状态）
- FGamePlatformSessionSnapshot（只读会话快照）
- IGamePlatformSessionTransport（真实网络传输接口）
- BeginOperation / BeginTransfer / Reconnect
- CancelTransfer / LeaveSession / NotifyDisconnected
- ResolveRemoteState（远端状态对账）
- ReportLocalFact（本地可信事实报告）

私有状态内核继续使用 FSessionConnectionState（会话连接状态内核），保持无UObject、无网络、无项目类型依赖。

### 3.2 GamePlatformServer（服务器平台层）

新增/保持唯一服务器准入边界：

- UGamePlatformServerAdmissionSubsystem（服务器准入子系统）
- IGamePlatformServerAdmissionProvider（服务器准入提供者）
- FGamePlatformServerAdmissionTarget（服务器准入目标）
- FGamePlatformServerAdmissionProof（一次性准入证明）
- FGamePlatformServerVerifiedAdmission（已验证准入投影）

该子系统只能接受C++可信握手层提交的Proof（证明），不能从URL Options（旅行参数）、客户端PlayerId或普通UniqueId直接建立权威身份。

### 3.3 Backend（业务后端）

Game Client（游戏客户端）只访问Gateway公共接口：

`POST /v1/divinebeasts/world-entry`

Gateway负责：

- Bearer Access Token（访问令牌）认证；
- 从认证上下文取得PlayerID / SessionID；
- 校验当前selectedCharacterId（已选择角色）；
- 校验expectedCharacterRevision（角色修订号）；
- 调用现有GameServerControl分配服务器并签发TransferTicket。

Game Client禁止直连：

`/internal/v1/gameservers/*`

GameServerControl内部HTTP接口统一要求内部Bearer；服务器专属操作还要求 `X-Game-Server-Id` 与实际作用服务器一致。

## 4. 分阶段执行计划

### P0-1：稳定Session公共恢复契约

状态：已实施，待最终UE构建验证。

修改内容：

- 增加显式 EGamePlatformSessionIntent，禁止根据“是否有Current”隐式猜测Reconnect。
- Snapshot增加 RecoveryState、bRecoveryRequired、bCanRetry。
- 增加 Reconnect / LeaveSession / NotifyDisconnected / ResolveRemoteState。
- 增加稳定错误码集中定义。
- 增加 RequiredFactsMask（必要事实掩码），替代状态推进魔法值。
- 非法Fact枚举明确拒绝。
- 相同OperationId活动重入幂等，不重复调用Transport。
- 保留 HighestAcceptedSessionEpoch（最高已接受会话代次），即使断线后也拒绝旧绑定回放。
- Reconnect只能在本地已断开时发起，不能覆盖Ready连接。

核心文件：

- `Source/GamePlatformSession/Public/GamePlatformSessionClientSubsystem.h`
- `Source/GamePlatformSession/Public/Types/GamePlatformSessionErrors.h`
- `Source/GamePlatformSession/Private/GamePlatformSessionClientSubsystem.cpp`
- `Source/GamePlatformSession/Private/State/SessionConnectionState.h/.cpp`

验收标准：

- Join/Transfer/Reconnect状态前置条件明确；
- 同Operation幂等；
- 旧Operation、旧AuthGeneration、旧SessionEpoch不能污染新会话；
- Snapshot不包含TransferTicket和Endpoint；
- 项目层无需读取私有状态。

### P0-2：统一失败、取消、超时和恢复语义

状态：已实施，纯C++状态测试已通过。

修改内容：

- Timeout时主动通知Transport取消未完成动作。
- Travel（旅行）前超时：TimedOut，但仍要求远端对账，防止丢失的分配响应形成幽灵预留。
- Travel后超时/失败/取消：Uncertain（结果不确定）+ ReconciliationRequired。
- ResolveRemoteState完成后：
  - 保留且确认原Current时恢复Ready，Recovery=None；
  - 确认无远端绑定时进入可重试Idle。
- Logout（退出认证）在Ready状态先调用Transport LeaveSession，防止账号已退出但网络仍停留旧服务器。
- Transport替换时取消旧活动操作，旧回调通过Operation栅栏丢弃。

回归测试：

- SessionStateTests.cpp
- GamePlatformSessionContractTests.cpp
- GamePlatformSessionSubsystemTests.cpp

全部纳入内部Bearer认证；其中assignment / validate-transfer / match-result按服务器身份增加 `X-Game-Server-Id` 校验。

### P0-4：服务器Admission可信边界

状态：边界代码已建立，真实Provider尚未接线。

已完成：

- Admission目标绑定GameServerId / ServerBootId / WorldId / ExperienceId / ProtocolVersion。
- Admission Proof不进入反射系统，Credential析构主动清零。
- 同Controller同一时刻最多一个准入操作。
- Provider缺失时Fail Closed。
- 迟到回调使用Operation Generation（操作代次）隔离。
- 验证结果必须匹配当前Boot、World、Experience、Protocol和ConnectionGeneration。

待完成：

- 实现唯一生产 IGamePlatformServerAdmissionProvider。
- 将真实NetConnection / PlayerController与一次性TransferTicket验证结果绑定。
- 玩家离开时释放远端Admission。
- Drain（排空）后拒绝新准入。

### P0-5：补齐可信Binding协议，再实现默认UE Transport

状态：阻塞，禁止提前伪实现。

当前现有Backend Transfer验证结果只包含：

- PlayerID
- SessionID
- AssignmentID
- DestinationWorldID
- DestinationExperienceID
- MatchID

但Session完整Binding还需要：

- GameSessionId（游戏会话身份）
- ServerBootId（服务器启动代次）
- ProtocolVersion（网络协议版本）
- SessionEpoch（会话单调代次）

因此当前不能安全实现默认ClientTravel Transport。

最佳实施顺序：

1. GameServer注册时生成/注入稳定 ServerBootId。
2. GameServerControl Registry保存BootId与ProtocolVersion。
3. Transfer签发绑定目标BootId。
4. Dedicated Server验证TransferTicket后，由控制面/服务器生成单调SessionEpoch。
5. Admission Provider返回完整VerifiedAdmission。
6. 客户端从可信服务器握手获得完整Binding。
7. Session Transport调用OnBindingPrepared。
8. 在真正执行ClientTravel前调用OnTravelCommitted。
9. NetworkFailure / TravelFailure按OperationId和Binding精确回收。
10. AdmissionConfirmed只能来自服务器确认，不由ApplicationFlow自报。

### P1：恢复与重连完善

在P0真实网络闭环完成后实施：

- ReconnectTicket（重连票据）与普通TransferTicket分离或增加明确Intent绑定。
- Reconnect必须绑定上一会话SessionEpoch或服务器确认的Resume身份。
- 网络瞬断采用有限指数退避，不允许无限重连。
- 后台切前台、网络切换、服务器重启、旧Boot重连全部加入故障注入测试。
- Reconcile（对账）增加Backend查询接口，禁止客户端仅凭本地Snapshot解除恢复屏障。

### P1：Telemetry与诊断

- 所有日志统一记录 OperationId、AssignmentId、GameServerId、SessionEpoch、状态和错误码。
- 禁止记录TransferTicket、AccessToken、RefreshToken、Admission Credential。
- Telemetry只消费公开脱敏事件，不反向成为Session依赖。
- 增加阶段耗时：Assignment、Travel、NetworkConnected、Admission、WorldLoaded、ControllerReady。
- 增加失败原因维度：Timeout、TravelFailure、NetworkFailure、AdmissionRejected、StaleEpoch、ReconciliationRequired。

### P2：工程化和性能收敛

- 在真实E2E通过后评估0.1秒Deadline Ticker是否改为单次Timer；在此之前不做低收益重构。
- 检查PIE多GameInstance隔离。
- 验证Client Target不带服务器实现、Server Target不带Session客户端模块。
- Dedicated Server最小Cook和插件依赖审计。
- 增加长时间断线/重连Soak Test（稳定性浸泡测试）。
- 补真实OpenWorld → Village → OpenWorld、OpenWorld → MainArena → OpenWorld往返测试。

## 7. 回退原则

1. 不回滚其它插件已有未提交修改。
2. Session公共类型一旦被DBAClient使用，修改签名前先检查调用方。
3. Backend新增Gateway接口可独立关闭worldEntry端口；端口未装配时返回ServiceUnavailable，不旁路内部服务。
4. Admission Provider缺失时保持拒绝准入，不提供开发环境“默认放行”。
5. 新增协议字段采用向后兼容扩展并更新Shared真源，再通过contractcodegen生成；禁止手改生成文件。
