# 《神兽联盟》GAS统一增减伤与限时护盾效果实施规范 V3.0

> 更新：2026-10-09。固定工作空间：DivineBeastsWorkspace（神兽联盟工作空间），UE5.8（虚幻引擎5.8），正式工程 Game/DivineBeastsArena.uproject（神兽联盟主工程）。
> 本文取代2026-10-09先前24→18→17→13属性过渡设计。**最终唯一生效的GAS数值基线为2个具体属性集、8个字段。**
> 状态：C++源码及静态架构审计已修改；真实UHT/Client/Server构建、资产兼容、双客户端联机和网络节省效果不得仅凭本文宣称完成。

## 1. 唯一字段清单

| 模块与具体类型 | 字段及中文职责 | 复制范围 |
| --- | --- | --- |
| GamePlatformCombat（平台战斗）/ UGamePlatformCombatAttributeSet（统一战斗属性集） | Health（当前生命）、MaxHealth（生命上限） | COND_None（随Actor网络相关性传给相关客户端；迷雾权限另行核实） |
| 同上 | DamageBonus（伤害增强/削弱，允许有符号Buff/Debuff）、DamageReduction（伤害减免/易伤，允许有符号Buff/Debuff） | COND_OwnerOnly（仅角色拥有者），服务器永久唯一真源 |
| 同上 | IncomingDamage（瞬时待结算伤害）、IncomingHealing（瞬时待结算治疗） | 不复制、不持久化，服务器处理后清零 |
| DivineBeasts/DBAGameplay/DivineBeastsCharactersRuntime（项目角色运行）/ UDivineBeastsMomentumAttributeSet（项目气势属性集） | Momentum（当前气势）、MaxMomentum（气势上限） | COND_OwnerOnly（仅角色拥有者） |

汇总：2组具体AttributeSet（属性集），8字段；2字段对网络相关观察者可复制、4字段仅拥有者可复制、2个Meta（结算元字段）完全不复制。GamePlatformAbilitySystem（平台GAS插件）只拥有中立属性集基类和唯一ASC（Ability System Component，能力系统组件），没有具体数值。**不存在盾容量的GAS属性。**

已取消且不可恢复：Shield/MaxShield（护盾及上限）、AttackPower/AbilityPower（攻击力/技能强度）、Armor/MagicResistance/Resistance（物理护甲/法术抗性/统一抗性）、ArmorPenetration/MagicPenetration/Penetration（穿透系列）、CriticalChance/CriticalDamage（暴击）、AttackSpeed（攻速）、Tenacity/Poise系列（韧性/失衡）以及未投入运行的MomentumGainMultiplier/MomentumDecayRate（气势倍率/衰减）。

## 2. 统一服务器结算次序

1. 技能由DBAGameplay（神兽联盟项目玩法插件）提供经过身份、技能授权、命中与金额/量级校验的BaseDamage（基础伤害）。
2. 来源ASC与目标ASC分别从同一 `UGamePlatformCombatAttributeSet`（统一战斗属性集）读取GameplayEffect（玩法效果）聚合后的DamageBonus（有符号增强伤害）与DamageReduction（有符号减免伤害），包含装备加成、增益Buff、削弱Debuff等修饰器，而不是为每一种效果增加永久GAS属性。
3. 通用普通伤害统一加减：`FinalDamage = max(0, max(0, BaseDamage + DamageBonus) - DamageReduction)`（最终伤害等于基础值加增伤，再减去目标减伤）。正DamageBonus表示来源增伤，负DamageBonus表示来源削弱；正DamageReduction表示目标减伤，负DamageReduction表示目标易伤。若用户希望百分比修正，必须提出独立规则变更，不在公式中隐式加入乘积。
4. Physical（物理）、Magic（法术）、Untyped（无类型）已发布枚举保留历史身份，均使用完全相同的加减规则。TrueDamage（真实伤害）按现有业务含义仍接受来源DamageBonus但忽略普通DamageReduction；是否绕过护盾取决于已有Combat.Damage.BypassShield（服务器授权绕盾标签），不由伤害类型猜测。
5. 限时盾GameplayEffect（限时护盾效果）在伤害加减后优先消耗独立的剩余吸收容量。剩余部分扣减Health（生命）。IncomingDamage（瞬时伤害元属性）与CombatComponent（战斗组件）负责权威结算、事件幂等、死亡处理。Healing（治疗）走既有独立元属性并限制在MaxHealth内，不增加盾容量或生命上限之外的虚假状态。
6. 效果到期、驱散、盾容量耗尽、死亡、角色重生、World（世界）退出时，效果失效；不能把同一个Buff/Debuff/盾重复算进第二套私有伤害框架。

**数值示例：** 技能基础100，攻击者Buff增加20，目标减免Buff增加15，则加减后应受105伤害；若目标仍有来自限时盾GE的50点吸收量，实际扣55生命，盾GE耗尽后移除。若目标被Debuff削弱减免15，则按负DamageReduction参与同一公式计算。

## 3. 临时护盾：GE效果实例，不是属性

- `UGamePlatformShieldGameplayEffect`（通用有限时护盾玩法效果）只赋予 `Combat.State.Shielded`（被盾保护）GameplayTag（状态标签），自身拥有GAS持续时间和驱散/失效生命周期。
- `UGamePlatformCombatComponent::ApplyShield`（权威施加盾效果）验证技能来源、目标、AvatarGeneration（角色代次）、效果容量与时长上限，创建对应独立ActiveGameplayEffectHandle（活动效果句柄）；实际剩余吸收量仅存在于**服务器同一战斗组件所拥有的有界临时效果账本**，不作为GAS长期属性，也不为每次受击复制盾容量数值。
- 临时效果账本与GE句柄一一关联，失效GE不再参与吸收；同时最多16个盾效果，按应用顺序消耗。盾耗尽移除该GE；角色死亡、重生或卸载时清理属于本组件的所有盾效果，不触动装备等外部提供的其他GE。为避免永久扫描开销，只在施盾、伤害和生命周期事件上进行检查，禁用Tick（逐帧轮询）。
- 服务器真正读取效果账本，在伤害结算中计算本次AppliedToShield（单次盾吸收量）与RemainingShield（本次结算后的剩余盾）；这些仅是CombatResult（战斗结果）与可选网络表现事实字段，**不是另一份永久可写的玩家属性**。
- 客户端通过GAS GameplayTag与合法授权的状态效果UI（Buff托盘）表现“护盾存在”，一次性受击表现可以依据权威AppliedToShield（本次吸收量）；不显示无法可靠同步的剩余盾百分比。现有Widget Blueprint（控件蓝图）旧ShieldBar（盾资源条）由项目UI C++强制隐藏，正式删改蓝图控件树必须通过Monolith MCP，不能伪造uasset。
- 当前仅 `ApplyShield`（权威施盾入口）同时授予临时吸收容量与效果句柄。外部模块不能只施加同名标签便自行获得盾容量；GE未按正确入口授予时，标签本身不产生伤害抵扣。
- 注意：仅依赖客户端Buff/Tag显示不等于迷雾保密；目标身份、允许观察的技能效果、引擎网络相关性、Mixed（混合效果复制）仍必须通过Dedicated Server（专用服务器）多客户端核验。

## 4. 三层归属

```text
DivineBeasts（第三层：神兽联盟项目）
  DBAGameplay/DivineBeastsCharactersRuntime（项目角色运行）
    UDivineBeastsMomentumAttributeSet（气势与气势上限）
  DBAGameplay/DivineBeastsAbilitiesRuntime（项目技能运行）
    AbilityBalanceRow（技能等级基础伤害/冷却/气势消耗；不定义重复攻击防御）
  DBAClient/DivineBeastsUIClient（项目客户端只读视图）
    生命/气势状态栏；限时盾/Buff/Debuff归状态效果托盘，不复制盾数值
          ↓
MobaCommon（第二层：MOBA通用）
  GamePlatformArena（竞技模式、队伍与复活规则）/MobaPresentation（通用表现）
    不拥有第二套伤害公式或新的AttributeSet
          ↓
GamePlatform（第一层：游戏平台）
  GamePlatformAbilitySystem（ASC、GameplayEffect、AbilitySet、无数值的通用属性父类）
  GamePlatformCombat（唯一统一战斗属性集＋伤害/治疗执行＋盾GE与临时效果账本）
  GamePlatformUI（不携带具体生肖玩法的通用UI基础组件）
```

依赖保持单向，下层不得公开引用上层生肖类型。Buff与Debuff通用实现用正式GE Modifier（效果修饰器）修改DamageBonus、DamageReduction，项目层提供策划批准的实际玩法效果资产，不新增独立Buff数值插件。

## 5. 修改范围与资产兼容风险

- 保留稳定的 `UGamePlatformCombatAttributeSet`（平台战斗属性集），从中删除Shield/MaxShield，并新增DamageBonus/DamageReduction；旧GamePlatformOffenseAttributeSet（攻击集）与GamePlatformDefenseAttributeSet（防御集）两套UClass（反射类型）及对应源码已删除。
- `FGamePlatformCombatSpec`（战斗请求规格）和 `FDivineBeastsAbilityBalanceRow`（生肖技能表行）不再包含AttackPowerCoefficient/AbilityPowerCoefficient（攻击/技能系数）；伤害/治疗与护盾生命结算统一进GamePlatformCombat。
- `IGamePlatformCombatStateProvider`（平台战斗只读接口）不再公开盾数字/最大盾；`FDivineBeastsPlayerStatusViewData`（玩家状态UI数据）只保留生命/气势。历史WBP盾资源条只在C++隐藏，尚未由Monolith改造正式蓝图资源。
- `FGamePlatformCombatFeedbackNetEvent`（平台战斗网络视觉事实）保留每次Hit（命中）AppliedToShield（盾吸收量）供表现层，删除已停用的暴击标志。与其相关的资产序列化/网络兼容和真实联机同步需要单独验证。
- 历史暴击/攻击系数GameplayTag（玩法标签）仅作为已发布字符串身份保留，不会参与当前结算。相关数据表/UClass/UStruct字段移除属于真实资产迁移风险；需使用UE AssetRegistry（资产注册表）检查现有蓝图、DataTable（数据表）/GameplayEffect（玩法效果）的属性引用，不以二进制字符串搜索证明全部资源安全。
- `Tests/Architecture/ValidateCompactGASAttributes.py`（精简属性架构审计）及`Tests/Architecture/ValidateZodiacAbilityIntegration.py`（生肖技能三层审计）检查源码合同，绝不等同UE编译、PIE（编辑器内运行）、Client/Server Cook或5v5带宽验收。

## 6. 必须取得的运行验收

1. UE5.8 `DivineBeastsArenaEditor`（编辑器目标）、`DivineBeastsArenaClient`（客户端目标）、`DivineBeastsArenaServer`（服务器目标）至少完成涉及Gameplay/Combat/UI/MobaPresentation的真实编译链接；引擎UHT（反射工具）必须识别已删除的旧UClass/字段。
2. 原生Automation（自动化）核验正负Buff/Debuff叠加、物理/法术同公式、真实伤害、NaN/Inf、治疗、两个来源盾先后消耗、耗尽/超时/驱散与角色重生清理，并审核16个盾实例上限。
3. 两客户端加独立Dedicated Server按1v1/5v5测试，验证生命与气势复制、非拥有者内部增减伤保密、有限时盾标签同步与受击表现；用NetTrace（网络追踪）记录真实字节数与CPU开销，不能直接把属性8项说成固定节省带宽百分比。
4. 现有历史蓝图、技能数据表、正式GameplayEffect资源要经过编辑器AssetRegistry与Cook验证，再决定是否实施资产批量升级；未经此项验收不可发布Production Ready（生产就绪）。
