# GamePlatformInventory（游戏平台背包插件）审查整改执行计划

版本：1.0｜日期：2026-09-29

## 目标

在不重建插件、不增加无职责 UE 服务端模块的前提下，把现有“背包客户端骨架”补齐为可验证的客户端请求链和 PlayerData 长期数据链。依赖方向保持 DivineBeasts（项目层）→ MobaCommon（MOBA通用层）→ GamePlatform（平台层）。

## P0：本轮执行

1. UE Client（客户端）复用 GamePlatformOnline（平台在线）的受保护请求通道，不再复制长期 AccessToken；认证刷新、超时、取消和同源限制统一由 Online 负责。
2. 修复 Snapshot（快照）与 Mutation（修改）竞态：同一账号只允许一个快照请求；普通刷新不能覆盖未决 Mutation；RevisionConflict（修订冲突）使用专门对账标记。
3. Revision（修订号）在公网 JSON 协议中使用十进制字符串，避免 JSON Number 超过 2^53 后的精度损失。
4. 错误处理改为稳定 errorCode（错误码）映射，禁止依赖响应正文自然语言关键字。
5. PlayerDataService（玩家数据服务）新增 Inventory（背包）领域、内存仓储、PostgreSQL 事务仓储、000008 迁移、OperationId 持久幂等与 Operation 查询。
6. Gateway（网关）新增本人背包查询、Move/Split/Merge/Quickbar 接口；PlayerID 只来自已认证 Session。
7. 更新自动化测试、Shared OpenAPI 契约与插件文档。

## P1：本轮同时完成的低风险项

- 公开 LastError（最后错误）只读查询。
- 快照校验重复 ItemInstanceId、重复 Container/Slot、Quickbar 重复槽和悬空引用。
- Build.cs 收敛 HTTP/JSON 实现依赖。
- 补齐公开类型、接口和状态机中文注释。
- Definition（物品显示定义）继续只承担显示语义；项目资源通过 Asset Manager（资产管理器）/SoftObjectPtr（软对象指针）在项目层解析。

## 明确不做

- 不创建 GamePlatformInventoryServer（背包 UE 服务端模块）。
- 不把 Economy（经济钱包）、Equipment（装备）、Entitlement（权益）并入背包。
- 不使用 FastArraySerializer（快速数组复制）同步长期背包。
- 不手工修改正式生成代码；缺少 go/protoc/oapi-codegen 工具链时，正式生成状态必须标记为未执行。

## 验收

- 客户端登录后自动初始化背包，退出/换号清空旧缓存。
- 401 刷新不要求背包重新持有 Token；写操作保持原 OperationId。
- RevisionConflict 后全量对账；结果未知只能查询原 OperationId，不自动生成新键。
- PostgreSQL 单事务保证物品/修订/Operation 结果原子提交。
- Shared 契约、源码、README 和详细文档的“已实现/未验证”状态一致。

## 本轮执行状态

已完成：

- UE Inventory Transport 已切换为复用 GamePlatformOnlineClient 的受保护请求通道，不再持有 AccessToken。
- Inventory Subsystem 已自动跟随 Online 登录/刷新/退出状态，并增加 AccountGeneration、SnapshotRequestGeneration、单飞快照和 RevisionConflict 专用对账状态。
- 公网 Revision 已切换为十进制字符串；UE/Go 内部仍保持 int64。
- Gateway/UE 错误处理已按稳定 errorCode 映射，删除自然语言关键字判断。
- Backend Inventory Domain、MemoryRepository、PostgreSQL Repository、000008 Migration、OperationId 持久幂等和 Operation 查询已实现。
- Gateway→PlayerData HTTP 背包链已实现；公网 API 仅使用认证 Session.PlayerID。
- Shared `inventory.openapi.yaml`、PlayerData Proto 协议源、UE/Go 测试源码、目录规划与插件文档已更新。
- Definition 已使用稳定 ItemDefinitionId 形成 PrimaryAssetId；真实神兽联盟显示资产仍由项目层 Asset Manager/SoftObjectPtr 映射。
- 项目背包页面已公开 LastError 给 Blueprint 查询。
- 默认 Online Gateway Transport 已从 `Public/Transport` 收回 `Private/Transport`，公共模块只暴露 `IGamePlatformInventoryClientTransport` 稳定接口，避免具体 Online 适配器成为外部编译契约。
- Backend/OpenAPI 的 `maxStackSize` 权威实例字段已与 UE ItemInstance/ViewModel/JSON 解析对齐，避免客户端丢失服务端堆叠边界。

当前验证/能力缺口：

- Runner 缺少 `go/gofmt/gopls/protoc/protoc-gen-go/protoc-gen-go-grpc/oapi-codegen`，因此 Go Test、Go 编译、Proto/OpenAPI Codegen 和 Generated 新鲜度未执行。
- 当前主机存在其他会话运行中的 UnrealBuildTool，背包模块增量 UBT 构建被全局互斥阻止；该状态不代表源码编译失败。
- `ValidateDesignBaseline.ps1` 中继承边界通过，但全局基线仍有 12 个生肖内容包缺真实资产以及 DBAWorlds 插件声明缺口；这些问题与本次 Inventory 修改无关，本任务不越界修复。
- 生产 gRPC 模式已更新 PlayerData Inventory Proto 协议源并装配 PostgreSQL Repository，但 grpcclient/grpcadapter 生成绑定尚未 Codegen，故 gRPC Inventory 链尚未验收。
- 可信 Dedicated Server 的 Grant/Consume、Quest Reward、External Pickup 尚未实现；在 GameServerControl/Session 的服务器实例—玩家归属校验接通前，不新增不安全的半成品授予接口。
