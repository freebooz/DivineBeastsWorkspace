# GamePlatformSFX 审查整改方案与执行计划

日期：2026-09-29

## 一、审查结论

审查前插件为严重不完整状态：uplugin和ClientOnly模块身份存在，但源码只有模块入口，缺少Definition、服务、播放实现、异步加载、实例句柄、生命周期、Presentation Provider、自动化测试和工程验证。

旧规格的方向“复用UE Audio/MetaSound，不重造Mixer”正确，但 `SFX Catalog/Resolver` 与已成熟的 `GamePlatformPresentation Catalog`、`GamePlatformData Definition` 发生职责重复，本轮予以取消。

## 二、问题分级

P0：插件没有可用运行时能力，无法承接Presentation SFX请求。

P0：没有Definition/软引用/异步资源加载，未来若直接PlaySound极易导致Gameplay硬资源耦合和同步加载。

P0：没有World/Owner生命周期和实例Handle，循环/附着声音无法可靠停止。

P1：没有SoundConcurrency/Attenuation统一接入，高频5v5场景存在音效风暴风险。

P1：没有参数白名单，MetaSound参数扩展缺少稳定合同。

P1：没有自动化/静态架构门禁和真实验证证据。

P2：Music/Dialogue/Voice等边界未完全冻结，容易未来把所有音频职责堆进SFX。

## 三、最佳修改方案

1. 保留唯一 `GamePlatformSFXClient — ClientOnly`，不建立空Runtime/Server/Editor模块。
2. Definition继承 `UGamePlatformDefinitionBase`，统一逻辑身份和版本。
3. 取消SFX专属Semantic Catalog；Presentation负责语义，Data负责Definition身份。
4. Service只接收逻辑DefinitionId，不接收资产路径。
5. 使用GamePlatformData World Lease + `SFXRuntime` Bundle异步持有Sound/Attenuation/Concurrency。
6. 使用UE原生AudioComponent、SoundConcurrency、Attenuation；SoundBase天然兼容SoundWave/SoundCue/MetaSound Source。
7. WorldSubsystem无Tick，通过Data完成回调和AudioFinished事件驱动。
8. Handle使用Id/Generation/Weak World；Attached使用Weak SceneComponent。
9. MetaSound/SoundCue仅开放Definition白名单浮点参数。
10. Presentation Bridge注册ProviderChannel=SFX，Prediction Cancelled按RequestId取消。

## 六、2026-09-29 深度复审后的问题清单

### P0

当前未发现必须立即推翻插件架构的 P0 问题。现有 `ClientOnly + Presentation语义真源 + GamePlatformData Definition真源 + SFX执行器` 主线可以继续保留。

### P1-01：自动播放早于结束事件绑定，极短音效存在资源回收窗口

位置：`GamePlatformSFXWorldSubsystem.cpp` 的 `HandleDefinitionLoaded`。

当前使用 `SpawnSound2D / SpawnSoundAtLocation / SpawnSoundAttached` 创建组件，这些接口会直接开始播放；随后代码才把实例加入 `ActiveInstances` 并绑定 `OnAudioFinishedNative`。极短声音、起播时间接近资源尾部或异常声音资产可能在绑定完成前结束。由于当前显式传入 `bAutoDestroy=false`，如果错过结束事件，平台侧组件与 Definition Lease 可能一直保留到 World 清理。

整改：统一改为“先创建但不播放的 AudioComponent → 完成属性/附着/参数配置 → 先登记实例并绑定结束事件 → 最后 Play/FadeIn”。优先复用 UE 原生 `CreateSound2D` 或受控 `UAudioComponent` 创建流程，不自建音频线程和对象池。

### P1-02：平台追踪上限不是总量上限

位置：`Play` 中的容量判断。

当前分别判断 `PendingPlays.Num() >= 128` 和 `ActiveInstances.Num() >= 256`，因此 Pending 与 Active 可以同时增长，总追踪量理论上可超过文档声称的 256。高密度 5v5 场景或调用异常时，会放大内存、租约和组件压力。

整改：增加统一 `MaxTrackedSFXRequests`，使用 `PendingPlays.Num() + ActiveInstances.Num()` 做总量门禁；Pending 上限继续作为子上限。容量拒绝新增明确的 `CapacityExceeded/BudgetExceeded（容量/预算超限）` 结果码，不再复用 `UnsupportedEnvironment（环境不支持）`。

### P1-03：缺少真实音频运行和高密度性能证据

当前静态门禁只能证明代码结构，不证明 5v5 技能密集情况下的 Voice 数、Audio Render CPU、Game Thread Spawn 开销、内存、虚拟化与抢占策略合理。

整改：建立 SFX Review Map（音效评审地图）和自动压力场景，覆盖 2D/World/Attached、短音效、循环音效、大量并发、预测取消和切图；通过 Audio Insights / Unreal Insights 记录目标平台数据后再确定 Voice、实例和并发预算。

### P2-01：参数集合没有数量安全上限

`Request.FloatParameters`、`AllowedFloatParameters`、`DefaultFloatParameters` 当前只校验名称和值，不限制条目数。它们虽然不是网络权威输入，但通用插件仍应防止错误内容或错误调用造成无界参数遍历和拷贝。

整改：在 Policy/Definition 中增加共享常量，例如 `MaxFloatParametersPerRequest`、`MaxDeclaredFloatParameters`，Runtime 与 Editor Validation 共用同一常量。

### P2-02：异步 Play 只有“已受理”结果，没有最终播放结果合同

`Play` 返回 `Queued` 只说明 Definition Lease 已被受理。后续 LoadFailed、DefinitionInvalid、AssetUnavailable、OwnerInvalid、SpawnFailed 只进入日志/Diagnostics，调用方无法通过稳定事件得到一次请求的最终状态。

整改：保持默认低成本接口不变，在兼容层新增可选 Completion Delegate（完成委托）或 Request State 查询合同；Presentation 普通路径可以忽略，调试、测试、关键本地反馈可订阅。禁止为了结果通知引入 Tick 轮询。

### P2-03：多 LocalPlayer / 分屏的 2D SFX 语义未冻结

Presentation Bridge 是 `ULocalPlayerSubsystem`，SFX 执行器是 `UWorldSubsystem`。在多 LocalPlayer 场景，同一世界中的 2D UI 音效可能被多个 LocalPlayer Provider 重复提交，而当前 SFX Request 没有 LocalPlayer/Audience 作用域。

整改：在正式支持分屏前明确契约：WorldShared（世界共享）与 LocalPlayer（本地玩家）声音如何去重/路由。若项目一期不支持本地分屏，文档和测试明确限制，不让未定义行为进入通用承诺。

### P2-04：Build.cs 公开依赖可以继续收敛

`GamePlatformPresentationCore` 当前放在 `PublicDependencyModuleNames`，但公开 SFX 类型/Definition/Service 并不暴露 Presentation 类型；Presentation 只用于 Private Bridge。

整改：实施阶段验证后将 PresentationCore 与 PresentationClient 统一收敛到 Private 依赖，减少下游模块的传递编译耦合。只有 Public 头真实引用的模块保留 Public Dependency。

### P2-05：Definition 内容质量缺少 Editor 级强门禁

当前 `ValidateDefinition()` 能校验 Sound、数值范围和参数白名单，但不会阻止高频 World/Attached 音效遗漏 Concurrency、空间音效遗漏合理 Attenuation 等内容质量问题。

整改：不在 Runtime 强制所有音效必须有 Attenuation/Concurrency，而是在 Editor/DataValidation 增加可配置规则：战斗高频音效必须声明并发策略，空间化音效应有明确衰减策略；允许 UI/特殊设计通过显式豁免字段或内容分类例外。

### P3

- Diagnostics 目前偏基础，可增加 CapacityRejected、CancelledPending、FinishedNaturally、LoadLatency 等低频指标；
- `ReleaseDefinition` 失败目前静默忽略，建议开发构建输出限频 Warning；
- `SetVolumeMultiplier` 应在 API 文档明确它是“运行时组件最终倍率覆盖”还是“相对 Definition/Request 的二次倍率”，避免调用方误解。

## 七、最新推荐架构

```text
Gameplay / Application Fact
        ↓
GamePlatformPresentation
中立语义 + Context + Provider 选择
        ↓
ProviderChannel = SFX
DefinitionId = 规范逻辑 ID
        ↓
GamePlatformSFX Presentation Bridge
        ↓
IGamePlatformSFXService
        ↓
UGamePlatformSFXWorldSubsystem
请求去重 / 预算门禁 / 生命周期
        ↓
GamePlatformData World Lease
        ↓
UGamePlatformSFXDefinition
Soft Sound / Attenuation / Concurrency
        ↓
受控 AudioComponent 创建
先绑定生命周期 → 再开始播放
        ↓
UE Audio Mixer / SoundConcurrency / Attenuation / MetaSound
```

架构原则保持：Presentation 负责“播什么语义”，Data 负责“Definition 是什么并如何加载”，SFX 负责“如何安全、高效地播放”；项目层只提供 Definition 实例和语义映射，不创建 DivineBeasts 专属 SFX C++ 执行器。

## 八、最佳整改执行计划

### Phase 0：冻结基线与调用方

1. 记录当前 uplugin、Build.cs、Public API 与全工程消费者；
2. 保留现有 Public 类型名字，避免无意义破坏；
3. 把现有静态架构门禁作为回归基线。

### Phase 1：先修 P1 生命周期与预算

1. 重构 AudioComponent 创建顺序，确保先绑定 `OnAudioFinishedNative` 后播放；
2. 增加总追踪上限和明确容量错误码；
3. 为极短音效、StartTime 接近尾部、循环音、Stop/FadeOut 增加自动化/功能测试；
4. 确认所有失败路径均释放 Lease、RequestId 映射和组件。

### Phase 2：健壮性与接口补强

1. 增加请求/Definition 参数数量上限；
2. 增加可选异步 Completion/状态查询，不改变普通 Presentation 调用成本；
3. 明确 SetVolumeMultiplier 语义；
4. ReleaseLease 失败在 Development/Test 构建可诊断；
5. 补齐非法 PlaybackSpace、无效 Owner、晚到回调、重复取消等测试。

### Phase 3：模块与三层依赖收敛

1. 复核 Public/Private Build.cs 依赖；
2. 在不影响 Public 头的前提下把 Presentation 依赖降为 Private；
3. 验证 ClientOnly 与 Server Target/Cook 隔离；
4. 保持 GamePlatformSFX 不依赖 Settings、UI、Combat、MobaCommon、DivineBeasts。

### Phase 4：Editor 内容门禁

1. 增加 SFX Definition DataValidation；
2. 校验高频战斗音效 Concurrency；
3. 校验 3D 音效衰减策略；
4. 校验参数数量、默认参数白名单、逻辑 ID 与 Soft Reference；
5. 不为形式创建无职责 Editor 模块；若现有 GamePlatformData Editor Validation 可扩展，则优先复用。

### Phase 5：真实运行与性能验证

1. 构建 Editor/Client；
2. 运行 `GamePlatform.SFX.*` Automation；
3. 建立 Review Map；
4. 验证 SoundWave/SoundCue/MetaSound、2D/World/Attached、切图、Owner 销毁；
5. 进行 5v5 高密度音效压力测试；
6. 使用 Audio Insights / Unreal Insights 形成 Voice/CPU/内存数据；
7. 只有有数据后才调整 128/256 等预算，不凭经验拍数值。

### Phase 6：文档与交付

1. 更新 Architecture/API/Performance/Testing/ManualReview；
2. 输出组件清单和项目层接入示例；
3. 明确已实现、已编译、已测试、真实运行验证四种状态；
4. 未验证项继续保留，不写成 Production Ready。
