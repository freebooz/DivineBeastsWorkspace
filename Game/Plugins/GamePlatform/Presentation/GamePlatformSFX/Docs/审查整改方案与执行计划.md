# GamePlatformSFX 审查整改方案与执行计划

日期：2026-09-29

## 一、审查结论

审查前插件为严重不完整状态：uplugin和ClientOnly模块身份存在，但源码只有模块入口，缺少Definition、服务、播放实现、异步加载、实例句柄、生命周期、Presentation Provider、自动化测试和工程验证。

旧规格的方向“复用UE Audio/MetaSound，不重造Mixer”正确，但 `SFX Catalog/Resolver` 与已成熟的 `GamePlatformPresentation Catalog`、`GamePlatformData Definition` 发生职责重复，本轮予以取消。

## 二、问题分级

P0：插件没有可用运行时能力，无法承接Presentation SFX请求。

P0：没有Definition/软引用/异步资源加载，未来若直接PlaySound极易导致Gameplay硬资源耦合和同步加载。

P0：没有World/Owner生命周期和实例Handle，循环/附着声音无法可靠停止。

P1：没有SoundConcurrency/Attenuation统一接入，高频5v5场景存在音效风暴风险。

P1：没有参数白名单，MetaSound参数扩展缺少稳定合同。

P1：没有自动化/静态架构门禁和真实验证证据。

P2：Music/Dialogue/Voice等边界未完全冻结，容易未来把所有音频职责堆进SFX。

## 三、最佳修改方案

1. 保留唯一 `GamePlatformSFXClient — ClientOnly`，不建立空Runtime/Server/Editor模块。
2. Definition继承 `UGamePlatformDefinitionBase`，统一逻辑身份和版本。
3. 取消SFX专属Semantic Catalog；Presentation负责语义，Data负责Definition身份。
4. Service只接收逻辑DefinitionId，不接收资产路径。
5. 使用GamePlatformData World Lease + `SFXRuntime` Bundle异步持有Sound/Attenuation/Concurrency。
6. 使用UE原生AudioComponent、SoundConcurrency、Attenuation；SoundBase天然兼容SoundWave/SoundCue/MetaSound Source。
7. WorldSubsystem无Tick，通过Data完成回调和AudioFinished事件驱动。
8. Handle使用Id/Generation/Weak World；Attached使用Weak SceneComponent。
9. MetaSound/SoundCue仅开放Definition白名单浮点参数。
10. Presentation Bridge注册ProviderChannel=SFX，Prediction Cancelled按RequestId取消。
