# GamePlatformSave 审查整改方案与执行计划

日期：2026-09-29

## 一、历史与现状结论

当前正式三层架构为：

DivineBeasts（神兽联盟项目层） → MobaCommon（MOBA通用层） → GamePlatform（游戏平台层）。

GamePlatformSave 位于 GamePlatform/Application（游戏平台应用机制分类）。审查前只有 GamePlatformSave.uplugin、GamePlatformSaveClient.Build.cs、模块入口和三行 README，属于二期预留模块壳。

历史基线已经冻结两条核心边界：

1. 只承载非权威本地数据。
2. 禁止保存金币、装备、等级、比赛结果等服务器权威数据。

当前插件主清单进一步明确后续重点为：版本化本地存档、原子写、备份、损坏恢复。

## 二、最新设计

本轮保留唯一 GamePlatformSaveClient — ClientOnly（仅客户端）模块，不机械增加 Runtime/Server/Editor 空模块。

核心结构：

- IGamePlatformSaveService：GameInstance（游戏实例）作用域异步服务契约。
- IGamePlatformSaveProvider：上层命名空间版本与迁移扩展契约。
- FGamePlatformSaveKey：Namespace/ProfileKey/SlotName 稳定逻辑键。
- FGamePlatformSaveRecord：SchemaVersion + 二进制 Payload。
- Envelope：固定格式版本、SchemaVersion、PayloadSize、CRC32。
- GamePlatformSavePolicy：Key/Record校验、稳定磁盘ID、Envelope编解码。
- GamePlatformSaveStorage：Saved/GamePlatformSave 下的文件存储、同目录临时文件、Flush、主档替换、.bak备份。
- UGamePlatformSaveSubsystem：无Tick，游戏线程接收请求，线程池执行磁盘IO，完成后回到游戏线程。
- 同一逻辑Key同时只允许一个进行中的IO操作，避免保存/删除/加载竞态。
- 主档损坏或缺失时允许读取有效 .bak；恢复只影响本地体验，不把本地数据提升为权威事实。

## 三、职责边界

允许：

- 教程已看提示等非权威本地体验状态。
- 本地UI布局草稿、非权威缓存或工具状态。
- 其他平台/项目插件通过独立 Namespace（命名空间）保存的可丢失本地数据。

禁止：

- 金币、货币、资产余额。
- Inventory（背包）权威库存。
- Equipment（装备）权威装备状态。
- Progression（成长）等级、经验。
- Quest（任务）权威进度。
- Match（比赛）结果、隐藏分、排位结算。
- Entitlement（权益）真源。
- 登录密码、Token、服务器凭据和其他敏感秘密。
- 世界权威可变状态或任何可用于绕过服务器校验的数据。

## 四、依赖与端侧

- 插件层：GamePlatform。
- 模块：GamePlatformSaveClient。
- 模块类型：ClientOnly。
- TargetAllowList：Client、Editor。
- Dedicated Server：不得链接。
- 插件级依赖：仅 GamePlatformCore。
- 模块依赖：Core、CoreUObject、Engine、GamePlatformCore。
- 不依赖 Online、Session、Inventory、Equipment、Progression、UI、Settings、Data 或 DivineBeasts。
- 上层调用方需要账号隔离时传入脱敏的稳定 ProfileKey；Save 不反向读取 Online 身份。

## 五、版本与恢复

两层版本：

1. Envelope FormatVersion：插件内部磁盘封装版本。
2. Record SchemaVersion：数据所属 Namespace 的业务模式版本。

存档插件只负责封装版本兼容和完整性验证。上层 Provider 负责把旧 SchemaVersion 迁移到当前版本。

当存档版本高于当前 Provider 支持版本时 Fail Closed，不猜测降级。

## 六、性能与线程

- 无 Tick/Ticker。
- 磁盘 Read/Write/Delete 在线程池执行。
- UObject、Provider注册、回调和迁移在游戏线程处理。
- 热路径不扫描目录、不读取磁盘。
- Payload 设置明确安全上限，防止损坏长度或调用方误用造成异常内存占用。
- 文件名使用逻辑Key的稳定SHA-1摘要，不把原始ProfileKey直接暴露到文件名。
