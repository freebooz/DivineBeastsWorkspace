# SinksAndExporters（输出器与导出器）

公共接口 `IGamePlatformTelemetrySink（遥测输出器接口）`提供 Start、SubmitBatch、Flush、Shutdown、GetHealth。

已实现 NullSink（空输出器）、Development LogSink（开发日志输出器）、NetworkSink（网络输出器）。LogSink 只输出 BatchId/数量/Drop，不打印 Attributes 或 Secret（敏感属性/密钥）。

NetworkSink 通过中立 `IGamePlatformTelemetryTransport（遥测传输接口）`工作，采用 bounded retry（有界重试）、exponential backoff（指数退避）、deterministic jitter（确定性抖动）、Retry-After 和 MaxPendingBatches。

未来可适配 IAnalyticsProvider（UE分析提供器）或其它 Exporter，但公共 API 不绑定第三方厂商。
## 自定义Sink同步重入与关闭合同（2026-10-09）

子系统公开控制/上下文/记录/刷新均在游戏线程执行。每个UObject仅初始化一个GI作用域；Deinitialize先永久关闭并失效实例代次、Sink代次和一次性调度资格，再摘下Sink。关闭期间ConfigureSink返回false、SetEnabled(true)和上下文更新忽略、RecordEvent/RecordMetric返回Disabled、公开Flush拒绝，不能用重复Initialize重开旧对象。

ConfigureSink持有候选，Start失败保留旧Sink并Shutdown清理候选；Start内同步关闭后候选也必须清理。正在配置（包括清理退休Sink）期间嵌套Configure明确拒绝，不调用嵌套候选Start。成功发布实际Sink后推进SinkGeneration并取消旧Ticker；旧Flush与Shutdown后复核代次，关闭则外层返回false。退休Sink清理仍要完成一次，不能因新Sink已关闭而漏掉旧Sink。

同一已安装Sink不重复Start，必须查询其状态非Stopped且所属代次有效才确认成功，不能通过重新安装同对象复活已Shutdown资源。正常刷新允许GetHealth内替换Sink；返回后必须在BuildBatch前复核实际Sink身份，旧Sink不能继续出队或Submit。每次Submit后同样复核，最多只报告已经发生的转交，不写后继代次诊断或调度。

最终Drain使用仅Deinitialize可调用的内部路径，绑定摘下Sink与关闭代次；仍为最多8轮、每轮现行有界批次数，不创建Ticker。旧Flush栈正在执行时关闭不递归Drain，剩余缓冲随关闭丢弃。Sink的Shutdown秒预算仍由既有Limits提供，不保证远端持久送达，也不回滚业务事务。

Submit完成先原子消费一次资格；后台完成只投递纯值及弱对象身份到游戏线程，再核实例/Sink代次才安排剩余缓冲。Ticker捕获实例、Sink及独立调度代次，旧Ticker不得清除新句柄。GetDiagnostics的自定义GetHealth若换代，返回最新基础诊断，不附旧Sink健康信息或递归查询新Sink。

账号/世界边界使用独立的ContextOperationGeneration（上下文操作代次），不以SinkGeneration（输出器代次）决定发布资格。BeginSession、EndSession、BeforeWorldTravel以及UpdateWorldContext发布后继世界时取得新操作身份；只替换Sink不能取消旧会话清理、新会话发布或旧世界清理。BeginSession的旧会话结束与新会话发布共用一个操作身份，内部结束不会再发起第二个公开EndSession。外部Flush返回后核关闭、实例和本次上下文操作身份；真实后继会话/旅行/世界已接管则旧栈停止，不能清新玩家、新世界或复活后继已结束的会话。关联/环境/内容修订等普通属性更新不取得边界身份，原有账号/旅行清理合同继续适用。

SessionGeneration继续用于现有采样会话身份，不复用为请求发布权；上下文、输出器、调度三个资格分别保护对应所有权。边界方法在同步外部调用期间保活子系统，仍遵守永久关闭门闩。没有新增公开接口、反射字段或序列化格式，Private布局变化需要随插件重新编译。

本轮新增GamePlatformTelemetryLifecycleTests.cpp八个实际Subsystem/IGamePlatformTelemetrySink回归：StartClose、ShutdownReentry、HealthReplacement、ConfigureNested、ExternalClose、CompletionGeneration、ContextSinkReplacement、ContextSuccessor。后两者分别覆盖三种GetHealth换Sink边界与真实Begin/End/Travel/后继世界重入接管。不联网，不保存凭据，不作为生产Sink。仅完成源码与静态门禁；尚未执行UE编译/Automation、真实网络断线、跨GI/多PIE和关闭预算性能验证。
