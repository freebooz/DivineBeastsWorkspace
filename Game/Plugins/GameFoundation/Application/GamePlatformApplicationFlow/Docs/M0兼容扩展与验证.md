# M0兼容扩展与验证

日期：2026-09-21。范围仅GamePlatformApplicationFlow插件；Core任务01另见其README。主工程装配、地图和真实资产生成、配置及全局目录由父任务处理。本文件记录实际已落盘接口与验证，不把预设身份当作已生成资产。

## 同一个执行器与旧接口

保留 `Configure(const FGamePlatformFlowDefinition&, FString&)`、`Start(UObject*, FString&)`、`Cancel(const FGamePlatformFlowHandle&)` 及节点 `Execute`／`Finish`。旧FGamePlatformFlowDefinition仍是显式C++配置，始终按DAG校验；旧重试、退避、超时、取消和关闭语义不变。未将旧类型批量换成Core类型。

新UGamePlatformFlowDefinition资产与旧C++图都转换到同一 `FApplicationFlowExecutor`，没有第二套状态机。子系统保存旧配置及其GC可追踪节点；资产终态后旧Start恢复上次旧配置，不重复运行已经释放租约的资产节点。只使用过资产模式而未Configure时，旧Start明确失败。

工厂、节点Execute／Finish、终态广播与虚拟资产校验均置于已有重入防护中。关闭请求先禁止新控制，待调用栈展开再清理；没有在执行器回调中销毁执行器。原生与UE层都拒绝控制重入。

## 新公开合同

以下方法均属于UGamePlatformApplicationFlowSubsystem，仅游戏线程调用：

```cpp
FGamePlatformFlowFactoryHandle RegisterNodeFactory(
    FName ExecutorId, FGamePlatformFlowNodeFactory Factory, FGamePlatformResult& OutResult);
bool UnregisterNodeFactory(const FGamePlatformFlowFactoryHandle& Handle, FGamePlatformResult& OutResult);
FGamePlatformFlowHandle StartFlow(
    FGamePlatformDataLease& InOutReadyLease, UObject* Payload, FGamePlatformResult& OutResult);
bool CancelFlow(const FGamePlatformFlowNodeToken& Token, FGamePlatformResult& OutResult);
bool SubmitEvent(
    const FGamePlatformFlowNodeToken& Token, FGamePlatformFlowNodeResult Event, FGamePlatformResult& OutResult);
```

`FGamePlatformFlowNodeFactory` 为 `TFunction<UGamePlatformFlowNode*(UGameInstance&)>`。工厂只创建节点，不启动请求；每run、每个资产节点都必须返回本实例新建的独立对象，不接受CDO、模板、跨实例节点、旧Configure节点或此前工厂对象。工厂注册句柄含ScopeId、RegistrationId、ExecutorId；重复键、空工厂、活动运行及重入均不能注册，旧或跨实例句柄不能撤销新注册。工厂闭包不受GC扫描，捕获外部UObject须用弱引用。

`FGamePlatformFlowNodeToken` 含Handle（ScopeId、RunId）、NodeId、NodeGeneration。Context原五字段顺序不变，在末尾追加 `uint64 NodeGeneration=0` 与 `FPrimaryAssetId InputDefinitionId`；旧配置后者为空。Snapshot末尾追加NodeGeneration。每次进入、重试、循环重访都会得到不同的非零代次；尚未开始或切换待开始期间为0。

SubmitEvent把现有FGamePlatformFlowNodeResult送入原单槽邮箱，和Complete竞争，首次有效完成生效。错误作用域、运行、节点、代次、重复完成和终态后投递均拒绝。此接口为游戏线程控制入口；工作线程继续使用原Complete回调。精确CancelFlow要求已开始的节点令牌；首节点开始前可用旧Cancel(运行句柄)。

## 资产字段与预检

公开头 `Public/Definitions/GamePlatformFlowDefinition.h`：

| 类型 | 字段及默认值 |
| --- | --- |
| UGamePlatformFlowDefinition : UGamePlatformDefinitionBase | EntryNodeId=None、Nodes数组、bAllowCycles=false、MaxImmediateCycleTransitions=64；继承Data的LogicalId、DataVersion、RequiredDefinitions |
| FGamePlatformFlowNodeDefinition | NodeId=None、ExecutorId=None、InputDefinitionId为空、TimeoutSeconds=30、NextNodeId=None、Routes映射 |

NodeId和ExecutorId是中立键。NextNodeId或Routes目标None表示成功终点；Routes键不允许None。InputDefinitionId可空；非空时必须是平台定义类型和合法逻辑身份。Flow只传递身份，不擅自建立输入资源加载器，也不把所有输入自动加入RequiredDefinitions。输入加载和其租约所有权归真实节点所属领域，跨节点保留需求须明确移交给业务所有者。

ValidateDefinition先执行Data基类身份／结构版本检查，再校验图：入口存在、节点ID不重复、全部节点可达、路由存在、超时有限且正、执行器键非空、预算为正。默认DAG；只有显式bAllowCycles允许循环。StartFlow在调用任何工厂前完成图校验和全部ExecutorId注册检查，再创建节点并验证归属、唯一性。缺失能力返回MissingNodeFactory等真实错误，不部分启动。

每次Tick最多开始一个节点。所谓“即时完成”指Execute返回时邮箱已收到结果；在连续即时片段中，只有目标节点已经被访问才消耗循环预算。最多允许预算指定次数的重访，下一次以ImmediateCycleBudgetExceeded失败。真正异步等待打断片段，重新计数。这既限制即时自环，也保留2,000节点等长无环链以及用户可多次交互的异步循环。

## Data租约转移与清理

调用者先用本实例IGamePlatformDataService::AcquireDefinition请求UGamePlatformFlowDefinition，在延后完成并真实成功后调用StartFlow。Flow不相信句柄中的RequestState快照，使用GetLeaseState与GetLoadedDefinition核实实际就绪、类型、作用域和调用者存活。

同步拒绝保持InOutReadyLease，不接管、不释放调用者资源，也不Execute任何节点。工厂创建阶段的临时节点由UPROPERTY保活，失败后撤销本次引用；从未Execute的节点不会伪造Finish。创建完成后再次核实租约有效，在同一执行器原子安装和启动接纳后才转移租约并清空输入。调用者不得继续使用之前保留的副本释放它。

运行期间节点、Payload与定义租约持续保活。每轮检查根租约有效性，失效以FlowLeaseExpired失败并清理，不把资源丢失当成功或用户取消。成功、失败、取消、关闭均先Finish已开始节点，再释放本流程根定义租约，最后广播终态。Data负责共享需求和其他调用者租约，Flow不卸载别人的资源。Data先关闭时由Data作用域清理全部租约，Flow不访问销毁后的服务；释放异常记录真实日志。

根定义租约终结不意味着项目probe或世界就绪租约也应结束；它们的所有权由项目协调器或领域服务持有。本插件不实现“Ready成功”替身，真实地图加probe就绪屏障属于主工程节点。

## 本轮实际验证

原生工具链：Win64、CMake4.3.2、VS2022生成器、MSVC19.38.33145.0，C++17，`/W4 /WX /utf-8`。实际执行：

```powershell
& 'Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/Tests/Scripts/TestApplicationFlow.ps1' -Configuration Debug -BuildDirectory 'Saved/Validation/FoundationM0/FlowNative'
& 'Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/Tests/Scripts/TestApplicationFlow.ps1' -Configuration Release -BuildDirectory 'Saved/Validation/FoundationM0/FlowNative'
```

命令从工作空间根运行；本机执行使用相同位置的绝对路径。两配置均输出 `Cases=31 Failed=0`，构建和CTest退出0。CTest登记为一个测试集合，不能写成31个CTest目标。

先写新增循环／代次断言，真实运行得到26场景4失败、CTest退出8，旧21场景仍全部通过；其后实现增量逻辑。独立保存的日志都在工作空间Saved内：

- `Saved/Validation/FoundationM0/FlowNative/Cycles-Red-20260921.log`：实际行为失败，不是缺少头文件的编译错误。
- `Saved/Validation/FoundationM0/FlowNative/Debug-31Cases-20260921.log`：Debug31场景通过。
- `Saved/Validation/FoundationM0/FlowNative/Release-31Cases-20260921.log`：Release31场景通过。

旧21场景全部保留，包括取消、超时、重试、跨线程完成、并发重复完成、独立作用域、关闭和2,000节点DAG。新增10场景覆盖显式循环与节点代次、即时循环预算、异步等待重置预算、循环模式结构约束、重试代次、外部事件与原回调竞争、精确取消和线程守卫、结构预检／原子启动失败、资产模式2,000节点长链、依赖失效终止清理。

UE测试源码包含31个纯核心场景、原7个适配场景和新增4个资产适配／集成场景，共42个预期测试。新增Validation、FactoryScope、EventToken检查反射资产校验、注册归属与撤销、失败不转移、输入空值兼容、外部事件和精确取消。RealLeaseLifecycle潜伏测试使用真实Data服务与实际生成的流程资产，验证未注册工厂拒绝且不转移、成功转移后清空输入、输入身份传递、取消和失败释放、旧DAG恢复、再次运行新节点、关闭清理和迟到回调。

真实资产测试参数为 `-GamePlatformFlowTestDefinition=GamePlatformDefinition:foundation.flow@1`；这是父任务选定的身份，本轮没有生成该uasset。测试缺参数、缺资产、缺AssetManager、加载失败或超时必须失败。节点等待函数仅是Private/Tests中的测试替身，Data和租约不被模拟。插件UE脚本已传递该参数并要求至少42项全部Success，但**本轮没有执行该脚本的引擎构建或运行路径**。

本轮明确未执行UBT、UHT、UE自动化、Editor／Client／Server／Game目标构建、Cook、Stage、多实例／跨图或真实Ready屏障验收。保留现存空描述文件，没有移走、修复或新建宿主绕过阻断；也没有复用历史临时宿主。旧版UE编译结果不能覆盖本次新增代码，当前交付是源码与原生验证，不是M0游戏可运行验收。
