# 应用流程接口与接入说明

M0更新：下文旧Configure／Start／Cancel与Execute／Finish签名、DAG合同继续有效；新增资产、工厂、租约和精确事件接口见 [M0兼容扩展与验证](M0兼容扩展与验证.md)。FGamePlatformFlowContext在原五字段末尾追加NodeGeneration和InputDefinitionId，旧聚合初始化保持原顺序；旧配置输入身份为空。

## 公开接口

| 接口 | 前提与所有权 | 结果／失败 |
| --- | --- | --- |
| Configure(Definition, OutError) | 游戏线程、空闲或终态；节点属于当前 GameInstance | 完整图校验成功后保活节点；失败原子保留旧图 |
| Start(Payload, OutError) | 已配置、当前无活动运行；Payload 为空或属于当前 GameInstance | 有效 ScopeId＋RunId；失败为无效句柄并设置中文诊断 |
| Cancel(Handle) | 当前作用域与运行代次都匹配 | 清理当前尝试、广播取消；旧句柄／重复取消返回 false |
| GetSnapshot() | 游戏线程 | 当前状态、句柄、节点、尝试号及脱敏错误 |
| OnFinished() | 调用方保存委托句柄并在自身销毁前解绑 | 每轮运行只通知一次终态；回调内只查询，不重入控制 |
| UGamePlatformFlowNode::Execute | 游戏线程；持有自己的异步请求令牌 | 调用完成函数提交 Success／Failure；允许异步或同步提交 |
| UGamePlatformFlowNode::Finish | 游戏线程，每个开始的尝试一次 | 取消请求、解绑委托、释放临时租约；不再提交业务结果 |
| UGamePlatformCallbackFlowNode::Bind | 游戏线程、执行和清理函数都非空 | 一次性绑定；已绑定或缺函数时失败 |

## 无虚构业务接口的组合根示例

下面的装配函数接收调用方提供的真实业务动作。它只构建机制，不假装已有登录、资料或服务器服务。调用方必须把真实请求和撤销动作成对传入，并检查返回值。

```cpp
#include "API/GamePlatformApplicationFlowSubsystem.h"
#include "Interfaces/GamePlatformCallbackFlowNode.h"
#include "Engine/GameInstance.h"

bool ConfigureEntryFlow(
    UGameInstance* Instance,
    UGamePlatformCallbackFlowNode::FExecuteAction BeginEntry,
    UGamePlatformCallbackFlowNode::FFinishAction EndEntry,
    UGamePlatformCallbackFlowNode::FExecuteAction BeginReadiness,
    UGamePlatformCallbackFlowNode::FFinishAction EndReadiness,
    FString& OutError)
{
    if (!IsInGameThread() || !IsValid(Instance))
    {
        OutError = TEXT("必须在有效游戏实例的游戏线程装配");
        return false;
    }
    auto* Flow = Instance->GetSubsystem<UGamePlatformApplicationFlowSubsystem>();
    if (!Flow)
    {
        OutError = TEXT("流程子系统不可用");
        return false;
    }
    auto* Entry = NewObject<UGamePlatformCallbackFlowNode>(Instance);
    auto* Ready = NewObject<UGamePlatformCallbackFlowNode>(Instance);
    if (!Entry->Bind(MoveTemp(BeginEntry), MoveTemp(EndEntry)) ||
        !Ready->Bind(MoveTemp(BeginReadiness), MoveTemp(EndReadiness)))
    {
        OutError = TEXT("每个节点必须提供真实执行和清理函数");
        return false;
    }
    FGamePlatformFlowDefinition Definition;
    Definition.EntryNodeId = TEXT("Enter");
    FGamePlatformFlowStep EnterStep;
    EnterStep.NodeId = TEXT("Enter");
    EnterStep.Node = Entry;
    EnterStep.NextNodeId = TEXT("Ready");
    EnterStep.TimeoutSeconds = 30.0;
    FGamePlatformFlowStep ReadyStep;
    ReadyStep.NodeId = TEXT("Ready");
    ReadyStep.Node = Ready;
    ReadyStep.TimeoutSeconds = 60.0;
    Definition.Steps = {EnterStep, ReadyStep};
    return Flow->Configure(Definition, OutError);
}
```

随后组合根可创建属于该 GameInstance 的强类型 Payload，调用 Start 并保存句柄，业务退出时 Cancel。函数式节点闭包不能强捕获 GameInstance／World；跨线程回调不要访问 UObject，只准备值结果并调用 Complete。需要从完成事件重新启动流程时，将新任务排入游戏线程队列。

## 分支和重试

步骤 NextNodeId 是默认成功边。为新手／常驻世界选择等增加 Routes，例如 `Village → VillageEntry`；节点用 `Success(TEXT("Village"))` 选择具名分支。返回未配置分支为 UnknownOutcome，不能静默走默认边。FName 大小写不敏感；适配层统一小写传入内部图，防止运行时名称匹配与校验不一致。

节点失败使用 `Failure(ErrorCode, ChineseMessage, bRetryable)`。只有 bRetryable=true 且未耗尽 MaxAttempts 才会重试；超时另由 bRetryOnTimeout 控制。默认 MaxAttempts=1；启用重试前必须考虑幂等键、一次性票据、重复支付／写入和请求取消是否生效。连接重试完成不自动复用旧世界地址或已消费准入票据。

## 内建错误码

NodeFailed（节点失败且未给码）、NodeTimedOut（超过截止时间）、UnknownOutcome（未声明分支）、InvalidClock（非法／回退时钟）、InvalidDeadline（截止时间溢出）、InvalidRetryTime（退避时间溢出）、AttemptGenerationExhausted（代次耗尽）、Cancelled（调用方取消）、Shutdown（作用域关闭）。适配层另有 NodeUnavailable（节点失效）、NodeNotReady（函数式节点未绑定或忙碌）。节点自定义稳定领域错误码不会被覆盖。

业务拒绝不能被标记为 Success；权限／票据／版本校验仍以服务端真实结果为准。本地流程状态、委托和 Payload 不具备网络权威或自动复制语义。
