版本：0.1.0｜执行日期：2026-09-21。源码实现、标准 C++ 核心验证和 UE 工程验收是三个不同结论。

注册路径 `D:\Program Files\Epic Games\UE_5.8` 缺少构建和编辑器必需文件；随后发现 `F:\UnrealEngine-5.8.0-release`，其版本文件为 5.8.0，具有源码、构建工具与编辑器程序。已使用后者尝试验证，不能继续将 D 盘缺失外推为全机无引擎。主工程 `.uproject` 及 Target 文件目前仍为空占位，本次不重建整个游戏宿主，也不以其他引擎版本替代 UE5.8。

## 二、可重复原生验证

在工作空间根执行：

```powershell
& 'Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/Tests/Scripts/TestApplicationFlow.ps1' -Configuration Debug
& 'Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/Tests/Scripts/TestApplicationFlow.ps1' -Configuration Release
```

默认生成目录为 `Saved/Validation/ApplicationFlow/Native/`。日志为 `Testing/Temporary/LastTest.log`，会被下一轮测试覆盖；需要归档时使用不同的 `-BuildDirectory`，不能声称同一个最新日志同时保存所有历史执行。

## 三、21 个核心行为场景

| 测试名 | 中文验证意图 |
| --- | --- |
| SequentialAndSynchronousCompletion | 顺序推进，同步完成不递归调用后继 |
| NamedBranchSkipsDefault | 具名结果选择分支，跳过默认后继 |
| UnknownOutcomeFails | 未声明结果明确失败并清理 |
| FailurePreservesError | 保留领域错误码与消息 |
| CancelAndLateCompletion | 取消后旧完成无效、清理一次 |
| CancelBeforeFirstTick | 尚未开始的节点不得被虚假清理 |
| OldRunCannotAffectRestart | 旧运行句柄和完成不能改变新运行 |
| DuplicateCompletionFirstWins | 重复完成仅首次生效 |
| DeadlineBeatsQueuedCompletion | 到达截止时间时超时优先 |
| RetryDelayAndOldAttemptIsolation | 重试遵守退避，前一次尝试回调无效 |
| RetryBudgetExhausted | 最大尝试次数耗尽明确失败 |
| TimeoutRetryAndCancelBackoff | 可选超时重试及退避期间取消 |
| InvalidGraphsAreAtomic | 非法图拒绝且保留原配置 |
| InvalidLimitsRejected | 非有限时间、非法上限等配置被拒绝 |
| BusyAndReentrantControlRejected | 运行中改图及节点回调控制重入被拒绝 |
| ThreadedCompletionAndControl | 工作线程可完成，不可控制流程 |

| IndependentScopes | 不同执行器相互隔离 |

| LongGraphDoesNotRecurse | 2,000 节点链不递归耗尽调用栈 |

## 四、UE 宿主验证入口与后续门禁

先确认完整可用的 UE5.8 及实际启用本插件的可构建宿主。脚本参数必须填写真实路径和目标，不按示意路径自动创建第二个正式游戏工程：

```powershell
& 'Game/Plugins/GameFoundation/Application/GamePlatformApplicationFlow/Tests/Scripts/TestApplicationFlowUnreal.ps1' `
  -EngineRoot '<完整UE5.8根目录>' `
  -Project '<真实宿主.uproject绝对路径>' `
  -EditorTarget '<实际Editor目标名>' `
  -ReportDirectory '<本轮全新Automation报告目录>'
```

脚本校验版本、工具、项目启用项和新报告目录；先构建 Editor，再运行 `GamePlatform.ApplicationFlow`。自动化队列清空后才退出，并检查 `index.json` 中至少 28 个对应测试均为 Success；无报告、空测试或失败都不能标为通过。只验证前置条件失败路径不能证明引擎报告格式与真实执行链可用。

适配测试 `Adapter.ScopeAndCancellation` 与 `Adapter.Shutdown` 覆盖 GameInstance 节点归属、FName 大小写、跨实例取消、终态事件重入拒绝、重复取消与关闭清理。`Adapter.ReentrantShutdown` 另有 Execute、FinishSuccess、FinishCancel、FinishShutdown、TerminalEvent 五个场景，验证在回调中退出不会释放仍在调用栈中的执行器，且清理与终态恰好一次。仍需追加并执行真实宿主跨地图／GC、多个 PIE GameInstance、服务注入、退出和服务器生命周期集成测试。

交付验收还需分别构建 Client、Server（及实际使用的普通 Game），核查插件依赖与服务端产物；对未来真实登录、角色、票据、连接和加载节点执行正常／失败／取消／重连联调。本轮没有完成这些领域服务，也不把测试节点当作正式业务实现。

## 五、本轮真实 UE 构建记录与阻断项

1. 最初尝试 UE 自带 BuildPlugin。其临时宿主生成到 `Saved/Validation/ApplicationFlow/UEBuildReview/`，未将该副本视作正式源码。发现该入口展开源码引擎构建后主动取消，退出码 1，不计为通过；后改用仅编译本模块的方式。
2. 创建 `Saved/Validation/ApplicationFlow/UEHost/ApplicationFlowValidation.uproject` 临时验证描述，通过 AdditionalPluginDirectories 引用工作空间唯一正式源码。没有改写 `Game/DivineBeastsArena.uproject` 或正式 Target。
3. 实际运行以下命令，UE 5.8.0、Visual Studio 14.44.35214 工具链、Windows SDK 10.0.22621.0。UHT 成功；第一次 C++ 编译发现 UE5.8 已将 ApplicationContextMask 改为独立常量，修正测试声明后重跑。

```powershell
& 'F:/UnrealEngine-5.8.0-release/Engine/Build/BatchFiles/Build.bat' UnrealEditor Win64 Development `
  '-Project=E:/poject/feebooz/DivineBeastsWorkspace/Saved/Validation/ApplicationFlow/UEHost/ApplicationFlowValidation.uproject' `
  -Module=GamePlatformApplicationFlow -UsePrecompiled -NoUBA -NoHotReloadFromIDE -WaitMutex
```

4. 重跑完成 `Module.GamePlatformApplicationFlow.cpp`（包含生成代码及全部 UE 测试）的编译，随后 DLL 链接失败：`LNK1181` 无法打开 `..\Intermediate\Build\Win64\x64\UnrealEditor\Development\Core\UnrealEditor-Core.lib`。进程退出码 1，不能将整体构建记为通过。
5. 检查 F 盘源码引擎及 D 盘注册引擎的 Intermediate，均未找到可供本次链接的 UnrealEditor-Core／CoreUObject／Engine 导入库。未跨版本替换库、未从 DLL 伪造导入库，也未为插件任务启动整套引擎重建。
6. 原始 UBT 日志按原字节归档到工作空间 `Saved/Validation/ApplicationFlow/UnrealEditor-20260921-LinkFailure.log`；源日志与归档 SHA256 一致。该日志证明编译与链接结果，不证明运行测试通过。

下一步需要提供与现有 UE5.8 二进制、头文件和工具链匹配的完整引擎开发产物，或由引擎维护任务完成相应构建。之后重新链接并执行 28 项 UE 自动化，尤其是新补的五种回调关闭回归；本轮未能执行这些回归的运行期红／绿验证。真实正式游戏集成仍需先将占位宿主落实为可构建工程。
