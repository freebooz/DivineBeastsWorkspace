# 应用流程架构与生命周期说明

## 职责与依赖

一个插件、一个 Runtime 模块。公开契约为 GameInstance 子系统、节点、定义、上下文、句柄、结果；Private/Execution 的纯 C++ 核心是唯一调度实现。UE 适配层只转换标识、管理 UObject 引用与 Ticker，不复制流程状态机。

组合根 → GamePlatformApplicationFlow → Core／CoreUObject／Engine／GamePlatformCore／GamePlatformData。M0资产入口消费Data租约，仍由同一执行器推进；没有Online、Session、MOBA、项目或表现插件反向依赖。新增契约见 [M0兼容扩展与验证](M0兼容扩展与验证.md)。

Core 标准库容器、互斥量和弱引用不需要新运行时依赖；节点接口不抛异常，UE 构建无需开启 C++ exceptions。底层核心不应由插件外直接包含，它仅作为内部实现和独立测试编译目标。

## 状态与时间

Idle → Start → Running。失败且可重试时 Running → RetryWaiting → Running；成功终点为 Succeeded，失败为 Failed，主动取消为 Cancelled，作用域退出为 Shutdown。

流程启动、节点开始和完成消费分开调度。每次Tick最多开始一个节点，同步完成也先进入邮箱，不递归进入下一节点。每个活动GameInstance只有一个Ticker；每轮检查状态、时间及资产租约存活，空闲和终态移除Ticker。旧图在Configure校验，资产图在Data校验和StartFlow预检；循环模式只对连续即时片段的重复节点转换计数，不遍历全图或限制长无环链。

UE 使用 FPlatformTime::Seconds 单调时间；超时与重试不会因世界暂停、切图或时间膨胀冻结。调度时到达截止时间则超时优先，即使结果已排队也不再接受成功。需要更宽容时间窗口的项目应配置合理 TimeoutSeconds。节点不能阻塞游戏线程，否则调度与超时只能在其返回后继续。

## 线程与重入

Configure、Start、Cancel、GetSnapshot、Initialize、Deinitialize 以及节点 Execute／Finish、终态广播都在游戏线程。完成函数可在任何线程调用，仅向互斥保护的单槽邮箱投递值，不解引用 UObject。每个尝试只接收第一次完成，其余忽略。

节点 Execute／Finish 和终态事件内禁止同步重入流程控制；会返回失败诊断。需要在完成后再次启动时，通过 AsyncTask 的 GameThread 任务或项目事件队列延迟到当前调用栈结束。终态广播内可查询快照。

## 作用域、GC 与清理

子系统由 GameInstance 管理，ScopeId 每次初始化重新生成。RunId 在同一执行器内严格递增，Configure 不重置运行计数；核心尝试代次也不因重试、重配或新流程复用。

节点及可选 Payload 由子系统 UPROPERTY 强引用，GC 可以遍历引用图；核心适配器只保存弱 UObject 引用，避免隐式全局保活。节点实例与 Payload 必须属于本 GameInstance 的 Outer 链；跨世界 Actor 不得用作持久载荷。闭包捕获 UObject 要用弱引用，节点使用世界时通过 Context.GameInstance 重新获取当前 World。

每次尝试退出先失效邮箱，再调用 Finish。先前步骤成功时已完成临时资源清理，后续步骤失败不触发其业务补偿。必须跨步骤存在的数据和持久租约移交明确领域服务或 Payload；不要在 Finish 中把下一步骤仍需要的领域状态销毁。

Deinitialize：拒绝新控制 → 移除Ticker → 失效回调 → 活动尝试Finish(Shutdown) → 释放本流程Data定义租约 → 广播一次Shutdown → 释放执行器、Payload、节点、工厂与监听器。取消未开始的流程不调用节点Finish；取消退避不重复清理已失败尝试。成功、失败、取消同样先结束节点再释放所接管租约；节点自己持有的其他领域租约仍由其Finish或明确的业务所有者负责。

若业务节点 Execute／Finish 或终态监听器触发宿主关闭，Deinitialize 先标记关闭并禁止后续控制，等当前分发／广播栈展开后才执行实际释放。重复退出不递归清理；若成功或取消已完成，则保留其尚未发布的终态，不再用 Shutdown 覆盖。节点不能直接销毁自己或执行器；结束作用域使用宿主生命周期。
