## 未完成及已识别风险

- **Important，OnlineSession.cpp 的 Submit／Finish 登录分支：** SigningIn 时第二次 Login 被 AuthenticationBusy 拒绝，但 Finish 只比较当前 Generation 和 SigningIn，仍可能清除第一个合法登录的状态。需要为请求记录“拥有本次登录转换”或仅由确实发起该代次的登录清理；现有用例只测已登录后的第二账号，未覆盖正在登录时第二次调用。按用户停工要求保留现状，未继续修复。
- **Important，OnlineSession.cpp 的 Finish／Deliveries：** 活动请求和刷新等待队列有上限，但拒绝请求产生的待交付完成值目前没有独立内存预算。大量同帧提交仍可堆积 Deliveries；后续须明确同步拒绝契约或有界完成调度，并保持一次性结果语义。
- 未实现真实 JSON 解析。已核验 UE `FJsonSerializer::EFlags::StoreNumbersAsStrings`，但尚未写入适配；原生大修订号测试只覆盖状态机的 int64 缓存，不证明 JSON 精度保留。
- 未实现 UE HTTP 适配、流式正文上限、私有 UObject 门面或公共静态函数定义；没有 Build.cs、uplugin、模块注册。因此公开头不是可链接运行的插件。
- 还需验证世界清理、GI 反初始化、回调重入及失效对象的真实 UE 行为。原生 IsAlive 函数替身只验证相应纯逻辑分支。
- 未全面审查主工程已写的节点与 driver；本轮只读取了部分调用名，不能宣称逐项集成验证。

## 引擎补丁与日志核查交接

用户批准由另一实施者补丁。已读取当前 `IHttpRequest.h`：宏 `UE_HTTP_HAS_REQUEST_REDIRECT_POLICY=1`，枚举 Follow／Reject，`SetRedirectPolicy` 默认 false；Curl 实现由该实施者交付。Online 尚未连接该 API。后续必须在有宏且实际 setter 返回 true 后发送每一项请求，未知后端 fail closed。存在虚表 ABI 变化，必须重编 HTTP 与调用方，不能用旧 DLL 证明补丁有效。

已读取 CurlHttp.cpp 的 DebugCallback：默认 LogHttp 类别是 Display；`CURLINFO_HEADER_OUT` 在 VeryVerbose 可输出完整请求头（当前补丁后约 770～811 行），可能包含 Authorization；DATA_IN／DATA_OUT 分支只记录大小。TEXT 调试内容还会缓存并在失败时以 Warning 输出。插件没有启用 VeryVerbose、修改日志级别或发送网络请求。不得将这些局部检查泛化为“所有 UE HTTP 日志均已证明不泄密”；后续仍须核对调试编译宏、其他日志路径及宿主日志配置。

已核验 `SetResponseBodyReceiveStreamDelegateV2` 的公开存在、返回值以及它禁用默认正文缓存的契约；尚未实现接收累积和线程同步，不能宣称传输中已有限额。
