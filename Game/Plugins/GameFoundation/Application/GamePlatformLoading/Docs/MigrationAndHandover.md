# 迁移与交接

本轮增量启用Loading，并仅替换主工程既有Ready工厂的节点实现。未重命名已发布模块/反射类型，未改变Data或Flow公开协议。回退应先让运行中节点Finish、撤订阅并Release，再在独立受审变更中恢复Ready工厂与依赖；不能卸载仍有工厂回调的模块。

后续World插件应通过公开任务工厂贡献真实区域/流送/导航/出生就绪任务；不是把`ReportWorldOperable`的基础声明改成完整世界Ready。本轮基础世界任务仍可用于最小开发宿主，正式场景将由项目规格选择更强屏障。

后续UI只订阅值快照，并在自己的本地玩家生命周期撤销订阅；视觉平滑与屏障分离。VFX仍只依赖Data租约和平台表现语义，不读取Loading私有算法，也不能因可选表现失败更改权威结果。

Session适配必须由完成真实会话链的客户端组合层提供，在同一实例核对准入、目标实例/启动代次、世界和连接代次。当前没有此接口，不能从Session私有测试内核复制一个公开替身。Online的并行实现需要独立真实回归后才可作为前置。

开发`UDBALoadingFlowNode`内的两份Foundation定义和基础bootstrap声明将由正式项目数据配置替换；`TestLatch`仅限测试，永不接入正式流程。替换TaskType或字段前应提供兼容策略；当前C++契约尚无已发布序列化版本，不声称蓝图资产迁移已完成。

下一明确断点：修复既有描述文件/引擎构建前置 → 三目标编译/UHT → UE自动化 → 真实资产生成与FoundationLoadingOnly → 双PIE和取消回归 → 干净Cook/产物审计 → Session公开链完成后再增加会话任务。**本轮不进入World/UI/VFX或下一插件实施。**
