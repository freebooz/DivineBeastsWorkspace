P01｜工作空间、服务器和产品边界

唯一根目录为 DivineBeastsWorkspace（神兽联盟工作空间）；顶层固定为Game（UE工程）、Shared（跨语言共享层）、Backend（Go后端）、Build（统一构建）、Deploy（部署）、Tests（跨系统测试）、Tools（工具）、Docs（正式文档）。主工程薄装配，插件源码唯一位于 Game/Plugins（游戏插件目录）。后端内部不得重新出现一份Shared（重复共享真源）。

正式服务器只有 OpenWorld（常驻世界：登录大厅＋主城＋开放世界区域）、Village（新手村＋教学＋训练）、MainArena（短生命周期1v1～5v5竞技）。大厅可以是体验／区域／页面，不再独立服务器角色、目标、插件或世界包。三种角色使用共用服务器目标，按角色、体验、资源和部署配置运行。原有普通游戏目标先核查，不能擅自删除也不能未经审计视为隔离客户端。

应用流程必须包含登录、加载资料、创建／选择英雄及进入真实三维服务器世界。世界、PCG（程序化生成）、通用服务器准入和最小表现都在一期。竞技完整支持1v1、2v2、3v3、4v4、5v5；人数来自模式定义，不能复制五套实现或从协议枚举值推导。

<a id="p02"></a>

P02｜三层归属、名称映射与可选性

DivineBeasts（项目层） → MobaCommon（MOBA通用层） → GameFoundation（基础层）表示依赖方向；项目也可直接依赖基础层。非MOBA世界、登录和通用角色不被迫依赖竞技。内容包在第三层内部。类型继承、模块依赖、子系统生命周期和资源交付分别设计，不机械一一对应。

保留 GamePlatformArena（竞技插件）内五模块：GamePlatformMobaCore（MOBA契约）、GamePlatformMobaData（MOBA数据）、GamePlatformArena（双端竞技）、GamePlatformArenaClient（竞技客户端）、GamePlatformArenaServer（竞技服务器）。明确增加 MobaPresentation（MOBA表现语义插件），不恢复附件示意中拆出的多套玩法插件。名称冲突与映射见总体规划IN02—IN05，不把参考附件里的每个名字都视为新建指令。

DivineBeastsPresentation（项目表现插件）按附件建立；项目公共运行时、角色、技能和竞技继续保留已定稿名称。VFX／SFX项目级上下文、目录与映射优先归项目表现，不重复造运行框架；项目UI、必要动画和相机特殊行为仍有自己的真实归属。

新增插件须给出真实使用者、公开契约、模块目标、状态和验收。状态只能是“一期必建／条件拆出／随内容交付／二期预留”；不能为占位创建空描述文件、空模块或固定返回成功的服务。

<a id="p03"></a>

P03｜插件叶子、模块名和资源身份

分类目录不放 .uplugin（插件描述文件）；真正插件有且仅有自身描述文件，不能在其内部继续嵌套其他插件。[S01] 项目插件与引擎插件遵守各自原生搜索和配置规则，物理分类路径不等于资源挂载名。

插件名、模块名、反射类名、主资产ID和资产文件名是不同身份。模块的目录、构建规则类、描述声明、注册名和导出宏必须互相一致，整个构建中模块名必须唯一；一个插件可以拥有多个不同名模块。[S02] DivineBeastsArena（主工程模块）与项目竞技运行模块不能重名，后者采用 DivineBeastsArenaRuntime（项目竞技模块）等既定唯一名。

只移动工作空间或分类目录，不得顺手改变已发布身份。实际重命名必须有引用清单、资源重定向、协议兼容、版本迁移和回退记录。

<a id="p05"></a>

P05｜依赖和公开边界

依赖必须同时满足三层方向、模块端侧方向和同层无环。插件关系写在描述中，模块关系写在构建规则中；代码Include（头文件引用）、蓝图父类、资产硬引用、软引用解析、配置及内容注册都纳入审查。

跨模块只能包含对方公开头；禁止加入私有包含目录“修复”编译。公开签名使用到的类型才形成公开依赖；仅实现使用的库保持私有。用一个接口包装Niagara指针、但让战斗仍链接VFX客户端模块，不算解耦。

同层固定：战斗依赖技能底座，技能不反向依赖具体伤害执行；角色依赖通用玩法／技能，通用玩法不依赖具体英雄；平台在线不导入项目协议；数据基础不依赖英雄／世界／特效具体领域；表现协调不反向导入所有播放器；世界和PCG不各存一份全局实例目录。

MOBA表现插件单向消费竞技事实。项目公共表现不硬依赖MOBA；竞技专用组合根可依赖并装配两者。必须同时检查模块图与插件图，不能只证明模块无环却留下插件级循环。

<a id="p06"></a>

P06｜目标、加载阶段与命令行

共享、客户端、服务器和编辑器是职责类别，不是从模块后缀推导的构建事实。每个真实模块必须记录宿主类型、目标允许列表、加载阶段、命令行可加载性、支持的世界和网络模式，并用实际构建证明。

本项目默认客户端模块采用 ClientOnly（排除专用服务器的宿主）并允许Client（客户端）／Editor（编辑器）目标；服务器专有模块采用 ServerOnly（排除专用客户端的宿主）并允许Server（专用服务器）／Editor（编辑器）目标。Runtime（共享运行）和Editor（编辑器）模块按自身用途限制。普通Game（游戏）目标只有既有工作流需要且经过审计才加入。宿主语义与目标限制是两个条件，不能互相替代。[S03][S04]

VFX定义和目录反射类型位于客户端模块，但编辑器烘焙需要读取源资产；因此客户端模块允许编辑器命令行加载类型，不选用阻断此用途的 ClientOnlyNoCommandlet（禁止命令行的客户端宿主）。与此同时，VFX世界服务、注册播放动作和预览实例在命令行中不得启动。

StartupModule（模块启动）仅注册不绑定玩家世界的能力入口、反射和编辑器扩展；按世界创建的Provider（提供者）在作用域初始化时注册，在作用域关闭时撤销。注册顺序必须由明确依赖和就绪条件保证，不依赖同加载阶段的偶然遍历顺序。

<a id="p07"></a>

P07｜生命周期和三种调用合同

服务型：调用方 → 服务契约 → 有作用域的服务／子系统 → 实际适配器。在线、会话、准入与匹配不必经过资产目录。

权威动作型：技能／战斗 → 动作任务 → 执行／取消 → 必要动作与运动数据。参与权威位移、技能时序或骨骼计算的动作不能变成可任意丢弃的特效请求。

表现型：中立语义请求 → 客户端服务 → 目录解析 → 定义主资产ID → 数据服务 → 已加载定义和具体资源 → 执行器 → 可撤销句柄。这个合同不把每个箭头都变成一个类。

实例级服务采用游戏实例生命周期；本地界面／输入采用本地玩家；世界表现／世界协调采用当前世界。核心类型、数据定义、实体能力和纯算法不为了方便访问而建立子系统。[S06] 一项流程只保留一个执行器，由三层注入各自节点。

必须处理跨地图失效、多个PIE（编辑器运行）实例、观察者变化、连接重试、取消和反初始化；不能通过全局世界或固定第零号玩家获取业务上下文。默认事件、委托、定时器和异步回调；需要每帧执行时说明成本与替代方案。

P13｜Catalog（目录）与Resolver（解析器）的确定合同

附件规定四种目录来源及默认覆盖关系：ContentPack（内容包） > Project（项目） > Moba（MOBA） > Platform（平台），并要求考虑语义、上下文、具体度、优先级和父语义回退；禁止依赖加载、数组、哈希或扫描顺序。[U1：966—1040]

以下完全排序是本版补充设计。

第一步做资格过滤：目标用途、包激活状态、定义类型／版本、权益与可见性、平台、画质和上下文条件全部满足才成为候选。任何高优先级条目不能越过资格过滤。这里的权益验证针对使用该英雄／皮肤的授权主体：观察他人已获授权的皮肤表现，不要求观察者也拥有该皮肤；缺少本地资源时回退基础表现，不泄露不可见对象状态。

第二步优先精确语义。在同一语义匹配级别，按“目录作用域优先级 → 上下文具体度 → 显式Priority（优先级）”降序比较。只在当前语义没有合格结果且允许回退时，逐级检查父语义；不允许用宽泛父标签覆盖已有精确语义结果。

一期具体度采用已验证等值约束项数：HeroId（英雄）、AbilityId（技能）、SkinId（皮肤）、WorldId（世界）、PlatformId（平台）、QualityTier（品质）各一个明确等值约束计一项，未约束不计。范围／集合查询作为资格条件，不随意计算“看起来更具体”；新增查询形式需同步解析规则和测试。

作用域、具体度和显式优先级完全相同但选择到不同条目时，返回可定位歧义错误；禁止用条目ID、文件名、注册时间或遍历顺序偷偷决胜。诊断必须显示候选PackId（包ID）、CatalogId（目录ID）、条目及条件。相同主资产ID也不能假定可忽略参数差异。

例如：同一精确命中语义下，匹配当前英雄皮肤的内容包条目覆盖项目默认；不匹配当前SkinId（皮肤ID）的条目被过滤。项目精确语义优先于内容包父语义回退。两个包相同优先级、相同具体度均匹配同一皮肤则报冲突，必须由配置修正。

解析输出必须包含定义主资产ID、匹配来源、目录代次、回退路径和诊断身份；随后由数据服务加载定义，再加载定义的实际资源。目录不Spawn（生成）对象、不扣血、不发奖励。

<a id="p14"></a>

P14｜注册、撤销和包激活事务

本版补充：项目组合入口选择包；平台数据服务发现并加载包描述与目录；DivineBeastsPresentationClient（项目表现客户端）协调表现目录；实际VFX服务预检并注册自己的目录片段。服务器有自己的玩法／任务装配，不读取纯VFX目录。

注册句柄必须绑定服务作用域、注册身份和Generation（代次）。同一包版本在同一作用域重复注册必须按已规定的幂等或引用合同处理，不生成重复项。必需包依赖无环、版本／目标验证、目录无歧义后才提交本次可见视图；失败回滚此前成功项，不遗留半启用目录。

注销顺序：阻止新请求 → 撤销本次目录可见性 → 停止或等待本次拥有的活跃效果 → 清理回调与提供者 → 释放自己的资源租约。正在运行的旧目录实例要么保留其快照／租约到结束，要么被明确停止，不能在资源卸载后继续访问。

包可安装、可发现、可注册、可加载、可播放是不同状态，不得用一个“Enabled（启用）”布尔值代替。普通插件一期不承诺动态原生代码卸载；内容热下载、Game Feature（游戏功能）激活另行设计和验证。

<a id="p15"></a>

P15｜统一数据加载与租约

附件明确VFX不能重建资产身份、主资产加载、资源租约、多PIE所有权或版本体系。[U1：1140—1183] GamePlatformVFXPreloadCoordinator（VFX预加载协调器）只分析定义／包需求，调用GamePlatformData（平台数据），保存并在合适时机释放自身句柄。

本版补充：一次请求的所有权至少区分请求租约、预加载租约和运行实例租约；播放实例仍存在时不能先释放其实际使用资源。数据服务聚合仍有效调用者的需求，按资产和加载分组集合计数或等价租约模型管理；不能一个世界离开就无条件卸载另一世界使用的同一主资产。

战斗、输入和逐帧路径不得阻塞加载。预热／预加载在进入体验或选择角色阶段申请；迟到的短促命中特效根据事件时效跳过或降级，不能在数秒后补播旧命中；持续状态根据当前权威可见状态重建，不按旧一次性事件盲目续播。

释放本地句柄不保证资源即刻回收；验证资源持有链、GC（垃圾回收）与引擎池行为。不能靠“指针已置空”证明无泄漏。

<a id="p16"></a>

P16｜句柄、异步、线程和结束语义

实例句柄、预加载句柄、注册句柄分别使用附件的三类名称，不互相强制转换。VFX请求另有请求身份，以便关联预测、确认、取消和诊断。[U1：201—212、271—278]

本版补充：所有句柄含作用域身份与Generation（代次），停止旧实例不能停止池中复用的新实例。重复停止／释放必须幂等或明确返回已结束，不可重复扣租约。外部调用不能长期保存池化组件裸指针。

请求至少区分等待资源、运行、完成、取消和失败；取消后到达的加载回调只能释放本次资源，不能生成新效果。异步回调必须检查世界有效、请求仍有效、目录代次和目标弱引用；不能仅检查某个UObject（反射对象）指针非空。

对象生成、附着、参数更新和销毁在引擎允许的线程执行。纯解析可以使用不可变快照在安全线程计算，但不在后台线程任意访问UObject。世界销毁时先阻止请求和撤销注册，再取消任务、停止实例和释放租约。

附着目标销毁、骨骼／挂点缺失、玩家退出、窗口关闭、断线、切图和资源失败均有明确终止／回退策略。循环效果必须有对应停止事件或可验证的最长存活策略，不能无限遗留。

<a id="p17"></a>

P17｜复合VFX、池化和性能伸缩

复合效果只编排已有定义，支持顺序／并行和明确子任务所有权；必须限制依赖深度、子效果数、总持续时间和失败传播。这些限制由经评审配置提供，附件没有给出数值，本规范不臆造。加载时和编辑器分别检测环；父取消必须停止其拥有的子实例并释放租约。

优先使用Niagara原生组件池和Effect Type（特效类型）伸缩能力，Pool（池）与Scalability（伸缩）各保持统一策略入口，不按Instant／Beam／Area（瞬时／光束／区域）等建立平行池。[U1：1187—1257] 原生组件池支持复用同资源的组件，Effect Type支持按平台及质量管理伸缩，策略仍需目标设备测量。[S07]

重要性采用附件Critical（关键）、High（高）、Normal（普通）、Ambient（环境）四类，与画质、距离裁剪、原生重要性和预算配置桥接。关键预警或命中可读性应有低成本替代，不能一律裁掉。性能降级不改变权威判定范围、时机或伤害；外观可以变化，玩法事实不变。

池复用必须重置附着、参数、材质、结束回调和内部实例身份，不把上一角色／上一皮肤数据泄漏到新实例。人工核验要覆盖场景叠加而非只看单效果。

<a id="p18"></a>

P18｜网络事件、预测和纯表现权威边界

服务器输出GameplayCue（表现通知）或已复制事实后，客户端才做语义适配；本地合法交互／界面请求可直接走客户端入口。预测表现需要OccurrenceId（事件发生身份）、PredictionKey（预测键）或等价去重合同，确认不能重复生成，拒绝必须取消或修正。

持续效果以可重建状态为基础，瞬时效果以明确时效为基础。不要同时监听两个网络来源而重复播放；不要让普通C++事件总线被误认为自动复制。上下文不能暴露未授权敌方位置、不可见世界状态或任意资源路径。

服务器不运行GamePlatformVFXClient（VFX客户端模块）、不生成VFX实例、不用Niagara碰撞决定权威命中。视觉投射物、护盾、区域和传送门只表达事实。[U1：1261—1303] 必要动画和动作执行例外只限明确参与权威逻辑的最小资源，不允许借例外把纯特效带回服务器。

P23｜开发顺序、未实现能力和失败行为

先确认真实源码与本版差异，再按测试驱动建立最小可运行链。VFX先完成确定性目录、统一数据接入、瞬时／附着、实例句柄和编辑器验证，再按实际内容增加其余行为；目标类型保留不代表空壳实现可交付。

不支持的行为／未知定义／禁用包必须返回明确诊断，不落入默认成功。纯表现按配置降级或取消；关键玩法数据缺失须拒绝初始化或准入。生产不得静默退回模拟后端、测试身份、默认无限余额或“所有包已安装”。

附件的高级核验工具和全部十行为可以增量实现，但阶段交付必须逐项说明“已实现／未实现／已验证／未验证”，不能因头文件齐全就宣称框架全部完成。
