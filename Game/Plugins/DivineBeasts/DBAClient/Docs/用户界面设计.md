> 文档状态：当前有效设计基线
> 所属插件：DBAClient（神兽联盟客户端组合插件）

## 1. 设计目标

本设计用于统一《神兽联盟》项目层所有用户界面对象、继承关系、目录、事件更新方式、PC/移动端适配方式和界面清单。

核心目标：

1. 所有项目层可视 UI 对象必须继承 GamePlatformUI 对应分类基础类，禁止业务界面直接继承 UUserWidget、UCommonUserWidget 或 UCommonActivatableWidget。
2. 所有 UI 状态更新优先使用事件通知，禁止业务界面通过 Tick 持续轮询角色、背包、任务、匹配、网络、会话等业务状态。
3. Widget（控件）只负责表现，ViewModel（视图模型）负责只读视图状态和命令提交，Definition（定义资产）负责静态配置。
4. PC 与移动端共享业务状态、ViewModel、事件和 Definition；优先响应式适配，结构差异明显时再使用平台 Widget 变体。
5. 界面层不得成为 Gameplay（玩法）权威状态源，不直接决定比赛、角色、物品、任务、货币、权限等最终结果。
6. 所有新增和修改的 C++、Build.cs 示例与实现必须具有完整中文注释；严格 JSON 文件不添加非法注释。
7. Dedicated Server（专用服务器）不得加载 DivineBeastsUIClient 或任何 UI 资源。
8. 保持单向依赖：GamePlatformUI → 项目层 UI 扩展，项目层不得反向修改平台基础类职责。

## 3. 总体分层

《神兽联盟》UI 分为四层。

~~~text
业务权威状态层
Application / Gameplay / Online / Session / Arena / World
                    │
                    │ 状态事件 / 查询接口 / 命令接口
                    ▼
项目视图模型层
DivineBeasts ViewModel
                    │
                    │ OnStateChanged / 细粒度事件
                    ▼
项目界面层
Screen / HUD / Panel / Overlay / Dialog / Notification
                    │
                    │ 继承
                    ▼
平台基础层
GamePlatformUI
~~~

禁止 UI 直接绕过 ViewModel 大量扫描 Gameplay Actor、ASC、Inventory、Quest 或网络对象。

### 5.1 ViewModel 职责

允许：

- 保存 UI 只读投影状态。
- 订阅项目状态事件。
- 将底层结构转换为 UI 可直接消费的数据。
- 向 Command Port（命令端口）提交用户意图。
- 管理 Pending Request（待处理请求）。
- 管理 Revision（修订号）和 PageGeneration（页面代次）。
- 广播 UI 更新事件。

禁止：

- 创建 Widget。
- AddToViewport。
- 操作 CommonUI Stack。
- 直接决定 Gameplay 权威结果。
- 保存密码等敏感字段到持久状态。
- 使用每帧 Tick 轮询业务对象。

## 6. 事件驱动更新模型

UI 更新必须采用事件驱动。

~~~text
业务状态发生变化
      │
      ▼
Query Source / Gameplay Event
      │
      ▼
DivineBeasts ViewModel
      │
      ├── 更新只读状态
      ├── Revision + 1
      └── 广播事件
              │
              ▼
Widget / Screen / HUD
              │
              └── 只刷新受影响区域
~~~

### 6.1 通用事件

项目 UI 应至少支持：

- OnViewStateChanged（视图状态变化）。
- OnLoadingStateChanged（加载状态变化）。
- OnBusyStateChanged（忙碌状态变化）。
- OnErrorStateChanged（错误状态变化）。
- OnAvailabilityChanged（可用性变化）。
- OnInputMethodChanged（输入设备变化）。
- OnViewportChanged（视口变化）。
- OnSafeZoneChanged（安全区域变化）。
- OnThemeChanged（主题变化）。
- OnAccessibilityChanged（可访问性变化）。
- OnLanguageChanged（语言变化）。

### 6.2 业务细粒度事件

推荐按实际业务拆分：

- OnHealthChanged（生命变化）。
- OnShieldChanged（护盾变化）。
- OnMomentumChanged（气势变化）。
- OnAbilityChanged（技能变化）。
- OnCooldownChanged（冷却变化）。
- OnStatusChanged（状态变化）。
- OnInventoryChanged（背包变化）。
- OnEquipmentChanged（装备变化）。
- OnQuestChanged（任务变化）。
- OnPartyChanged（队伍变化）。
- OnMatchmakingChanged（匹配变化）。
- OnArenaPhaseChanged（竞技阶段变化）。
- OnScoreChanged（比分变化）。
- OnResultChanged（赛果变化）。

### 6.3 生命周期绑定

Screen：

~~~text
NativeOnActivated
→ BindUIEvents
→ RefreshInitialState

NativeOnDeactivated
→ UnbindUIEvents
→ CancelPageScopedRequests
~~~

普通 Widget：

~~~text
NativeConstruct
→ BindUIEvents

NativeDestruct
→ UnbindUIEvents
~~~

业务 UI 默认禁止使用 NativeTick 查询业务状态。

## 7. PC 与移动端适配

### 7.1 共用原则

PC 与移动端必须共享：

- ViewModel。
- Definition。
- 状态事件。
- Command。
- 权限和业务规则。
- ScreenId / RouteId。
- 本地化键。
- UI 语义。

差异只能存在于：

- 布局。
- 控件密度。
- 输入提示。
- 触控控件。
- Hover 行为。
- 动画复杂度。
- 资源质量。
- HUD 信息密度。

### 7.2 响应式布局等级

推荐统一使用：

- Compact（紧凑）：手机。
- Regular（标准）：平板、掌机。
- Wide（宽屏）：PC、主机、大屏。

禁止业务页面直接大量判断 Android / Windows。

### 7.3 Widget 变体策略

默认采用同一 Widget + 响应式布局。

只有结构差异明显时才允许平台变体，例如：

- ArenaHUD（竞技 HUD）。
- TrainingControls（训练控制）。
- AbilityBar（技能操作区）。
- MobileVirtualControls（移动虚拟控制区）。

命名建议：

~~~text
WBP_DBA_UI_ArenaHUD
WBP_DBA_UI_ArenaHUD_Mobile
~~~

两者必须绑定同一个 UDivineBeastsArenaViewModel。

### 7.4 输入支持

统一支持：

- Keyboard + Mouse（键盘鼠标）。
- Gamepad（手柄）。
- Touch（触摸）。

使用 CommonInput / CommonUI，不建立第二套输入系统。

### 7.5 移动端强制要求

- SafeZone（安全区域）适配。
- 刘海、挖孔、圆角、系统手势区域适配。
- 最小触控目标尺寸。
- 触控摇杆和技能按钮不遮挡核心 HUD。
- 低性能设备允许降低动画、模糊和动态材质复杂度。
- 横屏为核心战斗默认方案。
- 所有核心操作必须有 Touch 对应入口。

## 11. 加载进度界面专项设计

加载界面必须显示真实进度，不使用假计时器从 0% 自动增长到 100%。

当前可用任务语义：

- SessionAdmission（会话准入）。
- ExpectedWorld（目标世界）。
- ExpectedExperience（目标体验）。
- CharacterBinding（角色绑定）。
- GameplayData（玩法数据）。
- ProjectReadiness（项目就绪）。

规则：

1. 有真实总任务和完成数时显示确定进度。
2. 无法计算真实进度时 Progress = -1，显示不确定进度动画。
3. 地图加载完成不等于项目 Ready。
4. 使用 GamePlatformLoadingScreenService 的 Token 获取、更新和释放机制。
5. 多个系统同时加载时由 LoadingService 合并状态，业务界面不得直接 ShowLoading/HideLoading。
6. PC 可展示较丰富加载提示、背景与世界观内容；移动端可使用更轻量资源，但状态语义相同。

推荐类：

~~~text
UGamePlatformLoadingScreen
└── UDivineBeastsLoadingScreen
    ├── UDivineBeastsBootScreen
    └── UDivineBeastsLoadingTravelScreen
~~~

## 12. 登录界面专项设计

登录页使用 UDivineBeastsLoginViewModel。

主要状态：

- 是否已认证。
- 是否正在自动登录。
- 是否 Busy。
- 是否维护。
- ErrorCode。
- ErrorText。
- Retry 状态。
- 登录按钮是否可用。

主要命令：

- TryAutoLogin。
- Login。
- Retry。
- Logout / AccountSwitch。

安全要求：

- Password 只作为瞬时 Command 参数传递。
- Password 不进入 FDivineBeastsUIViewState。
- Password 不写日志。
- Password 不写遥测。
- 登录成功后页面不自行跳转，由 ApplicationFlow 的新权威状态驱动路由变化。

- 中文类名。

- 依赖边界。
- 扩展方式。

- 输入。
- 输出。
- 状态变化。
- 异步行为。

~~~cpp
/**
~~~

## 20. 最终约束

《神兽联盟》所有后续 UI 开发必须遵循：

~~~text
平台分类基础类
      ↓
神兽联盟项目分类基础类
      ↓
具体 C++ / Blueprint UI
~~~

数据更新遵循：

~~~text
业务状态
   ↓ 事件
ViewModel
   ↓ 事件
Widget
~~~

PC 与移动端遵循：

~~~text
同一业务状态 / 同一 ViewModel / 同一事件
                 ↓
        Adaptive Context
           ↙         ↘
       PC布局       Mobile布局
~~~

不得通过深层业务继承、Widget Tick 轮询、直接访问权威 Gameplay 状态或复制两套独立业务逻辑来实现平台差异。
