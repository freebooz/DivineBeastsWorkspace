# 项目竞技生命周期整改（2026-10-09）

本轮对应GW-02/04/15/17。MainArena默认禁止UE提前生成Pawn，倒计时完整出生使用ADivineBeastsCharacter并经唯一Character初始化执行器。每GameMode有独立Adapter、出生代次、预热需求与复活Timer，不能覆盖另一World。

全部Pawn的Definition、ActorInfo、Combat与资格代次完整后才统一Active。死亡/断线/结束/准入撤销立即Inactive；活玩家重连可信重新出生，死亡中重连保留剩余复活等待。出生失败保留原重连宽限并恢复原Roster映射，新PlayerState保持断线；成功才消费Timer。旧连接Logout/过期事件不能撤销新连接。

Adapter借用所属World装配的Data预热需求，不自行释放。装配销毁顺序为撤销GameMode借用接口、Adapter停止Timer和失活/销毁自己生成的Pawn、最后释放本世界预热需求；角色自己的异步加载失败/取消仍撤销Ready/Active。

本地玩家竞技UI在世界退出/切换时清空旧比赛身份、队伍、记分板、计时和路由。订阅当前World.GameStateSetEvent处理迟到GameState，订阅Arena PlayerArray变化处理迟到/离场PlayerState；退出解绑，不使用Widget Tick。广播重入不重新绑定正在清理的旧世界。

五人数模式继续保留NotConfigured。没有批准生产地图、胜利策略、规则版本/内容版本等正式配置，不改为ProductionReady，不把原型地图当生产验收。新增Automation与实际联机/地图/Cook/设备验证仍待统一引擎构建与执行；本轮没有修改UI二进制资产。

追加真实死亡生产桥接：每世界Adapter订阅当前项目Pawn的中立OnAuthoritativeDeath，验证当前World、Match/GameState阶段、受信Roster Character/Team、当前受控Pawn/PlayerState与出生代次后转平台Trusted Death。替换Pawn、断线、结束/释放先解绑；同次死亡失活即解除该订阅，旧Pawn迟到死亡不能清新Pawn的Timer。RelatedPlayerId保持空，不猜击杀归因/助攻/目标或胜利规则。现有GameMode消费死亡记录并调用本Adapter的复活计时器；Private/Tests用真实Combat属性死亡结算核Death计数/Timer受理及重复/旧Pawn拒绝。该夹具使用明确前赛测试端口，不证明完整Hero预热出生、计时器到期重新Spawn/Possess或联机通过；这些及五模式生产配置仍是交付条件。

复活返回true只表示本世界Timer已受理，零秒也使用NextTick，避免Combat同步广播内销毁正在结算的Pawn。Timer到期若资源/世界/连接不满足仍保持Inactive并记录真实出生失败；GameMode死亡事实已经记录但失活/复活适配拒绝时明确返回false，不吞错误。尚未执行到期出生回归，不宣称真实死亡已成功复活。

第二轮死亡广播重入整改：GameMode在AuthorityRecordDeath同步统计通知之前保存原World、Match/Server、Adapter BindingId、PlayerState、受控Pawn/Controller与出生代次。统计通知及外部失活/复活受理返回后重新查同一拥有上下文；监听者EndMatch或World退出时死亡已记录，但后续复活/击杀动作正常撤销，不在结束后重新排Timer。缺合法捕获在记录统计前明确拒绝。

每个复活请求拥有独立RequestId、TimerHandle，以及原World/Match/Server/BindingId/Controller/PlayerState/可空Pawn/Character/Team/Policy/AvatarGeneration。已准入死亡重连尚无Pawn时可以保留最后签发的正代次，快照不代表Ready/Active；之后Pawn或连接变化即撤销。到期先匹配RequestId，再清理自己的Timer并复验原上下文。旧回调不得移除新Timer；结束、断线、换装配、不同World/Match/Server或Pawn代次均不能出生。

Spawn入口只允许本装配的Countdown初次出生或InProgress恢复，并核实际GameMode阶段、GameState、Match、Roster、连接和代次。出生点Blueprint解析、旧Pawn退出、Restart、初始化/预热与激活这些外部边界后再核上下文，结束后停止；失败保持Inactive。出生代次使用值快照，不跨同步广播借用可重新分配的TMap元素。

既有Private/Tests/DivineBeastsArenaDeathBridgeTests.cpp扩为三个独立命令：NormalAndOldRequest、StatsListenerEndsMatch、QueuedRespawnAfterEnd。真实Combat死亡统计监听者同步EndMatch后不得排Timer；已排Timer结束后主动驱动迟到回调必须拒绝，Pawn/代次保持；原正常用例追加旧RequestId不得清新Timer。第二轮未执行UE Automation、UBT或Native（本次只有UE对象/时序路径，现有Arena无Native CMake入口），由根统一锁定Server构建。静态检查仅证明合同和写入范围，不代替这些行为结果。

第二轮补充旧装配所有权：已经被新Binding替换的Adapter仍可清理自己的Timer/死亡订阅，但不能按同PlayerId修改新Pawn资格。资格写入还须自有SpawnedPawns指针、当前Controller、Pawn.PlayerState与State.Owner关系、可信Roster以及Combat/Gameplay同一正代次完整匹配；资格广播之后再核原拥有上下文。既有NormalAndOldRequest用例增加新Adapter/Pawn/Timer存在时旧失活拒绝、旧自有Timer清理、新资格/Timer不变和旧析构安全。测试预先置Active仅是观察旧写入的明确夹具输入，不代表无Definition角色通过生产Ready授权。未运行该UE行为。
